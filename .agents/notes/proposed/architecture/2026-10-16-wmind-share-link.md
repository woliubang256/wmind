# Agent Note: 分享链接独立建表，支持密码与有效期，不引入导图级 ACL

Status: proposed

## Problem

需求方确认一期要实现「分享链接与公开预览」（2026-10-16）。原截图的工具栏里有「分享」入口，但需求正文没有展开，因此需要先决定三件事：分享是什么形态、数据怎么存、失效怎么表达。

这三件事互相咬合：形态决定表结构，表结构决定失效语义，失效语义又直接影响安全边界（能否被枚举探测）。同时它还牵动前端——分享页需要渲染导图，但不能给编辑能力，这会反过来要求编辑器内核做一次抽象。

## Proposal

密码只存 bcrypt 的部分由[分享密码管理](../../implemented/feature/2026-10-25-wmind-share-password-management.md)取代：验证仍用哈希，新增属主可查看的加密副本。只读形态、ACL取舍与公开失效规则仍保留本篇理由。

**形态：公开只读链接，不是指定用户共享。**

拿到链接的人可以查看（可缩放、平移、折叠展开、切换画布），但不能编辑。一张导图可有多条分享链接，每条独立配置：

| 配置项 | 取值 |
| --- | --- |
| 访问密码 | 可选（bcrypt 存储） |
| 有效期 | 永久 / N 天 |
| 允许访问者导出 | 开 / 关 |
| 允许查看备注 | 开 / 关 |

**存储：新增 `share_links` 表**（`uid` / `token` / `map_id` / `owner_id` / `password_hash` / `allow_download` / `show_notes` / `expires_at` / `view_count` / `revoked_at`）。

**令牌存明文**，长度 ≥ 22 字符（128 bit 熵，base64url）。访问密码用 bcrypt。

**失效四态统一返回 404**：令牌不存在、已撤销、已过期、导图已删除——对外不可区分。

**`show_notes = false` 由服务端剥离**：返回前递归删除文档中所有 `notes` 字段，而不是靠前端隐藏。

**前端抽象约束**：抽出 `MindMapViewer` 组件，只负责「几何 + 样式 → SVG」，交互能力（平移缩放 / 折叠 / 编辑 / 拖拽）作为插件集合注入。编辑器传全套插件，分享页只传前两个。**这项抽象必须与渲染层同期做**，不能留到 M5 再回头拆。

## Alternatives considered

### 为什么不在 `maps` 表上加一个 `share_token` 字段？

实现最简单，一个 `UPDATE` 就能开/关分享，不需要新表与新仓储方法。放弃它的原因是表达力不足：无法支持一图多链接（同一张导图给对外演示和内部评审发不同权限的链接），无法保留已撤销链接的访问统计，也无法独立配置有效期与密码。而这些恰好是需求方确认的配置项。

### 为什么令牌不哈希存储？

哈希存储是凭据存储的默认正确答案，能显著降低数据库泄露的影响。未选的原因是它与核心使用场景直接冲突：「我的分享」页需要让创建者**随时复制回完整链接**，哈希会导致链接只能显示一次、之后永远找不回来——用户丢链接的概率远高于数据库泄露。

权衡依据是**分享令牌不是用户凭据**：它是只读访问凭证，泄露的后果是他人能看到一张只读导图，且创建者随时可撤销。用「可设密码 + 可设有效期 + 可随时撤销 + 默认 noindex」四道约束把风险压到可接受范围。访问密码仍然 bcrypt 存储，不可逆。

### 为什么失效原因不分开返回？

分开返回（404 不存在 / 410 已撤销 / 403 已过期）语义更清晰，排查问题时也更容易定位。未选是出于安全考虑：区分原因会让攻击者能判断某个 token 是否**曾经存在**，从而验证枚举结果、推断系统规模。统一 404 让「从未存在」与「曾经存在但已失效」不可区分。

### 为什么一期不直接上导图级 ACL？

一次到位，支持「共享给指定用户」，是更完整的协作模型。放弃它的原因是需求方要的是公开链接，而 ACL 需要额外的用户选择器、权限矩阵、邀请通知、变更通知，成本是分享链接的数倍，并且与「一期不做团队空间与细粒度权限」的范围边界直接冲突。`owner_id` 字段已存在，二期可平滑扩展 `map_acl` 表——这是被推迟的决定，不是被否决的方案。

### 为什么 `allow_download = false` 不改成「只下发预渲染 SVG」？

那样能真正阻止数据获取，是唯一能兑现「禁止下载」承诺的实现方式。未选是因为分享页需要支持折叠、缩放、切换画布等交互，这些都必须基于完整文档结构；只下发一张扁平 SVG 会把分享页退化成一张图片。因此接受一个明确的能力边界：`allow_download = false` **降低门槛而非访问控制**，只隐藏 UI 入口并拒绝服务端导出接口。真正的访问控制手段是访问密码。这个局限已写进文档，避免后续被当成 bug 或安全承诺。

### 为什么不用独立的短链服务或第三方分享方案？

引入外部短链服务能获得更短的 URL 与访问分析。未选是因为它会破坏「除 PostgreSQL 外无必需外部依赖」的部署原则，且把导图访问链路暴露给第三方。访问统计用本表的一个计数器 + 30 分钟去重窗口即可满足「我的分享」列表的展示需求。

## Acceptance criteria

1. 创建链接 → 无痕窗口打开可见只读导图 → 撤销 → 再打开返回失效页。
2. 令牌不存在 / 已撤销 / 已过期 / 导图已删除，四种情况返回完全相同的响应。
3. `show_notes = false` 时，递归遍历响应 JSON 不含任何 `notes` 字段。
4. 关闭 `share.public_link_enabled` 后，所有历史分享链接立即失效。
5. 密码连续输错 11 次后返回 429；输对后刷新页面不需重新输入密码。
6. `allow_download = false` 时分享页无导出入口，且带该 token 调用 `POST /export` 返回 403。
7. 借用分享身份导出其他导图（`mapUid ≠ share.map_id`）返回 404。
8. 以只读配置挂载 `MindMapViewer` 后，页面上不存在可编辑元素，按 Tab/Enter 不产生新节点。
9. 随机生成 1000 个不存在的 token 请求公开接口，全部 404 且响应时间无显著差异。

## Risks

- **分享页的职责边界会被持续挑战**。一旦分享页支持了折叠、大纲、配色切换，就很容易被要求「再加个编辑入口」「再加个评论」。需在 M5 开始时就明确「只读」是硬边界，任何编辑类需求走二期。
- **`allow_download = false` 容易被误解为安全承诺**。若使用者把它当成「禁止下载」，会产生错误的安全预期。已在需求文档、接口文档、导出文档三处标注能力边界，但产品文案上也应避免使用「禁止下载」这类措辞。
- **访问计数在单实例用内存去重**，多实例部署会重复计数。已把 `Counter` 抽象为接口，但部署方若不知情会误判数据准确性——需在部署文档中标注。
- **`M2.8 只读查看器抽象` 是硬约束**，若 M2 期间被跳过，M5 会付出拆渲染层的返工成本。这条已写进路线图的 M2 子阶段并标注「必须与 M2.3 同批做」。
- **纯 SPA 下分享页的社交预览受限**：`og:title` / `og:description` 由前端 JS 注入，不执行 JS 的爬虫拿不到。若需要良好预览，二期需为 `/s/*` 做预渲染，见 [前端采用纯 SPA](2026-10-16-wmind-spa-vs-ssr.md)。
