# Agent Note: 用户自助 TOTP 双因素认证

Status: proposed

## Problem

密码登录直接签发会话，用户无法增加独立验证因子。新增认证步骤还必须防止旧刷新令牌、并发请求及恢复码重复使用绕过第二步。

## Proposal

按存储、认证服务与 API、账户及登录界面三个单元落地。独立 user_two_factor 表保存版本化 JSON 状态，双方言共用查询；写入先锁定用户安全行，更新有 revision 校验。TOTP 采用标准 SHA1/6 位/30 秒、前后一个窗口；计数器只能前进。设置密钥十分钟过期，验证后才启用。恢复码为十个独立随机串，仅保存 SHA256，消费与会话签发同事务。

密码验证后生成五分钟、最多五次尝试的随机挑战，数据库只保留哈希，绑定用户、密码哈希及安全版本；每用户最多五个未过期挑战。完成第二步前不签发访问令牌或刷新 Cookie。启用/停用需要密码，停用与更新恢复码还需第二因子。启停随机更新安全版本并撤销全部刷新令牌，当前设备获得新会话；每次访问比较 JWT 安全版本，不能通过状态缓存放行旧令牌。Login/Refresh/设置共用安全行锁，锁顺序固定为安全行后令牌。

密钥由 AES-256-GCM 加密，AAD 绑定用户 uid 与用途。专用 WMIND_2FA_ENCRYPTION_KEY 优先；未配置时从 JWT 密钥按用途派生，兼容现有部署。必须备份并保持此密钥稳定，修改会使已登记验证器无法解密。二维码在服务端本地生成，任何密钥不发往第三方。

## Storage implementation

迁移 0003 和双方言 sqlc 查询已建立独立安全记录。Ensure 保证行存在，事务内读取锁定记录，Save 根据 revision 拒绝过期副本。共享仓储契约覆盖缺省状态、往返、过期写和回滚。状态 JSON 只作为内部领域记录，HTTP 使用独立 DTO。

## Related decisions

检索认证、双因素、TOTP 和会话笔记：现有[认证会话](../../implemented/architecture/2026-10-17-wmind-auth-session.md)与[认证数据层](../../implemented/architecture/2026-10-17-wmind-auth-data-layer.md)部分重叠，保留密码/刷新策略并互链；本篇增加第二步与安全版本。限流笔记继续负责进程内密码锁定；第二步挑战次数保存在数据库，多进程共享。邮件提案处理邮件交付，与 TOTP 无关。没有同主题旧提案需替代。

## Alternatives considered

- 短信或邮件验证码易于理解且无需安装验证器，但引入交付服务、运营成本与额外可用性依赖；本次采用离线 TOTP。
- 内存挑战实现简单且无迁移，但重启、多实例和并发消费难以保证一致；挑战归入持久化安全状态并用事务消费。
- 只撤销刷新令牌可复用现有实现，但旧访问令牌仍能使用十五分钟；增加随机安全版本并在认证时查验。
- 强制立即提供独立密钥能解耦 JWT 轮换，但会阻断现有部署启动；提供专用配置和用途隔离派生回退，明确持久化密钥要求。

## Acceptance criteria

验证标准 TOTP、加密篡改/跨用户隔离、密码后无会话、无效过期挑战、次数限制、单次恢复码和 TOTP 重放、旧访问/刷新失效、并发消费。保留普通密码登录。中英文界面提供设置、二维码/手输密钥、恢复码下载、重新生成和停用。

## Risks

每次鉴权多一次安全状态读取。单用户状态更新串行；挑战和恢复码有固定上限。恢复同时丢失验证器与恢复码暂不提供自动重置；运维必须保护密钥备份。
