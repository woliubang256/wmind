# Agent Note: M2 验收：8 条标准的证据、补上的三个快捷键与两个真 bug

Status: implemented

## Problem

M2 是「关键里程碑」，验收标准有 8 条，但它们要求的证据形式完全不同：

- 第 2 条（100 步撤销后逐字节一致）只有**单测**能证明——浏览器里数不出「完全一致」。
- 第 1、6、7、8 条是**纯浏览器行为**（键盘、徽标数字、拖拽反馈、只读模式），`go test` 与 Vitest 都覆盖不到。
- 第 3 条是**数字**（< 1.5s、60fps），而「60fps」在一个刷新节奏不一定是 60Hz 的环境里没有绝对标尺。
- 第 4、5 条已经在 M2.6 的批次里验过（21 项），但脚本放在 `/tmp` 里随环境清理丢了。

真正需要写清楚的是：**每条标准由什么证据支撑、数字是怎么量出来的、哪些是这一轮才发现的缺口**。含糊地写「8 条全过」会让下一个人以为它们都被自动化覆盖了。

## Decision

### 逐条证据，不合并成一句「通过」

| # | 标准 | 证据 |
| --- | --- | --- |
| 1 | 纯键盘完成全流程 | 浏览器脚本 14 项：打开即聚焦画布 → Tab×3 建子节点 → F2 改名 → ⌘B 加粗 → ⌘⇧H 变色 → ⌘. 折叠 → 撤销全部 → 重做全部 |
| 2 | 撤销/重做 100 步后逐字节一致 | `frontend/src/editor/store/history.test.ts`，4 个用例，`JSON.stringify` 快照比对 + 原引用比对 |
| 3 | 1000 节点 < 1.5s；拖拽 60fps | `/maps/stress` 的 **2000** 节点文档（比标准更严）：首帧 911ms、全部就绪 934ms、拖拽 76 帧零掉帧（最长 17.7ms）、落点重排 91ms |
| 4 | 刷新保持；断网 30s 后自动补存 | 浏览器脚本：编辑→已保存→刷新仍在；`setOffline` 30 秒显示「保存失败」且失败请求 < 20 次；恢复网络后自动补存并落到服务器 |
| 5 | 两标签页 409 与三个选项 | 浏览器脚本：三个选项**各自制造一次新鲜冲突**，逐一验证（放弃→回到服务端版本；副本→新地址带本地内容且原图不变；覆盖→服务器变成我的内容） |
| 6 | 折叠显示隐藏后代数 | 浏览器脚本：折叠根节点后只渲染 1 个节点，徽标文本 `6` |
| 7 | 非法落点被拒绝且有反馈 | 浏览器脚本：拖到自己的后代时出现文案「不能放到自己的子节点里」，松手后**布局签名一个像素都没变**；对照组合法拖拽确实改变了结构 |
| 8 | 只读查看器 | 浏览器脚本 9 项：无输入框 / 无「新建」按钮 / 无结构选择器；Tab、Enter、空格均不产生节点；缩放按钮与折叠徽标仍可用；退出预览后键盘恢复 |

### 第 1 条暴露了三个真缺口：加粗、变色、折叠都没有键盘入口

`docs/08` §4.2 第 1 条要求「加粗变色」也在纯键盘流程里，而键位表里根本没有这三件事：

- **加粗**：`updateStyleCommand` 早就有了，但没有任何入口。
- **变色**：原生 `<input type="color">` 的取色面板只能点。
- **折叠**：只有徽标点击与工具栏按钮。

补法是三条命令，都走已有的 `updateStyleCommand` / `toggleCollapseCommand`：

- `⌘B` → `fontWeight` 在 400 / 700 之间切。判据用**渲染出来的** `resolveStyle().fontWeight`，不是 `topic.style.fontWeight`——后者通常是 `undefined`（继承），拿它判断会让第一颗按键看起来毫无反应。
- `⌘⇧H` → `nextFillColor(theme, 当前渲染的 fill)` 在调色板里循环，走到末位之后回到 `null`（继承）。用「循环」而不是取色器，是因为取色器没法纯键盘操作；而调色板是封闭的六个颜色，循环一遍刚好够用，还顺带保住了「换主题整体生效」——只写 `fill` 一个字段。
- `⌘.` → 折叠 / 展开。

**折叠键本来定的是空格，被 pan-zoom 撞了。** 写完跑浏览器验证才发现：`pan-zoom` 插件在 `window` 上监听空格做「按住拖动平移」，两个处理器都会跑——用户按住空格准备平移，节点莫名其妙收起来。改成 `⌘.`（浏览器里没有默认行为）。这条只在真浏览器里能发现，键位表的单测看不见。

### 第 2 条抓到的 bug：样式命令的空操作会污染历史栈

写「同值再写一次是空操作」这个用例时失败：`revision` 从 1 变成 2。原因是 `updateStyleCommand` 无条件 `found.topic.style = { ...current, ...patch }`——**内容相同的新对象，immer 也判定为「改过了」**（它比较引用）。

后果不是脏数据，而是历史栈：用户连按两次 ⌘B（第一次已加粗），或者对同一批节点重复套同一个颜色，每次都会压一条「撤销了也看不出差别」的记录。100 步撤销的预算被这类空记录吃掉。

修法：补丁里每个键都等于现值时**不写回**。`resetStyleCommand` 同理（已是空样式就不写）。修完这条用例变绿，同时给 100 步测试腾出了干净的语义。

### 100 步测试的三个刻意设计

- **每步推进 1 秒时钟**。否则连续改名落进 800ms 合并窗口，100 次按键只留 1 条历史，「100 步」名不副实。
- **每条命令都保证改变文档**（加粗按奇偶交替、移动在两个父节点间来回、变色按调色板轮转）。混进一条空操作，`past.length === 100` 的断言就失真，反而掩盖真正的问题。
- **删除只删自己新建的节点**。固定骨架被删掉之后，后续命令会全部退化成「找不到节点」的空操作。

### 「60fps」怎么量：先量空闲基线

headless 合成器的刷新节奏不一定是 60Hz。直接断言「平均帧间隔 ≤ 16.7ms」量到的可能是环境节奏，而不是掉帧。

所以先跑 1.2 秒「什么都不做」的基线（实测 16.5ms ≈ 60fps），再断言两件事：拖拽均值不超过基线的 1.15 倍；**最长帧间隔 < 25ms**（掉一帧就是 33ms）。第一次跑出来 `max = 90.5ms`，一度以为掉帧，查下去是落点后那一帧的全量重排被算进了拖拽区间——把「拖拽期间的帧」与「放下的成本」分开统计，才是诚实的两个数字。

### 只读模式的 role 是 `img`，不是 `application`

只读时根 `<svg>` 的 `role` 从 `application` 变成 `img`（键盘不再接管，读屏把它当图）。验收脚本按 `svg[role="application"]` 找元素会在预览模式里超时——这不是 bug，是正确行为撞上了写死的选择器。

## Consequences

- 前端单测 237 → 254（新增 `commands/style.test.ts` 11 项、`store/history.test.ts` 4 项、键位 2 项）。
- `tsc --noEmit` 干净；`vite build` 通过，编辑器 chunk 66.17 → 67.45 kB（gzip 21.89 kB），远低于 350 kB 预算。
- 浏览器验收：标准 1/6/7/8 共 **32/32**；标准 3 共 **7/7**；标准 4/5 共 **17/17**。
- 新增三个快捷键（`⌘B` / `⌘⇧H` / `⌘.`），已同步进 `docs/05` §4.6.2 的键位表，并记下两处冲突的来由。
- 打开编辑器后**自动聚焦画布**：否则键盘用户第一颗 Tab 会去页头按钮，得连按若干次才能开始编辑，「纯键盘」第一步就卡住。只读模式不抢焦点。
- 实现与计划的 9 处差异回填进 `docs/08` §4.3（无 d3、奇偶分侧、`Ctrl+F` 未接线、五种结构等）。
- 已知限制：`Ctrl/Cmd + F`（查找）仍未接线，排在 M3；`timeline` / `fishbone` / `brace` / `tree-table` 四种结构遇到时静默回退到 `mindmap`。
- 已知限制：验收脚本仍在 `/tmp`，没有进仓库（`playwright-core` 不在 `package.json` 里，提交一个别人跑不起来的文件比不提交更糟）。断言与步骤写进本笔记，M6 做正式 E2E 套件时以此为清单。

## Alternatives considered

**把「加粗变色」推迟到 M3 的样式面板**：M3 本来就要做样式系统，现在做等于提前动手。放弃原因是验收标准 1 明写「纯键盘完成加粗变色」——推迟等于这一期验收不通过，而补三条命令的成本远低于把验收标准改成「M3 补」。

**变色用原生 `<input type="color">`**：实现最省事，也是 M3 样式面板里该有的东西。放弃原因是它的取色面板必须点，满足不了「全程不碰鼠标」；键盘可操作的取色器（色相环 + 方向键）成本高得多，且 M3 会重新设计样式面板。

**折叠用空格（树形控件惯例）**：单键、直观。放弃原因是它已经属于「按住平移」——一个键干两件事，按住空格准备拖画布时节点会收起来。这类冲突单测看不出来，只能在真浏览器里按一遍。

**给样式命令加 `coalesceKey` 来消除重复记录**：一行就够。放弃原因是合并窗口会让「加粗 → 取消加粗」这类快速来回也被合并成一条，撤销时行为反直觉；根因是空操作不该入栈，不是「入栈太频繁」。

**100 步撤销用浏览器脚本数节点**：更接近真实用户路径。放弃原因是「文档与初始状态完全一致」包含 `meta.updatedAt`、样式、children 顺序，浏览器里取不到整份文档，只能数节点数——那证明不了「完全一致」。单测直接比 JSON 快照才是对的工具。

**把验收脚本提交进仓库并接进 CI**：可复现、可回归。放弃原因是 `playwright-core` 与缓存浏览器不在依赖里，CI 要加 `playwright install` 与浏览器缓存；M6 明确列了 E2E 任务，现在引入等于留一个半成品套件。
