# Agent Note: M4 验收：24 项通过、1 项阻塞、4 项属于 M5、2 项缺外部基准

Status: implemented

## Problem

M4 的验收标准是 [08 §6](../../../../docs/08-开发路线图.md) 的 9 条 + [06 §6](../../../../docs/06-导入导出与主题系统.md)
的 IE-01 ~ IE-31。逐条跑下来有三类问题必须先定口径，否则「通过」两个字没有意义：

- **有的条目要求外部基准**：IE-20 要「与 XMind 同主题导出图对比，容差 2%」，IE-01/02/03
  要「真实 XMind 文件」。本机没有 XMind，也拿不到真实样本（GitHub API 未授权、
  没有 `gh`），仓库里的夹具是按规范**重建**的。
- **有的条目属于下一期**：IE-22/23/24 是分享页的导出控制，IE-30 是服务端导出，
  两者都排在 M5 / 可延后项，代码里根本没有对应实现。
- **有的条目字面要求与实现能力不一致**：IE-18 说「提示并引导服务端导出」，而一期
  没有服务端导出；IE-11 的「像素级一致」在字体内嵌完成前不可能成立。

### 两条口径

**IE-27 的「无跳动」要量布局宽度，不是 `getBoundingClientRect`。**
画布打开时是 100%，随后「缩放到适应」把它变成 78%，于是同一个节点从 94 CSS px
变成 73.5——看起来像跳了 22%。实际节点自己的 `rect[width]` 一直是 94，变的只是
缩放。用 CSS 像素做这条验收，测到的是缩放动画，不是布局。

**「像素级一致」要容忍抗锯齿。**
画布截图与导出 PNG 裁到各自的内容包围盒后，长宽比 2.413 对 2.414（同一套布局），
但逐像素直接比有 2.21% 的均值差——因为画布是 78% 缩放截的、导出是 1:1，文字与
线条的边缘各差半个像素。取 3×3 邻域最小值后再比，均值差降到 **0.2%**、显著差异
像素 0.14%。这才是「画的是同一个东西」的证据；直接把边缘抖动算进差异，任何
位图比对都不可能过。

### 验收暴露并修掉的两个真问题

1. **缺 `theme` 的文档让编辑器整页白屏**（`d74635d`）。加载路径没走归一化闸门，
   与导入路径分叉。
2. **导出的 SVG / PNG 用系统字体**（`a6497f5`）。字宽差 16%，文字会溢出节点框；
   IE-11 与 IE-29 都卡在这。

### IE-15 / IE-20 / IE-01 的缺口怎么记

- **IE-15（PDF）**：`jsPDF` + `svg2pdf.js` + `opentype.js` 三个依赖装不进
  `package.json`（沙箱 broker 拒绝 `rename node_modules/.bin/*`）。不用「整张 PNG
  塞进 PDF」糊过去——那与 §3.5 的矢量方案不符，也过不了 IE-29 的字面要求。记成
  阻塞，解锁条件写在下面。
- **IE-20（10 套配色与 XMind 对比 ≤ 2%）**：需要 XMind 侧的同主题导出图作为基准。
  配色本身的对比度已有闸门（`npm run check:palette`，最低 4.56:1），但「像不像
  XMind」没有基准就无从判定。
- **IE-01 / 02 / 03（真实 XMind 样本）**：[06 §2](../../../../docs/06-导入导出与主题系统.md)
  自己写着「夹具是按规范重建的，不是真实导出文件，M4.11 验收前需要 3~5 个真实样本
  替换」。本机没有 XMind、也拿不到公开样本，所以这一条**仍然欠着**——结构验证通过，
  但「真实文件的属性拼法可能比规范描述更杂」这半句没有被验证过。

## Consequences

- 浏览器验收脚本 **41 项**（导出 20 + 字体 19 + 像素 2），全部通过；单元测试
  **864 条 / 52 个文件**。
- 两次修复各带一份笔记与提交，`verify-notes` 55 条通过。
- 遗留清单（按解锁条件排序）：
  1. **PDF**：需要 `jspdf` / `svg2pdf.js` / `opentype.js` 能正常进依赖。
  2. **真实 XMind 样本**：需要 3~5 个真实文件（含自定义主题、图片、联系、外框、
     概要各一），据实修正映射。
  3. **IE-20**：需要 XMind 导出的 10 套同主题参照图。
  4. **IE-22/23/24、IE-30**：M5 的分享页与可延后的服务端导出。
  5. **IE-18 的「引导服务端导出」**：等服务端导出落地后补一句提示。
- 验收脚本仍在 `/tmp/wmind-accept`（沿用 M2/M3 的结论：`playwright-core` 不在
  `package.json` 里，提交一个别人跑不起来的文件比不提交更糟）。断言与口径写进
  本笔记，M6 做正式 E2E 套件时以此为清单。

## Alternatives considered

**把「未实现 / 阻塞 / 无法验证」写成「通过」**：验收表能全绿。放弃原因：这三类
条目恰恰是「下一期从哪儿开始」的输入，抹平之后 M5 会重新发现一遍。

**为了 IE-15 用「PNG 塞进 PDF」凑一个下载按钮**：验收表上能打勾。放弃原因：那
不是 PDF 导出，是「把位图换个后缀」；文字不可搜索、放大就糊，与 §3.5 写的矢量 /
转路径方案完全相反，而且会让人以为字体问题已经解决。

**为 IE-27 用 `getBoundingClientRect` 记录并「修复」那个 22% 的跳动**：会去改
一个不存在的问题（缩放动画），甚至可能把「缩放到适应」改坏。放弃原因：先确认
口径再动手，比先动手再解释便宜得多。

**把验收脚本提交进仓库并接进 CI**：可复现。放弃原因同 M2/M3：浏览器与
`playwright-core` 不在依赖里，M6 的 E2E 任务才是它该落地的位置。
