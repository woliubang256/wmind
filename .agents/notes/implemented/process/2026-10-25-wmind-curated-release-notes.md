# Agent Note: 发布日志以按版本整理的用户说明为准

Status: implemented

## Problem

v1.0.0 发布页从全部历史提交生成 229 条记录，混入文档、测试和发布维护记录。同一功能的分步实现、修复及已被替代的中间方案并列出现，用户无法从中确认最终交付能力。同版本反复发布仍重放全部历史，单纯按提交类型过滤不足以消除这些重复。

## Decision

发布前结合提交历史和当前实际行为，按功能合并并改写用户可见结果，入库到 `changelogs/vX.Y.Z.md`。首发覆盖完整已交付能力，新版本只写相对前版的增量；同版本重发更新同一份完整摘要，不追加本轮 commit 清单。

`scripts/release.mjs changelog` 只读取对应版本整理稿，验证版本标题、分类和条目，再按「新增功能 / 问题修复 / 性能改进」顺序输出。无内容分类不写；缺稿、空稿、未知分类、原样 commit 标题、尾部提交哈希、占位条目及完全相同条目阻止发布，绝不回退到 Git 历史。语义合并与事实核对属于发布前整理，脚本不声称能识别同义句。

流水线通过 `changelog` 生成日志，发布页、日志附件和部署包使用同一输出；打包命令在运行 Go 编译前拒绝与当前稿不一致的日志。此次现有 v1.0.0 Release 只同步页面正文，不移动 tag、不重建镜像、不替换已有附件，已有下载包中的旧日志留待下次正式发布更新。

## Alternatives considered

- **直接按 Conventional Commit 分类过滤**：零额外稿件维护，能保留完整可追溯历史；但开发步骤不等于用户功能，无法消除同功能多次提交及被撤回方案，故仅作为整理素材，不作为正式正文。
- **关键词或相似度自动去重**：无需外部服务且容易在 CI 中自动执行；但相似标题可能是不同功能，同一功能也可能使用完全不同表述，误合并会丢掉真实变化，因此只拦截完全相同条目。
- **CI 调用模型总结**：有语义合并能力，也可减少手工起草；但引入 Provider 密钥、费用、网络可用性及输出不确定性。整理稿随代码审阅，发布过程保持离线、可复现，不调用站点 AI 配置。

## Verification

- 回归测试先复现旧实现将同一 AI 功能的多次提交及文档、测试、维护记录全部输出的问题，修复后 `npm run test:release` 的 17 项通过。
- 测试覆盖无 Git 目录、跨版本取稿、同版本重发与已有 tag 下改稿、缺稿失败、三类顺序、空分类、重复条目、占位及原样提交拒绝。
- CLI 失败不覆盖已有输出；暂存包日志与生成结果一致，打包入口在运行 Go 前拒绝旧日志。复用现有白名单、符号链接和 Nginx 契约，不重建完整部署产物。
- `npm run verify-notes` 通过；格式测试不代替 v1.0.0 内容审阅和线上回读核对。

## Consequences

日志与开发提交解耦，可离线确定性复现，同版本重发不会追加重复开发记录。代价是每次发布需维护整理稿；测试只能约束格式和确定性，无法证明语义去重或功能描述准确，发布者仍须结合实际代码审阅。新增版本缺稿会阻止发布，这是有意的失败关闭行为；只有稿件维护成为明确瓶颈时才重访辅助起草工具，不能取消发布前审阅。此次只修改线上正文时，旧附件内日志与页面暂时不同，不以替换附件破坏已发布校验和。
