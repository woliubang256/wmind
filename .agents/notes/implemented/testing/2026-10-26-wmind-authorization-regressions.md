# Agent Note: 将安全审计的权限边界固化为路由回归

Status: implemented

## Problem

各模块已有导图、模板、主题和分享的跨用户测试，但匿名接口白名单与管理员接口范围没有统一的请求级守卫。审计临时测试证明当前路由的基础权限正确，却不进入后续 CI；新增接口或子路由漏挂中间件时，局部正常请求测试不会发现。缩略图、分享创建、回收站和资料批量字段注入也有交叉验证缺口。

## Decision

枚举真实 Gin 路由，只允许显式列出的 11 个 API 匿名入口；其余 API 无 Cookie/Authorization 请求必须返回 401，管理员子路由对普通用户必须返回 403。白名单须与真实路由双向匹配，防止拼错后静默漏测。`/uploads` 使用专门媒体授权回归，不混入 API 身份验证矩阵。

继续复用现有模块级跨用户测试，仅补缩略图、创建他人导图分享、回收站恢复/清理以及资料角色/状态/UID 注入。拒绝写入后再由属主读取、恢复或列出资源，确认没有副作用。

发布整栈媒体冒烟落盘真实 PNG：严格头像名称匿名返回相同字节，新私有文件及未知文件即使已经存在也必须匿名 404。公开目录任意文本下载不再作为正确契约，既有最新镜像晋升之前执行冒烟与隔离卷清理的顺序保留。

`npm run test:release` 同时执行全部 `deploy/*.test.mjs`，默认代理的固定地址、精确信任及示例配置检查随 CI 执行，不仅在本轮人工运行。

[OpenAPI 契约](../../implemented/architecture/2026-10-21-wmind-openapi-contract.md)负责形状与路由对等，本篇只持有身份和资源访问边界；两者部分重叠但不互相替代。私有媒体的业务规则由对应修复笔记持有。

## Alternatives considered

- 仅保留模块手写路由列表，失败定位清楚且已有覆盖，但新增管理员备份、AI 等接口仍需人为记得补清单；动态枚举以默认拒绝的方式补上新路由漏鉴权守卫。
- 从 OpenAPI 的 security 声明自动推断匿名接口，可避免重复维护声明，但生产实现与文档若同时错误地开放接口会一起通过；独立的精简公开白名单保留第二条权限证据。
- 将所有审计样例原样复制进一个大测试，保留证据最方便，但会与现有模块用例重复并引入旧漏洞期望；只固化基础控制和当前覆盖缺口。

## Verification

- `go test ./internal/httpapi -run '^TestAuthorization' -count=1` 通过：55 个受保护 API 匿名 401，18 个管理员 API 普通用户 403，公开白名单全部匹配真实路由。
- 注入字段不能改变角色、状态和身份，合法昵称仍可更新；缩略图与分享列表保持原值，跨用户恢复/永久删除被拒绝后属主仍能恢复并读取原图。
- CI 媒体契约测试在旧文本冒烟下先失败，改成合法头像、私有与未知 PNG 后通过；`npm run test:release` 全部 22 项通过，包含 PNG 签名、尺寸、像素解压验证、图片字节对比契约和默认代理部署契约。

## Consequences

新增路由默认进入认证守卫，减少手写列表漏掉新增 API 的机会，代价是新增真正匿名 API 时必须显式更新白名单并单独验证授权规则。临时 SQLite 证明 HTTP/服务装配行为，双方言资源隔离仍需仓储契约测试。发布镜像媒体冒烟只能由具备 Docker 的 CI 完成，静态契约测试不代替真实代理执行。
