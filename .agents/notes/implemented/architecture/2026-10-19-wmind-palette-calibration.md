# Agent Note: 10 套配色的校准、落库与对比度闸门

Status: implemented

## Problem

M3 要交付「10 套内置配色」，并把验收标准 5「所有配色的文字与填充对比度 ≥ 4.5:1」变成可执行的检查。落地前有三个具体问题：

- 色值从哪来？docs/03 §6.2 明确写着「近似值，待校准」，而本机没有 XMind 可采样。
- 文字色怎么定？按「亮度 > 0.5 用深色字」的阈值，还是存一张 `textColors` 表？
- 色值放哪？`create.ts` 里的 `RAINBOW_COLORS` 只有一个默认主题，10 套要能被面板、脚本、单测同时读到。

## Decision

### 以「最佳二选一」定义文字色，不存映射表

`readableTextColor(fill)` 在 `#1F1F1F` 与 `#FFFFFF` 中取对比度更高的那个，取代原先的亮度阈值（阈值 > 0.5 用 `#333333`）。

阈值法在中间调的饱和色上会选错：`#E53935` 上白字 4.23、深字 4.61，阈值法判给白字，正好选了差的那个。选高者永远不劣于阈值法，且对用户手动填的任意颜色都成立——存 `textColors` 表只能覆盖调色板里那 60 种。

深色字从 `#333333` 改成 `#1F1F1F` 不是为了好看：`#333333` 在中等明度的填充上够不到 4.5，而更深的灰几乎不改变观感。

### 校准只降明度，不动色相

对 60 个分支色 + 10 个中心主题色逐个核算，9 个不达标。按 docs/06 §5.4 第 3 步的做法，在 HSL 里以 0.5% 为步长降明度，到 4.55:1（留一点余量给十六进制取整）即停。最大改动是 `#EC407A → #E5175C`（−5% L），色相与饱和度原样保留。

校准结果：

| 配色 | 改动 |
| --- | --- |
| `vivid-entropy` | `#118AB2 → #107FA4` |
| `vivid-vitality` | `#845EF7 → #7E57F7` |
| `vivid-code` | `#0984E3 → #0877CD` |
| `classic-rainbow` | `#E53935 → #E32925`、`#1E88E5 → #1878CD` |
| `classic-rose` | `#EC407A → #E5175C` |
| `classic-greentea` | `#558B2F → #4F812C` |

校准后最低对比度 4.56:1。

### 色值落 JSON，装配留在 TS

`theme/palettes.json` 存 10 套的差异部分（6 个分支色、中心主题主色、三个角色样式），`theme/palettes.ts` 负责类型标注与「配色 → 完整 Theme」的装配，共享底稿（自由主题、概要、边界、关系线、布局开关）只写一份。

放 JSON 而不是 TS 的直接原因：校验脚本 `scripts/check-palette-contrast.mjs` 要读它，读 TS 就得让脚本解析 TypeScript。`defaultTheme()` 改为 `themeById(DEFAULT_PALETTE_ID)`，新建文档与面板切换从此共用同一份数据。

### 彩虹分支开关必须真的有效

原先 `rainbowBranch` 关闭时仍然按 `branchIndex` 在 `palette.colors` 里循环，而开启时用 `rainbowColors`——两者默认是同一个数组，于是开关两侧结果完全相同，面板上点它没有任何反馈；`palette.colors` 也被 `rainbowColors` 架空，换配色方案时分支颜色纹丝不动。

改成：开 = 各分支按序取 `rainbowColors`，关 = 所有分支统一取 `palette.colors[0]`。这是开关唯一说得通的语义。

### 两道闸门

`npm run check:palette` 读 JSON、逐色核算、不达标退出码 1，已接入 CI；`palettes.test.ts` 用真实的 `computeStyle` 把同一批色值再跑一遍。脚本负责 CI 里可见，单测负责防脚本与运行时逻辑漂移——两处各写一遍对比度公式，靠「同一批色值、同一个阈值」互相钉住。

## Consequences

- 默认主题（`classic-rainbow`）的根节点从 `#1E88E5` 变成 `#1878CD`、分支 0 从 `#E53935` 变成 `#E32925`。视觉差异在色卡上几乎看不出，但已落进 `resolve.test.ts` 的断言。
- 关掉彩虹分支后分支变成单色，这是**行为变更**：老文档里 `rainbowBranch: false` 的导图打开后，分支颜色会从「六色循环」变成「统一第一色」。存量数据极少（M2 之前没有面板能关它），且新语义才是用户预期的。
- `RAINBOW_COLORS` 常量删除，`create.ts` 不再持有任何色值；改配色只需要动 JSON。
- 校验脚本与运行时各有一份对比度实现，属于已知的重复。缓解手段是单测交叉验证；如果将来要消除，得把色值数学抽成一个两边都能加载的 `.mjs`。
- `docs/03 §6.2` 与 `docs/06 §5.3` 已回填校准后的色值、中心主题主色、以及「文字色不落库」的理由。

## Alternatives considered

- **存 `textColors` 表**：docs/06 原稿的写法。否决理由是对任意用户填充色无效，且多一份可能与 `colors` 不同步的数据。
- **按截图肉眼调色**：没有 XMind 可采样，只能保证「看起来像」，无法给出可复核的判据。改为以对比度为唯一硬约束、色相保持原稿。
- **配色数据放 TS 常量**：脚本读取需要解析 TypeScript，或额外引入构建步骤。
- **保留「关闭彩虹也用循环取色」**：等于承认开关是装饰品。
