# Agent Note: 概要 / 边界 / 联系（画在节点之间的三种附属结构）

Status: implemented

## Problem

XMind 里最常用的三种注释手段，wmind 一个都没有：

- **概要（Summary）**：框住几个同级分支，在右侧挂一个小节点写「这几条合起来是什么」。
- **边界（Boundary）**：给一组节点套一圈虚线框，表达「这是一个阶段 / 一个模块」。
- **联系（Relationship）**：在两个不相邻的节点之间画一条弧线，说明跨分支的依赖。

数据层其实早就准备好了——`Sheet.summaries` / `Sheet.boundaries` / `Sheet.relationships`
在类型里一直存在，XMind 导入也会写进来。缺的是三件事：**画出来、改得了、能新建**。
导入一张带概要的 XMind，打开后概要不显示；就算显示了也没地方改标题。用户能做的
只有「导入 → 发现注释丢了 → 回 XMind」。

难点不在画线，在三个地方：

1. **位置依赖主题布局的结果**。概要挂在「A1 和 A2 的并集」右侧，边界包住「A 的子树」，
   联系连「A1 的中心到 B1 的中心」——全都得等主题落位之后才知道坐标。
2. **XMind 把概要/边界存了两份**。`topic.summaries`（挂在父主题上）和
   `sheet.summaries`（平铺）都可能有，导入的文件两种写法都见过。只读一边就会
   「导入后概要少一半」；只写一边就会「改完名字，刷新又变回去」。
3. **概要节点会把画布撑大**。它挂在最右一列之外，不算进包围盒的话，
   点「缩放到适应」它有一半在屏幕外，导出图也会被裁掉。

## Decision

概要选区、左右方向和避让由[概要完整选区修复](../../implemented/bug-fix/2026-10-23-wmind-summary-selection-placement.md)部分替代；下文固定右侧的尺寸表描述原设计，其余分层和读写契约保留。

联系的画布编辑、样式、箭头和包围盒由[联系线编辑](../../implemented/feature/2026-10-23-wmind-relationship-editing.md)部分替代；下文联系不计包围盒、没有箭头的描述属于原设计。

**几何单独一层，不进 `layoutMindmap`。**

新增 `editor/layout/annotations.ts`，输入是「算好的主题布局 + 文档」，输出一份
`AnnotationLayout`（三个数组 + 一个总包围盒）。理由是这两件事的输入与失败模式
都不同：主题布局是**树**的计算（子树尺寸、兄弟对齐、折叠），附属结构是**区间**的
计算（一组兄弟的并集）。分开之后，改概要的画法不用重跑 876 行的布局，也碰不到
折叠逻辑。

三者共用「区间并集」这一个原语：

| 结构 | 几何 |
| --- | --- |
| 概要 | 括号贴范围右缘、开口朝左；节点在 `右缘 + 26`，竖直居中于范围 |
| 边界 | 范围并集外扩 16，圆角 10 的虚线框 |
| 联系 | 两端中心之间画二次贝塞尔，控制点从弦中点沿法线外推 `min(60, 弦长/4)` |

括号的圆角取 `min(12, 高度/2)`：范围只有一个节点时高度很小，硬画 12px 会让
两端叠成一团。

**联系线的控制点必须外推，不能取弦中点。** 取中点时二次贝塞尔退化成直线，
两个节点横向相邻时这条直线正好穿过它们中间的那个节点，标题也被压在节点下面
看不见——这是「画出来了但看起来像没画」的典型。

**存储读写对称。** `model/traverse.ts` 加 `collectSummaries` / `collectBoundaries`，
把 `sheet` 级和每个 `topic` 级的合并后按 id 去重；`commands/annotation.ts` 里的
新建 / 改名 / 删除**同时写两级**。这是这批改动里最容易出错的一处：只写 `sheet`
级，XMind 再导入时 `topic` 级的旧副本会赢，表现为「改名无效」。

**改名的 `coalesceKey` 是 `annotation:${kind}:${id}`。** 一个字一个字敲进去要合成
一条撤销记录，否则 Ctrl+Z 要按十几次才回到原名。

**面板新增「结构」页签，不是只加三个工具栏按钮。** 新建是一次性的，改名与删除是
**反复**发生的；只给新建按钮的话，用户建完就再也找不到「把它改掉」的入口。
三节同构（标题 + 提示 + 新建按钮 + 行列表），学会一节就会用另外两节。

**概要与边界计入包围盒，联系线不计。** 前者会真的把画布撑大；后者两端都在节点
中心、弧顶最多外推 60px，撑不开。`export/context.ts` 的 `contentBounds` 因此多了
一个 `annotations` 参数——不加的话导出图会把概要节点裁掉一半。

## Consequences

- `decorations.tsx` 从「自己算坐标」变成「只贴坐标」，导出与缩略图走同一份
  `AnnotationLayout`。所以「导出所见 = 画布所见」不是靠两边写得像，是同一组数字。
- 图层顺序定死：边界 → 连线 → 联系 → 概要 → 主题。边界在连线下面（它是背景区域），
  联系在连线上面（否则被密集的分支线盖住），概要在主题之前（括号的横臂会伸进
  节点之间）。
- 概要在面板里改名会实时反映到画布，但**拒绝空标题**：空标题的附属结构在画布上
  是一块点不中的空白，等于删不掉也改不了。输入框因此用本地 draft 而不是直接
  受控于文档，否则用户删空的一瞬间文字会自己跳回来，看起来像输入法在捣乱。
- 新增 25 个单测（`commands/annotation.test.ts` 13 个、`layout/annotations.test.ts`
  12 个）与一套界面验收 `e2e/annotations.mjs`（IE-ANN-01…11）。
- 已知未做：概要/边界/联系不支持拖动改范围、不支持多选后批量改样式；
  联系线没有箭头（XMind 也没有）。

## Alternatives considered

- **塞进 `layoutMindmap` 一起算。** 试过在布局里加一趟「算附属结构」，但布局函数
  已经 876 行，且折叠逻辑会提前 return；附属结构算在折叠之后才不会给隐藏节点
  画出边界，两段逻辑一缠就得重排整个函数。
- **只读 `sheet` 级、导入时统一拍平到 `sheet`。** 这要求所有写入口都记得拍平，
  漏一个就是数据丢失；而合并读取是幂等的，写两级是幂等的，两边都不依赖调用方
  的自觉。
- **联系线取弦中点（更简单）。** 见上，会退化成正穿节点的一条直线。
- **概要节点固定在「画布最右侧」而不是「范围右侧」。** 多个概要会叠在同一列，
  分不清谁概的是谁。
