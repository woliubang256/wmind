# Agent Note: 多画布、大纲视图与 ZEN 模式

Status: implemented

## Problem

M5 的最后三格：一张导图里放多张画布（底部标签栏）、把当前画布摊成缩进列表
编辑（大纲视图）、以及只剩画布的全屏编辑（ZEN）。

文档模型早就支持了——`WmindDocument.sheets` 是数组，`Sheet` 有 `id` / `title` /
`structure` / `rootTopic`，后端的 `validateDocument` 也是按数组逐张统计节点数。
缺的全在交互层：

- store 里有 `sheetId`，但**没有任何 action 能改它**——`setSheet` 不存在，
  界面永远停在第 0 张；
- `commands/` 里没有画布级命令（新增 / 改名 / 删除 / 排序）；
- 大纲视图和 ZEN 都还是路线图上的两行字。

真正需要想清楚的是三件事：**切换画布算不算文档变更**、**画布名和中心主题名
要不要联动**、**大纲里的缩进用什么键**。

## Decision

### 切换画布是视图状态，不是命令

`setSheet` 挂在 store 上，不进 `commands/`。理由：命令会产生历史记录，而
「切到画布 2」进了撤销栈之后，用户按 `⌘Z` 想撤销的显然是刚才那次编辑，
不是切画布这一步。

切换时清空 `selection` 与 `editingId`：选中记的是节点 id，属于上一张画布，
留着会让下一张画布上同 id 的节点莫名高亮（导入的文档里跨画布同 id 完全可能）。

`HistoryEntry` 里本来就存了 `sheetId`，所以撤销会把画布一起还原——在第 2 张
画布上编辑、切到第 1 张、再撤销，会回到第 2 张看到那次编辑被撤销。这是免费的，
不用额外写。

### 画布名与中心主题名不联动

草图里画布名就是中心主题名（XMind 是这样）。这里**刻意拆开**：

- `doc.title` 已经等于**第一张**画布的中心主题（`changeTitleCommand` 同时写
  两个字段），这是「根主题即文件名」那条老约定的延续；
- 如果每张画布都联动，改画布名就会悄悄改掉图里的字，而「重命名画布」这个
  动作听起来不像内容编辑；
- 反过来，在第二张画布上改中心主题**不能**改掉导图标题——否则用户在画布 2
  上给中心主题起个名字，列表页里的导图名也跟着变了。

`changeTitleCommand` 因此从「当前画布的根主题」改成「第一张画布的根主题」，
画布与大纲共用同一个 `commitTitle`，两处口径一致。

### 大纲视图不持有副本

大纲每次都从 store 的文档里 `flatten` 出来，没有任何本地缓存或同步逻辑。
「双向同步」于是成了架构的结果而不是一项功能：画布改一个字，大纲下次渲染
就是新的；大纲改一个字，画布也是。没有副本，就没有「同步漏了一次」这种 bug。

折叠状态跟着画布走（用扁平表的 `depth` 做一次栈式过滤），否则同一份文档在
两个视图里长得不一样。

### 大纲的缩进不用 Tab

XMind 的大纲用 `Tab` 缩进、`Shift+Tab` 升级。这里用 `Ctrl/⌘ + ]` / `[`：
`Tab` 是浏览器里唯一「离开这个控件」的键，被列表吃掉之后键盘用户就出不去了。
缩进本身也不该占用焦点切换的语义。

### ZEN 的 Esc 挂在 window 上

进 ZEN 会把页头连同「进入 ZEN」按钮一起卸掉，而它正是当时的焦点所在。元素
一消失，焦点落到 `body`，挂在编辑器根节点上的键盘监听再也收不到事件——用户
被关在全屏里。所以 `zen` 为真时把 `Escape` 监听挂到 `window`，并在进入时把
焦点交给画布（否则 ZEN 里什么快捷键都不好使）。

ZEN 用 CSS 撑满视口而不是另挂一棵子树：画布一旦卸载再挂回来，`ResizeObserver`、
字体测量缓存、焦点全都要重来一遍，切进切出会闪。

### 剩下的细节

- **至少保留一张画布**：删除命令在只剩一张时什么都不改（immer 返回原引用，
  store 判定为空操作，既不进历史也不标脏）；删除按钮同时藏起来。
- **有内容的画布才要二次确认**：空画布上没有一个字，`⌘Z` 一秒救回来，再弹
  一次确认只是把「连点两下」变成「连点三下」。
- **删除当前画布后挑邻居接上**：优先右边，没有就左边。不切的话 `sheetById`
  会静默回落到第一张，而 store 里的 `sheetId` 还指着一张不存在的画布。
- **新增画布沿用当前结构**：「再加一张同类型的图」是最常见的意图。
- **切画布重新适配视野**：两张画布的包围盒可以差两个数量级，沿用上一张的
  视口会让新画布要么小得看不清、要么整棵树在屏幕外。
- **页脚的节点数改成「当前画布」**：多画布之后「整份文档 1200 个节点」既解释
  不了视野里那 8 个框，也帮不上任何忙。
- **面板的「画布」标签改名「配色」**：它本来就是配色方案，现在「画布」另有
  所指（多画布），不改会撞车。

## Consequences

- 保存、版本、缩略图、分享、模板都不用改：多画布是**同一份文档内部**多了一层，
  服务端看到的还是一张导图。
- 缩略图跟着「当前画布」走（`useThumbnailUpload` 收的是 `sheetId`）：用户最后
  编辑哪张，列表卡片就显示哪张。这是可接受的，但如果有人期望「封面固定第一张」，
  需要另加一个 `coverSheetId`。
- 刷新后落在**第一张**画布上，不记忆上次看的那张（没有本地视图状态持久化）。
- 大纲是只读+改名+删除+缩进，没有拖拽排序，也没有「新建子主题」的专用键——
  要加子主题得回画布按 `Tab`，或者用行尾悬停出现的「＋」。
- ZEN 里页头一起收起，所以「保存状态」也看不见；自动保存照常跑，但用户在 ZEN
  里无法确认存没存上。要解决得在 ZEN 里挂一个极简状态点。

## Alternatives considered

**把 `sheetId` 放进命令上下文派发（`switchSheetCommand`）**：撤销栈里会堆满
「切到画布 2」，且撤销的语义会变成「先撤销切画布、再撤销编辑」——与用户预期
相反。视图状态就该在 store 上。

**大纲做成可停靠的侧栏（草图里的 `OutlinePanel`）**：要处理拖拽分隔条、宽度
持久化、窄屏折叠三件事，收益是「边看边改」。一期给全屏切换，没有布局回归。

**大纲用 `Tab` 缩进（对齐 XMind）**：键盘用户会被困在列表里，`Tab` 陷阱是
无障碍检查里必挂的一项。

**画布名与中心主题联动（对齐 XMind）**：见上面的 Decision——改名一个画布
会改掉图里的字，代价比收益大。

**切画布时保存一次**：没必要，也不安全。多张画布在同一份文档里，切换不涉及
任何落盘；主动保存会在用户没编辑时也撞版本号，反而多出一堆无意义的 409。
