# Agent Note: 全局错误边界与断网提示

Status: implemented

## Problem

M6 的「错误处理」那一格：全局错误边界、网络异常提示、离线草稿恢复提示。

在这之前，任何一处渲染期异常都会让 React 卸载整棵树——用户看到纯白页面，
控制台里躺着一条没人会去看的堆栈。这不是假设：M2 收尾时就撞到过一次，
`RemoteEditor` 拿到缺 `theme` 的文档后整页变成 react-router 的
「Unexpected Application Error」，而那句注释至今还留在代码里。

第二件事是断网。断网时页面上的表现是一组**互不相干的失败**：列表加载失败、
保存失败、缩略图没了、头像裂了。用户看到的结论是「这网站坏了」，而真实原因
只有一个。

## Decision

### 两层兜底，缺一不可

- **路由层**：`createBrowserRouter` 的默认错误页是一张英文堆栈
  （「Unexpected Application Error」），对用户毫无意义。给路由树加一个
  只挂 `errorElement` 的顶层路由（没有 `element`，等价于 `<Outlet/>`），
  子路由的渲染错误就冒到这里。
- **应用层**：路由之外的壳（`Providers`、`QueryClient`、`SiteHead`）崩了
  没有路由可以兜，所以 `main.tsx` 里再包一层类组件边界。

类组件是硬要求——函数组件实现不了错误边界，这一点在 React 19 也没变。

### 兜底页要能自己恢复、能报障

- 主按钮是「刷新页面」：应用状态已经不可信，刷新是唯一可靠的恢复手段。
  「返回首页」放在次要位置，留给「刷新后仍然崩」的情况。
- 详情折叠区里有**错误编号**（时间戳 + 随机四位的短串）与原始消息，编号同时
  打进控制台。用户报障时把编号贴过来，维护者就能对上那条日志。用随机串而不是
  自增，避免泄露「这是第几次崩溃」这种既无从解释又会吓人的信息。
- 文案**不走 i18n**：这一页要在「i18n 初始化也挂了」的情况下还能渲染，
  把 `t()` 引进来等于给它加一条新的崩溃路径。

### 断网提示用 `useSyncExternalStore` 而不是 effect 订阅

`online` / `offline` 是外部事件源。用 `useEffect` 订阅的话，首帧必然先渲染成
「在线」（初始 state 只能猜），第二帧才纠正——而断网时用户恰恰是**刷新页面**
的那一刻最需要看到提示。`useSyncExternalStore` 的初始快照直接读
`navigator.onLine`，首帧就是真值。

提示条放在**底部居中**而不是顶部通栏：顶部通栏会把页头挤下去，而页头里有
「保存状态」和「返回」，正是断网时最该看的地方。

### 草稿提示复用已有的那一条

编辑器本来就有「发现本地修改，是否恢复？」的横幅（M2.6），断网提示只需要
说明「这期间保存失败是预期的」，不需要再做一套草稿 UI。

## Consequences

- 崩溃兜底页是**整页替换**的：崩溃之后侧栏、页头都没了。这是刻意的——壳自己
  也可能崩，保留它反而可能让兜底页也崩。
- 没有 Service Worker，所以**断网时整页刷新加载不出 SPA**。提示条只对「已经
  打开着的页面」有效。要支持真离线得加 PWA，那是另一个量级的工程。
- 崩溃编号没有上报通道：只进控制台。没有后端接收端点的前提下，上报只是一句
  空话；等有了错误收集服务再补。
- 路由层的 `errorElement` 会同时接住 404 之类的路由响应（`useRouteError` 拿到
  的是 `Response`），所以 `errorMessage()` 对非 Error 的值给一句通用文案，
  而不是硬转成字符串。

## Alternatives considered

**只做路由层 `errorElement`**：`Providers` 自己崩了就没人接。虽然概率低，但
QueryClient 初始化抛错会让用户看到纯白页面，而这类错误恰恰最需要可读的提示。

**用 react-router 的 `RouteErrorBoundary` 组件 API**：它要求每个路由单独挂，
漏一个就回到默认页。顶层挂一次 `errorElement` 覆盖全部子路由。

**断网提示做成顶部通栏 + 把内容整体下推**：会挤走页头的保存状态，而那是断网
时最需要看的东西。

**给崩溃页加「重试」按钮（重新渲染而不是刷新）**：错误边界重置 state 之后
重新渲染同一棵子树，若错误来自不可变的数据（比如坏掉的文档），会立刻再崩一次，
用户看到的是闪烁。刷新页面能保证重新拉数据。
