# Agent Note: 分享链接

Status: implemented

## Problem

M5 里最后一块、也是最大的一块（5 人日）是分享：把一张导图以**匿名可读**的方式
发出去。它不是「加一个页面」——`/s/:token` 是本站唯一一个不经过 `RequireAuth`
的内容页，所有安全边界都得自己立起来。

数据库侧不需要迁移：`share_links` 表与 `idx_share_map` / `idx_owner` 从 M1 就在，
`domain` 里也有 `ShareLink` 的雏形。缺的是从查询到界面的整条链路。

动手前先把 `docs/04` §5.7 与 §7.7 读了一遍，发现设计稿里有五处**照抄会出错**的
地方，下面逐条记决策。

## Decision

[分享密码管理](../feature/2026-10-25-wmind-share-password-management.md)部分取代仅保存不可逆密码的限制：bcrypt 继续负责访客验证，新增仅属主可解密的密文；旧哈希无法恢复原密码，可重设。公开读取不查询密文，公开 DTO 与访问边界继续有效。

分享默认值、备注标签、表单异步配置重置和界面技术说明由[分享默认与说明](../feature/2026-10-24-wmind-share-form-defaults.md)部分取代；下述服务端访问边界、备注剥离与既有链接语义继续有效。下载的技术限制保留在本篇，界面仅说明开关对下载入口的影响。

[作者保存画布视角](../feature/2026-10-25-wmind-saved-canvas-view.md)补齐公开查看器宿主：初始读取作者最后保存画布、视角与折叠，访客在独立副本中临时折叠/展开，双轴滚动条和缩放共用编辑器视口数学，刷新恢复作者状态。焦点重取验证分享权限时不重置当前临时交互；服务端失效检查仍保持本文边界。

### 1. 失效四态统一 404，且四条路径要「看起来完全一样」

令牌不存在 / 已撤销 / 已过期 / 导图已删除，全部 `404 SHARE_NOT_FOUND`，消息体
逐字相同。区分的代价是告诉外人「这个 token 曾经存在过」——那等于把枚举攻击从
「猜 128 bit」降级成「猜一个曾用过的 token」。

实现上有个细节：`GetShareByToken` 用 `INNER JOIN maps` 并**同时选出 `m.deleted_at`**，
把「导图在回收站」折叠进同一条查询。否则要先查 share、再查 map，两条查询之间
用户刚好删图，就会出现「第一次 404、第二次 500」的抖动。

### 2. 站点关闭分享是 403 `SHARE_DISABLED`，不是 404

管理员关掉 `share.public_link_enabled` 时，前端必须能说「本站已关闭分享」而不是
「链接不存在」。前者是管理员的操作，用户需要知道去找谁；把它也糊成 404，用户会
以为是自己手上的链接坏了，反复找分享者要新链接。

而且关闭必须让**历史链接立即失效**，不只是拦住新建。只拦新建等于没有关闭——已经
发出去的链接还在正常工作，验收判据 11 说的正是这件事。所以 `ReadPublic` 第一行
就是 `requireEnabled()`，在任何查询之前。

### 3. `X-Share-Access` 用不同的 `iss`

登录令牌 `iss = wmind`，分享访问令牌 `iss = wmind-share`，同一个密钥签发。

如果 `iss` 相同，分享令牌在结构上就是一枚合法的访问令牌：`typ: share` 只是
payload 里的一个字段，任何一处忘记校验 `typ` 的中间件都会把它当登录态放过去。
改 `iss` 之后，两种令牌在 jwt 库的 `WithIssuer` 校验层就互相拒绝，`typ` 退化成
第二道锁而不是唯一一道。

`sub` 绑 `share.uid`，所以把一个分享的凭证用到另一个分享上会失败——这条单独有
测试。

### 4. 剥离备注用 JSON 往返，不用 `WalkAll`

设计稿写的是遍历文档模型把 `Notes` 清空。实现改成：解成 `map[string]any` → 递归
删 `notes` 与 `extensions` → 序列化回去。

理由是**默认值的方向**。`WalkAll` 依赖模型结构体，将来模型新增一个字段（协同编辑
的内部 id、新的渲染提示），只要没人记得在剥离函数里补一行，它就自动出现在公开
响应里。JSON 往返是相反的：默认全部透传，只删明确要删的，漏删只会漏掉该删的，
不会漏掉新增的。

两个坑：

- 必须 `dec.UseNumber()`。默认解码把数字变 `float64`，`16777217`（2^24+1）会回来
  成 `16777216`。某个节点宽度会静默少 1px，而且只在特定尺寸下出现。
- 剥离必须在**解析之后**再做，解析失败的访问不记入 `view_count`——否则「访问
  次数」里混进了「被服务端拒绝的请求」。

### 5. `UpdateShare` 整行写入

「只更新传入的列」要写 `CASE WHEN narg(...) THEN narg(...) ELSE col END`，而
sqlc 的 SQLite 引擎不会重写 `ORDER BY` / `SET` 表达式里的命名参数（M5.1 排序时
已经踩过）。所以 `UpdateShare` 是全量写，service 做读-合并-写。

非原子，并发 PATCH 是 last-write-wins。可以接受：这几个字段是同一人在同一个
对话框里翻的独立开关，不是多方协同编辑。

`password: null` 与「字段缺省」必须区分（null = 清除密码，缺省 = 不改），所以
handler 用 `json.RawMessage` + `optionalPassword()` 解析这一个字段。用 `*string`
会把两者折叠成 `nil`，结果是「只想关掉下载」顺手把密码抹掉。

已撤销的链接不可修改（`revoked_at IS NULL` 兜在 UPDATE 里）：撤销是终态，允许
修改等于允许复活一条已经告诉对方「已失效」的链接。

### 6. 计数去重 30 分钟，IP 进哈希

键 = token + SHA-256(IP)。同一访客刷新十次不该算十次。IP 不明文存表：访问记录
可能被导出做排查，「哪个 IP 看了哪张图」属于访问数据，不该在表里躺着。

单实例内存实现（`ViewDeduper`），上限 20000 条、超了按窗口修剪。多实例会重复
计数，已抽象为接口，文档里标注了这个限制。

### 7. `allow_download = false` 是降门槛，不是访问控制

分享页要支持折叠和缩放，就必须把文档结构下发到浏览器。所以「禁止下载」能做到的
只有：不显示导出入口 + 拒绝服务端导出接口。懂技术的人开开发者工具照样能看到。

这句话同时写在 `docs/04` §5.7、代码注释和界面上那条 hint 里。不写清楚，用户会
以为它是一道权限墙。

### 8. `site.base_url` 为空时返回相对 URL

`url` 可能是 `/s/<token>`，前端用 `window.location.origin` 补全。反代后面的服务端
看到的 `Host` 往往是内网地址、容器名或带端口的名字，在服务端猜绝对地址比让
浏览器补更错。

前端的 `resolveShareUrl` 对**带 scheme 的值原样返回**，不拼 origin。用 `new URL()`
"解析" `javascript:` 是会成功的，而这个值紧接着进剪贴板。

### 9. 前端结构

- `features/share/share-dialog.tsx` —— 建完**立刻显示链接本身**。用户的下一步一定
  是复制，让他再去列表里找一遍是把成功变成一次额外操作。撤销用 `ConfirmDialog`
  二次确认，记录保留并标「已撤销」，访问次数不丢（用户想看的往往就是撤销前有多少
  人看过）。表单默认值来自 `shareDefaultExpireDays` / `shareDefaultAllowDownload`，
  否则后台那两项设置改了等于没改；每次打开都重置，上次留在表单里的密码不该被复用。
- `features/share/public-share-page.tsx` —— 四种状态各自有界面。`auth: false` 打
  在两个公开接口上：分享页的 401 意思是「需要密码」，走 401→refresh 会把匿名访客
  拖进一条注定失败的刷新链。
- `features/share/shares-page.tsx` —— 分页而不是无限滚动。「我到底发过多少条」用
  页码回答更直接。
- `ConfirmDialog` 从 `features/maps/` 挪到 `components/ui/`：导图页和分享页都要它，
  两份实现迟早在文案或禁用逻辑上分叉。
- 分享对话框**不**动态 import（就几个表单控件，比一次动态导入往返更轻），导出
  对话框**必须**动态 import（字体分片、图片内嵌、栅格化全在里面）。

### 10. `READ_ONLY_PLUGINS` 只挂平移缩放与折叠

只读不是「把编辑 UI 藏起来」，而是那些插件**没有被挂载**——页面上不存在编辑事件
处理器，不是靠 CSS 或 `disabled`。

## Consequences

- 后端新增 9 条查询、`domain.ShareRepo`（10 个方法）、双方言仓储、`ShareTokenIssuer`、
  `ShareService`、`ShareHandler`、6 条路由（3 组：属主维度 / 我的分享 / 匿名公开）。
- `POST /public/shares/{token}/verify` 挂 10 次/分钟的 IP 限流。分享密码常是 4 位，
  没有限流时 10000 种组合几分钟就能穷举完。
- 测试：service 层 15 条（含「访问令牌绑定到自己的分享」、去重窗口三阶段、部分更新
  合并、已撤销不可改）、文档剥离 6 条（含 `16777217` 精度）、去重 4 条、HTTP 层 8 条
  （含「公开路由不得返回 401」、响应体里不得出现 `uid` / `email`）、仓储契约新增
  一条跨双方言的分享子测试。前端 `shares.test.ts` 5 条（相对 URL 补全、`javascript:`
  不补全、按 token 分键存储）。全量 880 条通过。
- 界面验收 24 条（`/tmp/wmind-accept/e-share.mjs`）：判据 7–11 全过；判据 12 只过
  前半句——服务端导出（IE-30）未实现，`POST /maps/{uid}/export` 拿到 404 而非 403。
- 打包新增 `export-dialog` chunk（57 kB / gzip 25 kB），仅分享页与编辑器点到导出时加载。
- 已知缺口：改密码不影响已发放的访问凭证（30 分钟自然过期），要立即失效只能撤销
  重建；多实例部署下访问计数会重复；分享页没有 SEO 用的 `og:*` 元信息（`docs/08`
  列了这一项，未做）。

## Alternatives considered

**失效原因分开返回（410 已撤销 / 410 已过期 / 404 不存在）**：对分享者更友好。
放弃原因是它把「这个 token 存在过」告诉了任何拿到链接的人——包括链接被转发到的
第三方。要区分原因，可以只在属主登录时于 `/shares` 列表里显示，公开接口一律 404。

**把 `share.require_password` 也放进站点公开配置**：前端能提前禁用「创建无密码
链接」的按钮。放弃原因是它只影响提示，不影响结果——服务端该拒还是拒；公开它反而
多给出一条可探测的策略信息。

**`showNotes = false` 时连 `notes` 键都删掉，而不是置空**：响应更小。放弃原因是
置空会让「有备注但内容是空」和「这个版本没有备注字段」不可区分，前端将来要做
「备注图标」时得靠猜。现在整键删除，语义唯一。

**分享页做 SSR / 预渲染 SVG 以支持 `allow_download = false` 的严格模式**：能真正
挡住数据。放弃原因是那等于把渲染层搬到服务端并保持像素一致（IE-30 的完整版），
而分享页当前的第一需求是「能看、能折叠」。严格模式留给二期。

**把访问计数的去重表落库**：多实例天然正确。放弃原因是每次公开读都要多一次写，
而分享页是「一个匿名访客唯一的一次请求」——为它加一次写库，比少算几次访问更贵。
