# Agent Note: 参考色板目录、默认黎明主题与分类 Tab

Status: implemented

## Problem

默认彩虹先降低饱和度后显得偏灰。用户提供 XMind 的色板截图并确认按图实现：缤纷 10 套、经典 9 套，分类使用 Tab，新图默认 Dawn（黎明），中心主题白底黑字。继续对单套彩虹做整体降饱和，无法还原参考图里各套色板的差异。

## Decision

- 以截图中的名称、顺序、色彩组合整理 19 套可见色板；不声称十六进制值来自 XMind 原始文件。每套保留真实颜色数量，填充、连线和彩虹序列同步。
- 新图默认 `vivid-dawn`，中心主题无可见边框、白底深色字。内置色板继续走 JSON 共享数据及最佳深浅文字色规则，全部文字对比度必须 ≥ 4.5:1。
- 对比度不达标时保留色相与饱和度，在两个明度方向寻找最小改动；不再统一给整套色板加灰。接近白色的填充使用稍深的同色相连线，白色画布上的线条对比度至少 1.5:1（可见性门槛，不是文字 AA 阈值）。
- 已有同名色板沿用旧 ID，即便 ID 前缀与新分组不同。旧高熵、和风作为隐藏兼容项保留，参与旧 ID 查找和 XMind 主题匹配，面板只显示 19 套。
- 不迁移已保存的完整 Theme，不覆盖节点显式样式。新图和主动选择色板才使用新值。
- 两个分类 Tab 只切换浏览内容，点击色板才产生编辑命令；按名称在上、连续色条在下排列两列。支持键盘、选中描边和中英文名称。

### 分类回显与浅色连线

分类浏览状态同时记住当前应用的主题 ID，每次主题 ID 变化都同步更新。仅在渲染时比较“浏览时 ID 是否相同”会在撤销回到旧 ID 时命中过期的浏览分类；浏览器回归覆盖应用、切换分类、撤销和重做的交替序列。

`branchColor` 对仍使用色板默认值的彩虹分支读取独立 `lineColors`，避免把白色填充直接用作白色连线；另外指定的彩虹颜色仍沿用用户选择，不替换其值。`themeSwatchColors` 的预览上限从 6 增为 8，完整显示七色主题，不改保存的颜色序列。

## Alternatives considered

- **继续微调一套低饱和彩虹**：改动小、能保留此前已确认的柔和方向；但实际画布已经被用户否定为过淡，且不能提供截图中的完整两组选择。
- **删除旧色板，只留新目录**：目录最简单；但旧模板与导入可能仍引用旧 ID 或旧颜色，保留两个隐藏兼容项能避免回退并不增加面板负担。
- **Tab 一切换就应用该分类首项**：一步就能看到新颜色；但浏览会改动文档、增加撤销历史，和“选择色板才应用”的预期冲突。

## Testing

- 缤纷 10 套、经典 9 套，名称顺序和配色接近参考图；新图中心无色块，分支使用黎明。
- 字色对比度检查、旧主题解析、旧 ID 导入匹配均通过。
- 分类 Tab 支持左右键及 Home/End；切换分类不改变画布、保存状态或撤销历史。
- 19 套逐个应用不丢标题或节点，保存刷新及撤销重做有效，节点显式颜色不被冲掉。
- 中英文、浅深主题及窄屏中可以辨认名称、选中态和色条。
- `frontend/e2e/palettes.mjs` 覆盖真实新建、分类与键盘、19 套画布指纹、浅色连线、保存刷新、七色自定义主题、撤销重做、旧主题保留、中英文及窄屏；已接入 `run-all.mjs`。
- 主题解析、样式、旧主题匹配、模板和语言包使用对应的 Vitest 测试；`npm run check:palette` 校验可见 19 套与兼容 2 套。

## Consequences

- 截图采样存在显示与压缩误差，最终需用同一画布检查观感；对比度校验只能保证文字可读。
- 已保存导图不会自动变为新配色，需要用户主动选择。
- 旧前缀 ID 与新分类可能不同，但没有强制迁移文档；目录展示和匹配范围分开，兼容项不增加界面负担。
