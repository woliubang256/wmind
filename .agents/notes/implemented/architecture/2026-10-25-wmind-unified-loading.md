# Agent Note: 加载界面统一 W 扫光与图片就绪边界

Status: implemented

## Problem

认证页已有 W 扫光，其余页面仍混用文字、旋转圆圈和骨架。图片请求尚未完成时没有一致的占位，直接复用整页灰度又会抢走内容的视觉重心。画布与导出共用 SVG 渲染器，加载占位不能进入导出成品。

## Decision

共用 LoadingMark 的标准、小号、行内和浅灰外观。LoadingState 提供统一状态语义与必要文字，供页面、列表、表格和弹窗共用；按钮只替换现有加载表现，保留操作文字、禁用条件和具体进度，不把所有 disabled 按钮误判成加载。

LoadingImage 按 src 隔离就绪状态，兼容浏览器缓存、懒加载、地址切换和失败回退；加载中显示浅灰 W，成功或失败均停止动画，不新增网络预请求。SVG 图片使用独立的 LoadingSvgImage，仅实时查看器启用，静态导出输出原始 image，不含占位或动画。图片尺寸仍由原有几何决定，不参与文档存储、布局测量和撤销历史。

## Historical audit

按 LoadingMark、扫光、loading-mark 搜索活跃笔记无已有归属。字体分片笔记的“字体就绪后再测量”仍成立；图片上传笔记的显示尺寸与来源规则仍成立；头像笔记的手动头像、Gravatar、首字符回退顺序仍成立。本方案只统一等待时的表现。

## Alternatives considered

- **全局 CSS 改造现有 spinner 和骨架**：迁移最少，不触碰调用方；但不能给纯文字状态增加图标，也无法可靠判断图片加载完成和失败，故用显式组件。
- **预先用 Image 加载全部图片**：HTML/SVG 可共用一套预取结果；但会绕过 lazy loading、重复请求并增加 CORS/缓存分支，故监听原生图片事件。
- **在所有 SVG 输出里保留加载 W**：查看器和导出无需区分；但静态渲染无法接收 load 事件，W 会留在导出成品，故仅实时查看器启用。

## Consequences

- 整页、局部、按钮加载共享同一 W 与尺寸约定；具体进度和错误必须保留，不重复添加说明。
- 图片不额外预取，浅灰在深浅主题分别定义，原生 load/error 和缓存 complete 均结束等待。减少动画设置保留静态标志。
- 导出默认只输出原始 image；实时渲染必须显式启用加载占位。
- 图片新增状态会增加每张图的组件成本；只有等待期间渲染动画，完成后卸载。极小头像使用缩小的 W；画布图片仍随当前缩放缩放。

## Testing

组件单测覆盖轮廓、尺寸、浅灰、多实例 ID、状态文字唯一、原生图片参数和静态 SVG 不含占位；浏览器夹具只模拟接口和图片，不修改开发数据库。
