# Agent Note: 登录密码使用公钥信封与共享一次性挑战

Status: implemented

## Problem

HTTPS 已加密网络传输，但当前登录 JSON 直接含有原密码，TLS 终止后的请求体日志仍可能暴露密码。用户要求登录请求体使用公钥加密，同时兼容既有 bcrypt 账号、2FA 和 PostgreSQL 多实例。

## Decision

登录先 POST `/auth/login/challenge`，提交账号标识；服务端不查询账号是否存在，统一返回随机 256 位挑战、RSA-OAEP-256 公钥和 120 秒有效期。浏览器通过 Web Crypto 使用 OAEP 的 label 绑定挑战，只加密密码；POST `/auth/login` 只接受 identifier、challengeId、encryptedPassword，拒绝原 password 字段及混合请求。HTTPS（或本机开发的安全上下文）仍是前提；不支持 Web Crypto 时明确报错，不能回退明文。

独立 `login_challenges` 表保存挑战哈希、规范化账号哈希、到期毫秒和 AES-256-GCM 加密的 PKCS8 私钥。每个进程只生成一对 RSA-2048 密钥，私钥按挑战随机封装，AES 密钥从现有有效 2FA/环境密钥按独立用途派生；无需新环境变量和密钥挂载。挑战封装的 AAD 绑定挑战、账号及到期时间，跨实例可用共享环境密钥解开，不依赖会话粘滞、进程缓存或启动顺序。

双方言用一条 DELETE RETURNING 原子消费未过期且匹配账号的挑战，消费在解密和 bcrypt 前完成，错误密文/错误密码也不可重试同一挑战。RSA label 阻止相同公钥下的跨挑战密文搬运。新增挑战时清理到期行，expiry 索引控制清理成本，公开挑战入口按 IP 限流并限制请求体大小。密钥、原密码、密文和挑战不进入日志；失败不回传原始加密错误。

应用 ZIP 归档不包含 login_challenges，成功恢复在同一数据库事务中清除现存传输挑战；恢复失败回滚保持原状态。数据库物理备份依然可能包含尚未清理的封装私钥。

后端仅将解密后的密码交给既有 Login 服务，2FA、状态检查、失败锁定和 Cookie 策略沿用旧契约。前端每次主动提交重新获取挑战，不缓存密码、私钥或挑战到持久化存储；网络结果不确定时也不自动重放登录。

## Alternatives considered

- 仅依赖 HTTPS 是标准密码登录的常用做法，协议简单且已保护网络传输；用户另外要求请求体不直接出现密码，因此增加应用层信封，但不宣称替代 TLS、抵御页面脚本或数据库和环境密钥同时泄漏。
- 固定 SHA256/MD5 可减少前端改动；摘要本身会成为可重放的等价密码，并且无法沿用现有 bcrypt 校验，故不采用。
- 挑战及私钥只放进程内存，最省数据库代码；请求落到另一实例、进程重启及并发消费会失败或被重复接受，故共享挑战和封装私钥进入数据库。
- 共享明文 PEM 环境变量或新密钥文件支持成熟 RSA 工具链；却额外要求部署者配密钥、处理挂载和多实例同步，故使用现有环境密钥分用途封装短时挑战私钥。

## Verification

RSA 原语测试通过，覆盖跨实例、随机密文、中文及字节上限、label/AAD/密文和密钥篡改。旧明文 HTTP 登录先复现为 200，而新契约要求 400。迁移 0005 和 sqlc 双目标生成完成，真实 SQLite 迁移结构测试通过。

SQLite 和 PostgreSQL 的完整仓储契约均通过 `-race` 验证，覆盖账号隔离、有效期边界、过期清理、十二个并发消费者恰有一个成功及事务回滚，双方言采用相同 DELETE RETURNING 查询。

测试同样遵守分层：真实数据库与跨实例服务互通放在 `internal/integration`，服务单测只使用领域仓储桩验证账号绑定和有效期参数；`dialectcheck` 不为测试放宽规则。

两个独立 LoginEncryption 实例共用真实 SQLite 挑战表，通过不同 RSA 进程密钥及共享环境密钥完成跨实例解密，重放拒绝通过；服务单测验证 120 秒毫秒边界、规范化账号绑定和非法输入。这两项测试均通过 `-race`。原明文 HTTP 复现已变绿，错误密码、未知账号、账号替换、篡改和混合提交定向集成测试通过。

两个独立 API 进程共用真实 PostgreSQL：在 A 获取挑战、在 B 登录成功、在 A 重放得到 422；同一信封并发发送到 A/B，只产生一个 200 和一个 422。

HTTP 完整认证回归通过，OpenAPI 与实际 63 条路由一致；公开挑战有 4 KiB 请求限制、严格字段解析、无会话 Cookie 及 60 次/分钟限流。限流返回也必须 no-store，该缺口由第 61 次请求先复现再修复。

前端全量 1251 项单测、类型检查和生产构建通过。真实 Chromium 的 9 项登录协议验收通过，包括捕获请求体不含原密码、bcrypt 账号会话、重放/明文拒绝、错密后新挑战及加密能力缺失时无回退。

真实浏览器 2FA 验收 8 项通过，覆盖验证器、恢复码、重放拒绝、重新生成恢复码、停用、旧令牌失效以及中英文和窄屏。浏览器 REST 辅助方法同步使用 RSA-OAEP，2FA 脚本通过现有顶栏语言入口切换。

后端包测试通过，PostgreSQL 备份往返在全新隔离数据库验证成功；应用归档排除临时挑战、恢复成功清除挑战、失败恢复回滚均有双方言契约覆盖。双目标 sqlc 生成无漂移、迁移 parity、`go vet ./...`、`dialectcheck` 与笔记门禁通过。

## Consequences

登录请求体不直接包含原密码，截获的信封无法重复使用，既有 bcrypt 账号与 2FA 保持可用；代价是每次登录增加一次请求、一次挑战写入与原子删除。挑战存储为短期私有状态，其中不含原密码。数据库与环境密钥同时泄露会暴露挑战私钥，应用层信封不抵御服务器控制权丢失。升级需要应用迁移 0005，旧前端必须同步更新，旧明文 HTTP 客户端需迁移；注册、改密及其他密码接口本次不改变协议。
