# Agent Note: 导出长宽比（M4.10 的一部分）

Status: implemented

## Problem

导出的图尺寸完全由内容决定：一张横向很宽的导图是 1762×528（约 3.3:1），贴进 16:9
的 PPT 会留两条巨大的白边，发朋友圈会被裁掉两头。用户只能导出后再去别的软件里
对比例——而「导出」本来就该是最后一步。

docs/06 §3.7 把「长宽比（16:9 / 4:3 / 1:1 / 9:16）」列为待实现项。

## Decision

### 只加边，不裁切

目标比例比内容「宽」就加宽，比内容「高」就加高，内容永远完整。另一种做法是裁切到
目标比例，但那是**另一个产品**（「裁剪导出」）：用户没法从「长宽比 16:9」这个词
判断自己会拿到「加了两条白边」还是「被切掉了右边三分之一」。真要做裁切，它应该是
一个单独命名的选项。

实现是 `fitAspect(width, height, ratio)`，纯函数：

- `current < ratio` → 加宽（`height * ratio`），高度不动；
- 否则加高（`width / ratio`），宽度不动。

### 多出来的空间取整后对称分配

`width + extra * 2`，而不是让两侧各得 `(need - width) / 2` 的小数值。半像素偏移在
栅格化时会变成一条模糊的边；而且 `extraX` 只取整一次再翻倍，左右必然相等——直接
两边各取整的话，奇数差会让一侧比另一侧多 1px，肉眼能看出来。

代价是最终比例与目标可能差 1 个逻辑像素（乘倍率后 1–4 像素）。实测：
881×264 的图导出 1:1 得到 1762×1764（差 2 设备像素 / 1764），16:9 得到 1762×992。

### 居中的是内容盒，不是整张画布

页脚（品牌标识、日期）在基础高度里已经占掉 `FOOTER_HEIGHT`。所以竖直居中做在
「内容 + 留白 + 页脚」这个盒子上，品牌/日期贴画布底边——它们是水印，不是内容。
测试里钉住的不变式是 `下边距 − 上边距 = 页脚高度`，比「上下相等」更准确。

## Consequences

- `ExportOptions` 多一个 `aspect`（默认 `auto`），`ExportContext` 尺寸计算多一步
  `fitAspect`。`auto` 时 `extraX/extraY` 都是 0，行为与之前完全一致。
- 文本格式下这个选项随其余图形选项一起收起（Markdown / OPML 没有画布）。
- 长宽比只改画布尺寸，不改内容：图片、连线、关系线的坐标都没动过，所以不存在
  「加高之后某个装饰跑位」这类问题。

## Alternatives considered

- **裁切到目标比例**：见上，语义含糊且会丢内容。
- **让用户手填宽高**：比四个预设自由，但要用户自己算比例，而且填错就会裁切。
- **把内容缩放到刚好填满目标比例**：会改变字号，等于偷偷改了导图的排版。
- **在导出后用一个 canvas 二次合成加边**：多一次全图重绘，且 SVG 输出也要走位图
  路径——直接在上下文里改尺寸，两种输出都能用。
