# Agent Note: 图片导出（M4.7）

Status: implemented

## Problem

M4.6 只导出了 SVG。用户真正会用的格式是 PNG——贴进文档、发到群里、当 PPT 配图，
SVG 在这三个场景里都不好用（Word 对 SVG 的支持时好时坏，微信直接不认）。JPEG 更
极端：很多内部系统只收 JPEG。

栅格化本身不难，难的是三件「不写就会错」的事：

- **Canvas 有尺寸上限**，而且超限的表现是**静默失败**：`drawImage` 不报错，只给
  一张空白图，或者把图裁掉一块。用户拿到的是「导出成功了，但图是白的」。
- **JPEG 没有 alpha 通道**。透明像素会被编码成黑色，而预览里看到的是白底——最
  典型的一种「预览与成品不一致」。
- **中文与字体**。SVG 通过 `<img>` 载入时拿不到父页面的 `@font-face`。

## Decision

### 尺寸闸门分三级，不是一个布尔值

`checkRasterSize` 返回 `ok` / `warn` / `too-large`：

| 情况 | 结果 |
| --- | --- |
| 单边 ≤ 8192 且总像素 ≤ 268M | `ok` |
| 单边 8192 ~ 16384，总像素 ≤ 268M | `warn`：提示卡顿，允许继续 |
| 单边 > 16384 或总像素 > 268M | `too-large`：禁用下载按钮 |

合成一个布尔值的话，用户要么在 9000px 时被拦住（明明能导），要么在 20000px 时
拿到一张空白图（明明不该导）。三个数都有出处：16384 是 Chrome / Firefox 的单边
硬上限，8192 是 Safari（尤其 iOS）的实际可用上限——它超限时**不报错**，只会裁图
或给白图，所以只能靠保守的阈值提前警告。268M = 16384²，按 4 字节/像素算正好 1GB。

「尺寸算不出来」也归到 `too-large`：宁可拦住，也不要拿一张 0×0 的图去撞 canvas。

**SVG 不受这个限制**，所以「太大」时的出路写的是「降低倍率**或改用 SVG**」——
只给「降低倍率」等于逼用户牺牲清晰度。

### JPEG 的透明在上下文阶段就处理掉

`ExportOptions.format` 参与背景计算（`backgroundColor()`）：

- `jpeg + transparent` → `#FFFFFF`；
- `png + transparent` → `null`（保留 alpha）；
- 不透明 → 主题背景色。

不是等到 `toBlob` 之前才补白。原因只有一个：**预览与成品必须一致**。预览用的
是 `ctx.background`，如果上下文里是透明的、编码时才补白，用户就会在棋盘格上
看到一张图、拿到手是一张白底图。顺带在选项面板补一句「JPEG 没有透明通道，将
填充白色」——勾着「透明背景」却看到白底，不解释一句就是「选项失效」。

`rasterPlan()` 里 `jpeg` 的 `fill` 兜底成 `#FFFFFF` 而不是 `null`：即使调用方
漏传背景，也不能产出一张黑底 JPEG。

### 画布尺寸取目标值，不取 `<img>` 的自然尺寸

SVG 里的 `width` / `height` 已经是「逻辑尺寸 × 倍率」，看起来用 `naturalWidth`
等价。但浏览器对超大 SVG 会降采样，`naturalWidth` 可能小于声明值——用目标值
才拿到用户要的精确像素数。

### 先铺底色再 `drawImage`

顺序反了底色会把图盖住。`raster.test.ts` 里用调用顺序断言（`['fill', 'draw']`），
因为这件事在浏览器里肉眼看不出来，但错了就是一张纯色图。

### 顺手修掉关系线的「标签被节点盖住」

导出验证时发现：`RelationshipsLayer` 用弦的中点当二次贝塞尔的控制点，曲线退化成
直线，横向相邻的两个节点之间那条线正好穿过中间那个节点，标题也被压在节点下面。
画布上同样看不见，只是没人注意到。

改成控制点沿法线外推（弦长的 1/4，封顶 60px），标题放在 t = 0.5 的位置。这样
关系线是一段真正的弧，绕开节点，标题也露出来了。

## Consequences

- 新增 `frontend/src/editor/export/raster.ts`：`RASTER_LIMITS` / `checkRasterSize` /
  `rasterPlan` / `rasterizeSvg`（依赖注入，纯逻辑可测）。
- `ExportOptions` 多一个 `format` 字段；`buildExportContext` 的背景计算按格式分支。
- 导出对话框：格式单选（SVG / PNG / JPEG）、底部三态提示（尺寸 / 超限 / 图片未内嵌）、
  栅格化期间按钮显示「正在生成…」并禁用，失败时 `toast` 且**不关对话框**（关掉会
  丢掉用户刚调的选项）。
- 文件扩展名按格式给：`.svg` / `.png` / `.jpg`。
- `decorations.tsx` 的关系线改为真正的弧，标题不再被节点遮挡。
- 前端 751 个测试，其中 `raster.test.ts` 18 个（尺寸三级、JPEG 不透明、调用顺序、
  失败也释放 objectURL）。
- **`too-large` 的 UI 路径只有浏览器手工验证**：用 `/maps/stress`（2000 节点）
  拉到 4× 得到 3096×239136，按钮禁用、提示正确。没有自动化 UI 测试（项目没有
  jsdom，组件测试做不了）。

## Alternatives considered

**`canvas.drawImage(svgElement)` 直接画 DOM**：少一次编解码，但在部分浏览器上
得到空白画布——`drawImage` 不接受没被渲染过的 SVG DOM。走 `Blob` + `<img>` 是
唯一稳定的路径。

**用 `img.naturalWidth` 定画布尺寸**：看起来更「忠实」，实际会被浏览器的超大
SVG 降采样坑到。

**JPEG 透明时留 `null`，交给 `toBlob` 处理**：`toBlob` 不会帮你补白，透明像素
在 JPEG 里变黑。必须在画布上先填。

**超限时自动降倍率**：用户选的 4× 被悄悄改成 2×，导出的图糊了却不知道为什么。
宁可禁用按钮并说清楚。

**超限时自动切到服务端导出**：服务端导出本身还没实现（路线图里是可选项），
而且它同样受渲染尺寸限制，只是换了个进程崩。

**关系线保持直线，只把标签挪开**：标签挪开之后线还是穿过节点，看起来像连错了。
控制点外推的改动只有十几行，顺手就修了。

**栅格化失败也关掉对话框**：用户刚调好格式与倍率，关掉等于让他重来一遍。
