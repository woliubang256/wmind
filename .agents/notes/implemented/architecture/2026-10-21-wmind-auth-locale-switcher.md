# 登录页右上角的语言切换

- 日期：2026-10-21
- 分类：architecture
- 关联：`frontend/src/components/locale-switcher.tsx`、`frontend/src/features/auth/{login,register}-page.tsx`、`frontend/src/lib/i18n/preference.ts`、`frontend/e2e/locale.mjs`

## Problem

语言偏好存在浏览器里（`wmind:locale`），而**唯一能改它的入口在 `/account`**——
那是登录之后才到得了的页面。第一次来的人恰好是最需要它的：

- 浏览器报 `en-US`、站点却是中文界面（或者反过来）；
- 他读不懂「用户名」三个字，因此也进不去设置页；
- 除了猜，这一页没有任何出路。

这不是「少一个便利功能」，是**首次使用的死锁**：要改语言得先登录，要登录得先
看懂当前语言。同一个问题在 `/register` 上更严重——那一页还有「本站暂未开放注册」
这种只有一句话的终止态。

## Decision

在登录页与注册页卡片的**右上角**放一个原生 `<select>`，三个选项（跟随浏览器 /
中文 / English），并且让它成为页面上**第一个可聚焦元素**。

四个具体选择：

1. **原生 `<select>`，不是按钮 + 弹出层。** 三个选项、无分组、无搜索、无多选，
   弹出层能做的它都能做；键盘、读屏、触摸、移动端滚轮全部由浏览器负责，不用
   自己写焦点陷阱和 `Escape`。`styles.css` 里已经按 light/dark 设了
   `color-scheme`，深色主题下原生下拉也是深色，不会白底白字。
2. **`LOCALE_LABEL` 提到 `lib/i18n/preference.ts`。** 设置页的分段控件与这里的
   下拉是同一份列表，两处各写一份必然出现「加语言时漏改一处」。原来那张表在
   `account-page.tsx` 里是模块级常量，现在两个页面共享。
3. **语言名用该语言自己的写法**（中文 / English），只有「跟随浏览器」跟着界面
   语言变——它本来就没有自己的写法。否则英文界面下是 `Chinese` 与 `English`、
   中文界面下是「中文」与「英文」，用户要在一堆看不懂的字里找看得懂的那一个。
   `<option>` 上同时标 `lang`，读屏才会用对语音包。
4. **注册页的两个分支都加**：正常表单，以及「暂未开放注册」的终止态。后者只有
   一句话和一个返回按钮，是**最需要**切换的地方——把它漏掉，关站期间英文用户
   连「这里为什么不能注册」都读不懂。

`mt-5`（sm 起 `mt-7`）是给 logo 让出来的一行高度：绝对定位的控件不占流，窄屏上
会和居中的 logo 在角上蹭到一起。

## Consequences

- 语言从「设置项」变成「首屏可见的控件」。`/account` 那张卡片保留——它带说明
  文字（「只影响这台设备上的界面文字」），适合需要解释的人；右上角那个只负责
  「我现在就想换」。
- 新增 `frontend/e2e/locale.mjs`（12 条）：入口存在、**几何位置在右上角**
  （`gapRight`/`gapTop` 都 ≤ 40px）、**第一个 Tab 落在它上面**、切英文后整块卡片
  零残留中文、`html[lang]` 与 `localStorage` 同步、刷新后保持、注册页与关站页
  同样有入口、切回中文。
- 那套脚本会关一次注册（验关站页），`finally` 无条件恢复——与 `register.mjs`、
  `export.mjs` 同一约定。
- 「整块无中文」这条用克隆节点 + 摘掉 `<select>` 做。第一版顺手把 `<label>` 也
  摘了，结果输入框的「Username or email」一起没了，断言失败看起来像漏翻，实际
  是脚本把要验的东西删了。`<select>` 必须摘（下拉里永远有「中文」两个字），
  `<label>` 不能摘。
- 与 `export.mjs` 里那批语言断言的分工：那边验「登录之后」的界面（导航、账号页、
  导出对话框），这边验「登录之前」的三页。两边都改语言，互不影响——每套脚本
  独立进程、独立 context。

## Alternatives considered

- **放在登录卡片底部、和「忘记密码」并排。** 不占额外高度，但落在视线之外：用户
  的第一反应是「这页有英文版吗」，眼睛扫的是边角，不是表单下面。
- **放在页面最外层（`AuthLayout` 的右上角，贴视口）。** 视觉上更「全局」，但
  `AuthLayout` 是 `place-items-center` 的居中容器，绝对定位要额外包一层，而且
  离卡片太远会让人不确定它管的是整页还是卡片。
- **用按钮切换（中 / EN 两个状态）。** 少一次点击，但表达不了「跟随浏览器」这
  一档，而这一档恰恰是新用户的默认值——把它藏起来，用户会以为站点只有两种语言。
- **做一个「首次访问按浏览器语言自动选」的弹窗。** 弹窗比下拉更打扰，而且它要
  在用户还没读任何文字之前要求一个决定。
