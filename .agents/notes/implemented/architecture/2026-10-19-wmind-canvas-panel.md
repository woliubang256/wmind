# Agent Note: 画布面板：样式 Tab、配色 Tab 与键盘归属

Status: implemented

## Problem

M3 要交付「样式面板 + 配色面板」，对标截图 3 与截图 4。开工前有几件事必须定下来，否则后面全是返工：

- 面板改的是节点还是文档？两者的撤销、持久化、换主题行为完全不同。
- 回显哪个值？`topic.style` 里大量字段是 `undefined`（继承），直接显示会满屏「未设置」。
- 颜色字段的「继承」怎么表达？`fill: null` 在解析链里是「无填充」，不是「跟随主题」。
- 面板出现之后，快捷键归谁？原来的监听挂在画布上，焦点一进面板 `⌘Z` 就失灵。
- 截图 4 的「同级主题对齐」开关在布局里根本没实现，做不做？

## Decision

### 样式改节点，画布改文档

两个 Tab 的边界就是数据边界：样式 Tab 写 `topic.style`（是内容，进撤销栈、进自动保存），画布 Tab 写 `doc.theme`（不碰任何节点）。这样「换配色不丢内容」不需要额外机制，它是两个字段本来就不相交的结果。

配色页内的「缤纷 / 经典」分类 Tab 只切换浏览状态，点击某个色板才写 `doc.theme`。19 套目录、连续色条、分类键盘和旧主题兼容见[参考色板目录](2026-10-23-wmind-reference-palettes.md)。

### 回显解析后的样式

`StyleTab` 的 `style` 取自 `layout.styles`（布局阶段已经算好的 `ComputedStyle`），不是 `topic.style`。一级分支的填充色是渲染期按 `branchIndex` 从调色板算出来的，`topic.style.fill` 通常是 `undefined`——拿它当显示值，面板会写「继承」而画布上明明是红色。

复用 `layout.styles` 而不是再 `resolveStyle` 一次，也顺手保证了「面板显示的颜色」与「画布用的颜色」是同一个对象，不会因为上下文算错而错位。

### 颜色的三种状态，用 `undefined` 表示继承

`updateStyleCommand` 原先的语义是「`null` = 清空该字段、回到继承」，但解析链里 `null` 是**有效值**（`fill: null` = 无填充，且不会被调色板顶掉）。两种「空」被混成了一个，用户改完颜色就再也退不回「跟随主题」。

改成：补丁里 `undefined` = **把键从 `topic.style` 里删掉**（回到继承），`null` = 显式的「无」。面板上对应三个入口：色块、`无填充`（仅填充字段）、`继承主题`。

`JSON.stringify` 会丢掉 `undefined`，所以样式缓存键与磁盘格式都不受影响。

### 只用原生控件

`<button aria-pressed>`、`<select>`、`<input type="checkbox">`、`<input type="color">`，没有任何自绘弹层。自绘取色器要自己补焦点陷阱、方向键调值、Esc 关闭、点击外部关闭——这四件事任何一件没做对，键盘用户就卡在弹层里出不来。原生取色器各平台长相不同，但都能用键盘打开。

代价是「取色」这一步必须依赖系统对话框，所以每个颜色字段都并排放着预设色块：不想进系统取色器时直接点色块。

色块的 `aria-label` 写的是色值本身。60 个色值里「浅蓝」和「天蓝」根本区分不开，写色值至少是可核对的。

### 快捷键的归属：两级过滤

`useHotkeys` 从画布容器上移到**编辑器根节点**（画布 + 面板），并加第二级过滤：

- 文本输入框里：所有键都不拦（`⌘Z` 留给浏览器做文字撤销）；
- 按钮 / 链接 / 选项卡 / 复选开关上：只拦不带修饰键的键，`⌘Z` / `⌘S` 照常作用于导图。

没有第二级过滤的话，裸 `Tab` 会在面板里被「新建子主题」吃掉——用户想从色块跳到下一个控件，结果画布上多了一个节点。反过来，只保留第一级的话，焦点停在色块上按 `⌘Z` 什么都不会发生，用户会以为撤销坏了。

### 「同级主题对齐」实现为列布局

普通布局里子节点的 x 是「父节点右边 + 间距」算出来的，同层不同宽度的父节点会把各自的子节点推到不同的列。打开对齐后先算出每层最宽的节点，给该层预留一列，所有同层节点落在同一列的左边缘（左侧分支对齐右边缘）。

代价是画布变宽：一层里只要有一个长标题，整层都按它留白。所以这是开关而不是默认。自由主题不参与列对齐——它们的起点是整棵树的左边界，套用主树的列坐标会被拽到树中间去。纵向树忽略这个开关（它对齐的是行）。

## Consequences

- 面板宽度 288px 固定，画布用 `flex-1`；收起后画布自动变宽，`ResizeObserver` 会重新适配视野。
- `StyleTab` 在未选中任何节点时作用于**中心主题**，而不是禁用整块面板。用户打开新图想先调中心主题，不该先学会怎么选中它。
- 一次改色 = 一条撤销记录。拖动 `<input type="color">` 的取色器会连发多次 `change`，目前每次都会压一条历史；等 M6 做「连续操作合并」时用 `coalesceKey` 收拢。
- 面板里的下拉同时出现在页头（结构切换）与样式 Tab 里，两处绑同一个 `sheet.structure`，不会漂移；页头那个是快捷入口。
- `docs/05 §5.4` 已改写为实际实现，并列出与截图 4 的四处差异（纯色带代替渐变缩略图、原生取色器、多出「继承/无填充」两个按钮）。
- `docs/05 §4.6.2` 补上了两级过滤的说明，并把 `Ctrl+F` 查找从「M3 一起做」改到 M6——M3 的交付物里本来就没有它。

## Alternatives considered

- **面板直接读写 `topic.style`**：实现最省事，但一级分支的颜色永远是「未设置」，面板与画布对不上。
- **用 `null` 兼表「继承」**：需要改解析链把 `null` 当成跳过，于是「无填充」这个真实需求就没法表达了（XMind 里透明节点是常用的）。
- **自绘取色弹层**：视觉更统一，但键盘可达性要自己从零做对。
- **快捷键继续只挂画布**：面板里按 `⌘Z` 无反应，是那种「用一次就再也不信撤销」的体验。
- **「同级主题对齐」先放个不生效的开关**：面板上点下去毫无反馈，比没有这个开关更糟。
