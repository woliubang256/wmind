# Agent Note: 时间轴、鱼骨、括号与树型表格

Status: implemented

## Problem

M3.4 要补齐 `timeline` / `fishbone` / `brace` / `tree-table`，让九种结构都有真实几何。四个问题：

- 主轴、鱼骨的主骨、括号的竖干这些「结构装饰」怎么画？它们不是父子连线，但只能用连线画。
- `lineStyle` 是文档字段（用户可选的四种），结构自带的画法要不要塞进去？
- 鱼骨的主轴和鱼头之间没有父子关系，谁负责画？
- 树型表格的行高怎么定才不会让父节点压到上一行？

## Decision

### 三种画法，不是一个算法套九次

- **横向树**（`mindmap` / `logic-right` / `logic-left` / `tree-right` / `brace`）共用 `layoutHorizontal`，差别只在分侧与连线形状；
- **纵向树**（`org-chart`）是横向树的转置；
- **专用几何**（`timeline` / `fishbone` / `tree-table`）各有一套摆放规则。

前两族共用带式布局，是因为它们的差别只是「带」按高度还是按宽度切。后三种不是：时间轴的主轴是一条线，鱼骨是斜插，表格是一层一列一叶一行——把它们硬塞进 `layoutHorizontal` 会得到一堆 `if (structure === ...)`，比各写一份更难读。

### 结构自带的画法是 `EdgePath` 的私有形状

`EdgePath.lineStyle` 从 `LineStyle` 放宽为 `EdgeShape = LineStyle | 'axis' | 'brace'`。

- `axis`：先横后竖。时间轴里所有 `axis` 线段的**横段叠起来就是那条主轴**，竖段就是每个节点的刻度——不需要额外画一根「主轴」元素。
- `brace`：从父节点横出一小段，在**同一个 x** 上竖直走，再拐进子节点。同一个父节点的所有子线共用这个 x，合起来就是「}」。

两种形状只存在于布局与渲染之间的契约里，**不进文档**：`Style.lineStyle` 仍是 `straight | curve | elbow | none`，存量文件与导入导出不受影响。让布局层直接给出形状、而不是让渲染层看 `sheet.structure` 猜，是为了不让「结构」这个概念漏进渲染层。

`brace` 结构因此只需要「几何同 logic-right + 连线换成 `brace`」两行，不用另写一套摆放。

### 鱼骨的主轴是一条合成边

主轴从鱼头左边缘拉到最远的附着点，两端没有父子关系。用 `id: 'spine:<rootId>'` 的合成边表示，`parentId` / `childId` 只是借位——`EdgePath` 本身不要求两端真有父子关系，渲染层只负责画。

代价是 `edges` 数组里出现一条「不是父子连线」的记录。目前没有任何代码假设 `edges[i].parentId` 一定是 `childId` 的父节点（拖拽落点用 `boxes`，导出按路径画），所以这个假设成立；写进注释以免以后有人按父子关系去反查。

### 树型表格用统一行高

行高取**所有节点的最大高度**加一点间距，而不是每个叶子按自己的高度排。

按叶子高度排会紧凑一些，但父节点可能比它那一行还高，于是压到上一行去。表格里出现重叠比浪费几像素难看得多，而且「一行一叶」的语义也要求行是等距的。

### 堆叠布局单独一套高度函数

横向树的 `subtreeHeightOf` 是 `max(自身, 子树和)`——父节点在带里居中，和子节点重叠是允许的。时间轴和鱼骨里后代是**朝一个方向排出去**的，不能重叠，所以另写 `stackHeightOf = 自身 + 间距 + 子树和`。两个函数名字相近但语义相反，注释里写清楚了，免得以后合并成一个。

## Consequences

- 九种结构全部可选，工具栏与样式面板的下拉都列全了；M2 那条「四种结构静默回退到 mindmap」的差异已回填为「已补齐」。
- 浏览器验证 27 项：每种结构都检查「节点数不变、两两不重叠、全部落在画布内」，九种全过。
- `layout/mindmap.ts` 涨到约 900 行。三种画法各自成段，暂时还能读；如果再补结构（比如 `tree-left`），应该先把它拆成 `layout/horizontal.ts` / `layout/vertical.ts` / `layout/special.ts`。
- 鱼骨与时间轴的连线颜色取自**子节点**（分支色），所以主轴和鱼骨是彩色的——与横向树的规则一致，不是 bug。
- `brace` 与 `tree-table` 在几何上都是「一层一列」，视觉差别只在连线形状与行距。这是两种结构在 XMind 里本来的关系，不是实现偷懒。

## Alternatives considered

- **给 `lineStyle` 加 `axis` / `brace` 两个枚举值**：会改文档格式，存量文件校验、XMind 导入映射、导出 SVG 全要跟着改，而这两个形状根本不该由用户选。
- **额外画一个「主轴」SVG 元素**：需要给渲染层新增一种图元类型，而「横段叠加」已经能画出同样的效果。
- **鱼骨主轴由鱼头连到第一根骨**：只能连到一端，主轴长度不够；而且第一根骨本身已经有一条边，会被画两遍。
- **树型表格按叶子高度排行**：紧凑，但父节点压行。
- **四种结构都退回 mindmap**：M2 的临时做法，M3 验收标准 4 明确要求八种都能正确渲染。
