# Agent Note: 字体与品牌静态资源的内容版本和分层缓存

Status: implemented

## Problem

EdgeOne 遵循源站 Cache-Control。Vite 的 JS/CSS 已有内容哈希，但 public 中的字体 CSS 和 Logo 使用固定 URL 并返回 no-cache，重复访问仍需回源验证。Noto 字体分片只按编号命名，却返回一年 immutable；更新同名分片无法让已有浏览器缓存失效。

## Decision

Vite 构建插件生成内容哈希 URL：字体分片先哈希，重写所属 CSS 的分片引用后再哈希 CSS，内置 Logo 单独哈希。共享虚拟模块让字体注册表、应用 Logo 和 HTML 图标引用同一产物；开发模式保留源路径。public 源文件和 docs 原图原位保留，旧固定 URL 继续随部署包提供，避免旧页面立刻失去资源。

派生文件放在既有长期缓存的 /assets/ 命名空间；这里只改变内置资源的内容身份，不改变 API 与上传访问权限。字体注册表在开发时仍解析到 /fonts/，生产时由虚拟模块提供派生 URL，加载器和导出模块自然共用同一地址。字体源码校验检查 publicAssetUrl 包装中的固定源路径，继续核对源 manifest 与字重。

### 旧笔记归属

- [字体分片与加载](../../implemented/architecture/2026-10-20-wmind-font-sharding.md)部分重叠，继续持有源分片生成和字体就绪顺序，本篇新增生产 URL 与缓存契约，互链。
- [导出字体内嵌](../../implemented/architecture/2026-10-21-wmind-export-font-embed.md)部分重叠，导出继续读取同一注册表，无需另造 URL 或重新决定内嵌策略。
- [私有媒体权限](../../implemented/bug-fix/2026-10-26-wmind-private-media-access.md)继续持有上传读取授权与 no-store，本篇不改变授权边界。
- 其余发布和代理笔记只要求固定版本、准确转发和安全头，与内容哈希决定无重叠，不替代或归档。

## Alternatives considered

- 固定 URL 直接改一年缓存最简单，命中率也高；但字体或 Logo 更新无法可靠到达已有浏览器，所以长期缓存必须由内容版本支撑。
- 用发布版本或提交 SHA 拼查询参数实现容易；但项目允许同版本重发，而且无关修改会清空全部字体缓存。内容哈希只使实际变化的资源失效，也不依赖 CDN 是否忽略查询参数。
- 将全部分片重命名入库可复用 Vite 默认导入；但会扰动源字体校验与生成器并产生大量机械文件变更。构建期生成派生文件保留源资源契约，字体加载仍按需进行。

## Testing

- 真实 Vite 构建测试先复现固定字体 CSS/Logo 不随内容变化失效，再验证修复。
- 相同输入两次构建输出相同 URL；单个分片变化只影响该分片及所属 CSS；Logo 内容变化独立失效。
- 三字体族、各字重、unicode-range 保留，开发加载和导出内嵌读同一字体注册表。
- 缺失分片中止构建；相关字体加载、导出内嵌和 Logo 回归、类型检查、208 分片校验与生产构建通过。

## Consequences

已被旧一年缓存命中的编号字体无法远程强制清除；新页面使用全新哈希 URL 绕过旧缓存。新旧页面跨部署同时存在仍可能请求已不在当前镜像中的旧哈希文件，CDN 已缓存的旧文件可继续服务，未缓存的资源需要重新加载页面。构建产物多保存一份派生资源，换取旧 URL 兼容；不能把私有上传混入公共缓存规则。
