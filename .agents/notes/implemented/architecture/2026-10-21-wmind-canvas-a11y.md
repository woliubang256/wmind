# Agent Note: 画布的无障碍（role=tree、播报与两个键盘陷阱）

Status: implemented

## Problem

M6 的无障碍那一格原本只有一行字：「画布 `role="tree"` 语义、键盘全覆盖、焦点
可见、图标 `aria-label`」。实际状况是：

- 画布的 `<svg>` 声明的是 `role="application"`（只读时 `role="img"`），里面的
  主题节点是**一堆没有任何角色的 `<g>`**。读屏用户进入画布只会听到「应用程序」，
  既不知道里面有什么，也听不到按方向键之后选中了谁——`role="application"`
  把按键交给了页面，页面却什么都没说出来。
- 焦点环被 `outline-none` 去掉了，注释里写的替代方案是「选中节点的描边」。但
  选中描边描述的是**选中**，不是**焦点**：用 Tab 把焦点移进画布时，屏幕上不会
  有任何变化，键盘用户不知道自己现在在哪。
- 图标按钮大多已有 `aria-label`（M2 时就补了），这一项基本没欠账。

真正需要先想清楚的是：**SVG 里的节点拿不到焦点，树该由谁来当？**

## Decision

### 焦点留在容器上，活动项走 `aria-activedescendant`

`<g>` 在 SVG 里不是可聚焦元素。可行的做法只有两个：给每个 `<g>` 加
`tabindex`（Safari 与部分读屏支持很差），或者让焦点留在画布容器上、用
`aria-activedescendant` 指过去。

选后者：容器本来就是一个 `tabIndex={0}` 的 `div`（快捷键监听、点击聚焦都在它
身上），现在让它声明 `role="tree"`，每个主题 `<g>` 声明 `role="treeitem"` 并
带一个稳定 id（`wmind-topic-<id>`）。方向键一动，`aria-activedescendant` 换人，
读屏念出新节点。

id 由 `editor/viewer/a11y-ids.ts` 里的一个函数算：渲染层写 `id`、页面写
`aria-activedescendant`，**两边必须用同一个函数**。各自拼字符串的话，一处改前
缀、另一处忘改，读屏会静默地什么都不念，而且没有任何报错——这类 bug 没法靠
类型系统拦。

### SVG 让出角色

编辑态给 `<svg>` 设 `role="none"`。它默认是 `graphics-document`，会在树与
treeitem 之间插进一个没有意义的中间节点。`role="none"` 只移除元素自身，子元素
的 treeitem 不受影响。

只读态（`preview` 开关、公开分享页、模板预览）反过来：整张图是一个
`role="img"`，名字是导图标题，**里面一个 treeitem 都不挂**。那里没有任何编辑
能力，冒出一棵「没有名字的树」比不报还糟。为此 `TopicsLayer` 多了一个
`treeItems` 开关，导出路径不传（导出没有读屏可言，也省一次建表）。

### `aria-label` 用原始标题，不用 `lines`

`TopicNode` 手上的 `lines` 是**测量产物**（按盒子宽度折过行），拿它当名字会读
出「分支⏎A」——读屏把换行当停顿，听起来像两截。所以 `MindMapViewer` 用
`walkSheet` 建一张 `id → 原始标题` 的表传下去，只在 `sheet` 变化时重建。

### 播报只播选中变化

`aria-live="polite"` 的隐藏区域，文案由 `features/editor/canvas-a11y.ts` 的纯
函数产出：未选中 / 叶子 / 有子节点 / 已折叠 / 多选，五种 key + 参数，调用方翻
译。做成纯函数是因为这是整套无障碍里唯一有分支判断的地方，而它**在浏览器里几
乎没法断言**——读屏的实际发声不进 DOM。

不播报「已删除」「已加粗」这类动作结果：每件事都播会让读屏变成一台不停说话的
收音机，用户连按五下方向键就得听五段无关的话。选中变化是唯一每步都必须说清楚
的——它就是导航本身。

用 `polite` 而不是 `assertive`：连按方向键时 assertive 会互相打断，polite 只念
最后一句，正是想要的。

### 只播报「键盘/鼠标选中」，首次挂载跳过

一进页面就读「未选中任何主题」纯属噪音。用一个 ref 记住上一次的选中 key，首次
渲染只记录不播报。

### 焦点环用 `focus-visible`，不是 `focus`

鼠标点一下画布也会让它聚焦，`focus:` 会在每次点击后闪一圈框；纯 `outline-none`
又让键盘用户完全没有位置感。`focus-visible:ring-2 ring-inset` 只在「经由键盘到
达」时出现，且内嵌环画在画布边缘，不会挡住内容。

### 顺手修掉两个键盘陷阱

验收脚本（真的按键）抓到两个 **WCAG 2.1.2 键盘陷阱**，都不是靠读代码发现的：

1. **画布的 `Shift+Tab` 被当成「新建子主题」**。`keymap` 初版只判
   `key === 'Tab'`，于是按 `Tab` 进画布（加了个节点）、再按 `Shift+Tab` 想退回
   去（又加了个节点），焦点永远出不去。现在 `Shift+Tab` 返回 `null`，交还浏览
   器；裸 `Tab` 仍然拦（那时用户就是想加子主题）。
2. **大纲视图的裸 `Tab` 被全局快捷键吃掉**。大纲自己没处理 `Tab`，但监听挂在编
   辑器根节点上，于是 `Tab` 变成了「新建子主题」——与 docs/05 §4.6.2「大纲不用
   Tab 缩进，Tab 是离开控件的唯一出路」的约定正好相反。现在行内 `keydown` 对
   `Tab` 只 `stopPropagation()`、不 `preventDefault()`。

修第二个时又发现：行内两个按钮（折叠、加子主题）都可 Tab，50 行的导图要按 100
次 `Tab` 才能离开——那和陷阱只差一步。两个都改成 `tabIndex={-1}`，整棵树只剩
「活动行」一个停靠点；动作改由 `Ctrl/Cmd + .` 与 `Ctrl/Cmd + Enter` 承担。读屏
的浏览模式照样能找到按钮。

## Consequences

- **`role="tree"` 的键盘语义与 ARIA 的 tree 模式不完全一致**：ARIA 说
  `←`/`→` 是折叠/展开与父/子，这里 `←`/`→` 是**几何邻接**（左分支的右邻其实是
  父节点）。这是导图的性质决定的，不改。要按结构跳转有 `Ctrl/Cmd + 方向键`。
- **编辑时 `textarea` 会短暂成为 `role="tree"` 的子元素**，违反 ARIA 的
  content model（tree 只允许 treeitem/group）。浏览器不会因此破坏树，且那时焦点
  本来就在输入框上，读屏读的是 textbox。为它把编辑框移出树需要改动
  `MindMapViewer` 的 DOM 结构，收益不值这个改动面。
- **播报文案只有中文与英文两份**，加语言要同时补 `canvas-a11y.ts` 里那五个 key。
- **`aria-label` 走的是 `walkSheet` 全量遍历**，一张 2000 节点的图每次 `sheet`
  变化会多一次 O(n)。实测可以忽略（同一帧里布局本身是 O(n) 且更贵）。
- 只读预览不再有 treeitem，意味着**分享页上读屏用户只能听到标题**。这是刻意的：
  分享页是只读的，本来就没有可操作的东西；真要逐行读结构，导出或让作者截图更
  实际。

## Alternatives considered

- **每个 `<g>` 加 `tabindex`**：Safari 对 SVG 的焦点支持很差，且 2000 个节点会
  产生 2000 个 Tab 停靠点。
- **给画布加 `role="application"` 再配 `aria-label`**：application 模式是「把
  按键都给我」，而当时页面并不播报任何东西，等于把用户关进一个黑盒。现在这套
  做法（tree + activedescendant + live region）在语义上更准确。
- **只读页也挂 treeitem**：试过，`aria-label` 会变成一棵没有名字的树，读屏报
  「树，4 项」却不说是谁的树。撤掉了。
- **把整棵树的 DOM 镜像出来做隐藏列表**：能让读屏拿到完美的树，但要维护两份
  渲染、两份焦点、两份选中，且大纲视图已经是这件事的现成答案。
- **播报每一次命令结果**：信息更全，但读屏会被淹没。只播选中变化。
- **`assertive` 播报**：更「及时」，但连按方向键时互相打断，听不清最后一句。
- **给大纲每行的按钮保留 Tab**：符合「所有按钮都可 Tab」的直觉，但 50 行的图要
  按 100 次 Tab 才能离开。改成组合键 + `tabIndex={-1}`。
