# Agent Note: 字体分片构建、按需注入与「字体就绪 → 测量 → 布局」

Status: implemented

## Problem

M3.6 的交付项是「字体注册表与分片构建」，[08 §5](../../../../docs/08-开发路线图.md) 的原话是「Noto Sans SC 四字重的 `unicode-range` 分片构建；分片完整性校验接入 CI」，硬约束是「字体就绪 → 文本测量 → 布局，顺序不可颠倒，等待期间显示骨架屏」（[ADR-016](../../../../docs/09-技术决策记录.md)）。开工时只有注册表（标识符 → CSS 栈），没有任何分片文件，也没有加载器。要落地必须先回答四件事：

- **分片从哪来？** 自己用 `pyftsubset` 切，还是拿现成的？ADR-016 写的是「TTF 静态实例」，可静态实例要切 4 遍（每个字重一套）。
- **CSS 怎么送到浏览器？** 一份 `fonts.css` 放进 `index.html` 最省事，但那份文件是 514 KB（sans 一族）/ 724 KB（三族）。
- **「就绪」怎么判定？** 直接 `await document.fonts.load(...)` 看起来够了，实际上不够——见下面「假就绪」。
- **中途换字体怎么办？** 首屏的顺序守住了，用户在面板里把某个节点改成等宽时，新字体的分片还没到，布局已经量过了。

## Decision

### 用 Google Fonts 的可变字体分片（ADR-018）

`scripts/fetch-fonts.mjs` 拉 Google Fonts 的 CSS 与 `.woff2`，落盘到 `frontend/public/fonts/`，产物入库。每族 101 个分片（mono 6 个），**同一组文件覆盖该族全部字重**——可变字体按 `wght` 轴实例化，不必为 300/400/600/700/800 各存一套。

字重定为 5 档（sans 300/400/600/700/800、serif 400/700、mono 400/700），比 ADR-016 的 4 档多一个 600：样式面板的字重下拉本来就有「中粗 600」，可变字体能真实实例化，不该让浏览器合成假粗体。

实测产物：**3 族 / 9 个字重面 / 208 个分片 / 10.10 MB**。自己切 5 套静态实例会到 30 MB 量级，还要在 CI 装 fonttools。

### 每族一份 CSS，按需注入，不进 `index.html`

`/fonts/{sans,serif,mono}.css` 三份，由 `ensureFonts()` 在首屏往 `head` 里插 `<link>`。理由不是「省一次请求」，而是**骨架屏根本画不出来**：sans 的 CSS 是 514 KB，用 `<link>` 阻塞渲染意味着在它到达之前页面是空白的，而 ADR-016 要求「等待期间显示骨架屏」。按需注入后骨架屏立刻可见，字体到了再进布局。

浏览器实测：把 `sans.css` 人为拖慢 1.2 s，期间画布 **0 个节点**（布局确实没跑），CSS 到达后才出现节点。

### 先有 `@font-face`，再问「就绪了吗」

`document.fonts.load()` 对一个**还没注册任何 face** 的字体族会立刻 resolve，返回空数组。也就是说「直接 `await load()`」拿到的是**假就绪**——代码接着就用回退字体量了宽度，而测量缓存键里没有「字体到没到」这一维，错宽度会被永久缓存。这正是 ADR-016 想防的那个 bug，只是触发条件从「没等字体」变成了「等了个寂寞」。

所以 `ensureFonts()` 的顺序是死的：注入 `<link>` → 等 `load` 事件 → 才 `document.fonts.load(font, text)`。样式表 404 时不再等（没有任何 face 可等，等下去只是白等满超时），直接降级并 `console.warn`。

### 一个总预算，不是两级各自超时

样式表与分片共用一个 `deadline`（默认 4 s）。分开计时的话最坏情况要等 8 s 才出图。超时后 `ready: false`，调用方（`useFontsReady`）仍然放行布局并记一条 warning——停在骨架屏上比跳一下严重得多。

### 文本按真实内容传

`document.fonts.load(font)` 不带第二个参数会加载该字体描述符下的**所有**分片：sans 101 个、4.29 MB。传文档里的全部文字后只取覆盖这些码位的分片。实测：9 个汉字的默认文档在五个字重下命中 **13 个分片、约 315 KB**（多等几个字重几乎只增加请求数、不增加字节，因为分片文件跨字重共享）。

### 字体族集合要算上节点级覆盖

`scanDocument()` 收集的族集合 = 主题全局 + 三个角色样式 + **每个节点的 `style.fontFamily`**。最后一项是这套按需注入特有的坑：以前所有族的 `@font-face` 都在 `index.html` 里注册好了，节点级换成宋体照样能渲染；现在样式表按需注入，节点级覆盖若不参与扫描，那个节点就会静默退回系统宋体，用户以为「换字体没生效」。

一次 DFS 同时取字体族与文本，成本与 `layoutMindmap` 同阶。

### 换族后作废测量缓存

`measure.ts` 新增 `clearMeasureCache()`。`useFontsReady` 每轮就绪后清一次缓存并把 `generation` 加一，`editor-page` 把 `generation` 放进布局的依赖里。没有这一步的表现是：把节点改成等宽 → 布局立刻用回退字体量了一遍 → 分片到了，画面不重算，节点框比文字窄几个像素，而且会一直错到下次编辑。

## Consequences

- **10.10 MB 入库**（208 个 `.woff2` + 3 份 CSS + manifest + 2 份 OFL 许可）。字体升级要重跑 `npm run fonts:fetch`，diff 里是整批二进制变更。这是刻意的：字体是构建产物，不是手写源码。
- `scripts/fetch-fonts.mjs` 支持 `--family <key>`（只重建一族，其余从 manifest 沿用）与 `--css-only`（不重下 10 MB，只按 manifest 重写 CSS）。后者是给「改注释、改排版」用的，避免为一行注释重新拉一遍 CDN。
- **`npm run check:fonts` 六项校验**接进 CI：分片文件与字节数、每族 CSS 与 manifest 逐段一致（含孤儿 CSS / 孤儿分片）、覆盖率下限、重叠只报告、`font-display: block`、前端注册表与 manifest 一致。缺分片的失败方式是「静默显示方框」，必须在构建期挡住。
- **覆盖率是下限不是全覆盖**：Noto Sans SC 对 U+4E00–U+9FFF 只覆盖 58.4%（12258 / 20992）——它本来就没为每个码位画字形。要求全覆盖等于要求字体做它不做的事，闸门会永远红。真正的完整性由「文件在 + CSS 与 manifest 逐段一致」保证；区块覆盖率只是防「整批分片被换成了错误的一套」。
- **重叠只报告不失败**：Google 的相邻分片确实共享少量码位（sans 279 段），这是它的切分方式，不影响渲染。
- **`FONT_DEFINITIONS` 多了 `cssPath` 与 `weights`**，与 manifest 双向核对。改一处不改另一处会红——这条以前只写在注释里（「check-fonts 会核对」），实际没人核对，本次把注释兑现成代码。
- `docs/08 §5` 的 M3.6 行、`docs/08` 的字体风险段、`docs/09` ADR-016 的修订横幅与新增 ADR-018 已同步。
- 新增前端测试 19 条：`font-load.test.ts`（11，含「先注入样式表再问就绪」的顺序断言与两条超时路径）、`use-fonts-ready.test.ts`（7，扫描语义）、`measure.test.ts` 加 1 条（缓存作废）。

## Alternatives considered

- **`pyftsubset` 自切静态实例**：可控、无第三方依赖。代价是 5 个字重切 5 套，体积与构建时间翻倍，CI 要装 fonttools 并维护切分表。
- **单一 `fonts.css` 阻塞加载**：一条 `<link>` 最省事。代价是 724 KB（三族）阻塞渲染，首屏白屏，与「等待期间显示骨架屏」直接冲突。
- **再按字重拆 CSS**（`sans-400.css`）：首屏 CSS 能再省一半。代价是换字重就要插新 `<link>` 并触发重排，注入状态从「每族一次」变成「每族每字重一次」。当前 gzip 后 156 KB，收益不够支撑这份复杂度，记为二期优化。
- **从 CDN 直连 Google Fonts**：零产物。私有化部署必须离线可用，直接否掉。
- **`document.fonts.load()` 不传文本**：省掉「收集文档文字」这一步，代价是首屏拉满 101 个分片、4.29 MB。
- **信任 `load()` 的 resolve，不先注入样式表**：少一次 DOM 操作，代价是假就绪 + 宽度永久错。
- **字体族只扫主题全局与角色样式**：省一次全树扫描（其实省不了，文本也要扫），代价是节点级字体覆盖静默失效。
- **换族后不清测量缓存**：省一次重排，代价是节点宽度一直错到下次编辑。
