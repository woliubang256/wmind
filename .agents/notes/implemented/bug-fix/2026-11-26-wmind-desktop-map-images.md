# Agent Note: 桌面导图同步先传输主题图片

Status: implemented

## Problem

桌面本地导图的主题图片使用本机 `/uploads/…` 地址。将原文提交给云端时，云端的属主与文件检查无法找到合法图片，带图导图无法上传。两端的上传目录不同，拉回云端地址也不能直接当作本机图片显示。

## Decision

首次上传、增量推送和冲突保留本地共用图片转换。沿用主题树图片遍历，逐图读取已授权的本地资源、走远端鉴权上传、仅替换送往云端的图片地址。拉取与选用云端版本执行反向转换，将图片保存在本机，使后续编辑及离线浏览可以使用。每次转换保留原稿和独立的两端内容摘要，只处理实际主题图片，覆盖多画布和浮动主题。

同步元数据在 `sync_meta` 同一条 SQL 内写入双向图片地址，按服务器与云端账号隔离。重试检查目标文件，缺失时重新传输。任一图片失败时暂停提交目标导图，已传输的图片在同一连接下复用。首次绑定由用户在卡片上发起，上传、同步与冲突处理串行运行。拉取时以一张导图为单位持有本地维护门，覆盖图片下载落盘到引用提交，避免备份恢复或回收在两者之间执行。云端创建响应丢失时按原 UID 重试，返回的文档和发送的内容不一致则记录冲突。

## Related notes

[桌面客户端架构](../architecture/2026-11-08-wmind-desktop-client.md)描述了图片映射和显式首次上传，本篇落地图片传输细节。图片附件沿用[桌面令牌会话](../architecture/2026-11-26-wmind-desktop-token-session.md)和服务端文件权限。

## Alternatives considered

- 直接保留地址省去了传输，但本机与云端的路径相同并不意味着文件相同，且远端严格检查图片归属。
- 合并一份导图及全部图片的专用接口可让上传更接近原子操作，但需要引入一套额外的服务端接口及兼容策略。沿用文件及导图接口可以使用现有鉴权、限制、幂等与资源清理。

## Verification

`cd desktop && go test . -run '^TestDesktopUploadsLocalMapImagesAndRetries$' -count=1` 使用隔离的云端和两台桌面，先复现云端拒绝本机图片地址，再验证显式首次上传、部分图片失败后复用、创建响应丢失后幂等重试、增量推送和第二台设备离线读取。桌面同步引擎测试覆盖冲突、版本漂移和游标。后端业务与 HTTP 测试验证原有授权和图片上传路径。

## Consequences

每张新图片需要单独传输，拉取大批图片时当前导图落盘前会延后本地维护。若网络在文件上传成功但返回地址前中断，服务端可能留下无引用文件，由既有宽限期清理。已同步文档中的旧损坏地址需要在源端补齐图片再同步。列表封面沿用云端媒体代理。
