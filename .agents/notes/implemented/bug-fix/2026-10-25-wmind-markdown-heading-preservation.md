# Agent Note: Markdown 混合标题与列表不再按数量丢弃标题

Status: implemented

## Problem

二手车综合业务需求使用一个文档标题、九个二级模块、三级小节和大量两层列表。既有 `headingCount >= 2 && headingCount >= listCount / 2` 将列表多的文档判成列表模式，再把所有标题改成正文备注。结果导入成功但九个主分支和小节消失。原始文本正则计数还把围栏里的 `#` 算作标题，与真正分词结果不一致。

## Decision

以 `tokenizeMarkdown()` 的结果作为唯一语法来源：只要存在真正的 heading 令牌，就保留标题层级，列表按各自缩进挂到最近标题下面；没有标题才走纯列表建树。一个标题与若干列表仍得到同样的根与列表结构，不需要数量阈值。解析入口只分词一次，公开探测函数沿用同一令牌判定。

围栏中的伪标题和反斜杠转义的 `\#` 不参与标题判定；不对用户全文去除转义。层级跳跃不补空节点。修复只影响新导入，已保存的错误图无法可靠区分备注与原始标题，不自动重排。

## Alternatives considered

- 保留数量启发式并降低阈值，可以最大程度保持旧笔记的自动分类；但任何有限阈值都会再次把足够多列表的有效标题写入备注，不能提供不丢层级的保证。
- 全文移除 `\#` 的反斜杠可以兼容从富文本复制的伪 Markdown；但会把本应显示字面量的标题变成结构，也破坏导出行首转义，因此只识别真实 Markdown 语法。
- 无条件使用标题建树可删除模式分支；但纯列表的首个正文行作为根的语义已经稳定，改动范围超出缺陷所需，保留无标题时的列表路径。

## Consequences

标题不再受列表数量影响，真实分类作为可见节点保留。含真实标题但此前因数量被当成列表的文档会按标题结构导入，这是此次修正的预期行为；已有文档不迁移，错误旧图需要从原 Markdown 重新导入。语法子集不扩展为完整 CommonMark，文字转义不作为结构修复猜测。
