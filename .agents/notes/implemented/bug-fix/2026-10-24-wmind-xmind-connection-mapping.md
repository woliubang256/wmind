# Agent Note: XMind 分支连线与节点边框分开映射

Status: implemented

## Problem

用户提供的现代 XMind 文件包含 95 个主题、94 条父子连线，首次导入后所有连线宽度为 0，重新选择配色才出现。来源主题使用 `line-width: 2pt` 表示分支线，`border-line-width: 0pt` 表示节点无边框；既有导入器将两组属性对调，导出器也依照同一错误表写入，自家往返测试因两端同时出错而未发现。

## Decision

主题的 `border-line-*` 只映射节点边框，`line-color` / `line-width` 映射父子连线，分支几何从 `line-class` 读取。继承值保持缺省，明确为 0 的分支线宽和 none 线型仍可隐藏连线，不能全局强制改为正值。联系与外框按自身的线条语义单独映射，避免共享函数把装饰线误读成主题边框。

导出同步写标准属性及 `line-class`，metadata 增加 `wmindStyleVersion: 2`。旧版 wmind 导出带 `creator.name: wmind` 且缺此标记，导入前只对这种已知旧包转换错误属性；原生 XMind 和不明来源不猜测。现有 `.wmind` 存档不做无依据的样式迁移。

用户原文件只作本机验收，不进入仓库，回归夹具使用相同属性的匿名主题。浏览器测试可通过 `XMIND_IMPORT_SAMPLE` 指定本机原文件，默认夹具不依赖私有内容。

## Alternatives considered

- 导入完成后自动重选主题可直接让连线恢复；但会覆盖原有字号、边框和显式颜色，且保留错误持久化数据，因此修正属性来源。
- 将所有 0 宽连线改成默认宽度只需一条兜底；但真实用户可能明确隐藏分支，无法区分错误边框宽度与有效分支设置，因此保留零值语义。
- 只改导入器可修复这次样本；但新导出仍向外写错误字段，旧 wmind 包也会反向受损，因此同步写入标准格式并按来源标记兼容旧包。

## Verification

- 匿名主题先复现旧实现的线宽 0 / 线型 none，修复后保留边框 0、连线 2 和曲线/折线形状，继承与明确隐藏测试通过。
- 新导出测试直接解压 ZIP 并断言标准字段；旧 wmind ZIP 导入保留边框、连线、自由主题、联系及双端箭头。
- 用户原文件与匿名 95 主题夹具分别通过浏览器验收：首次打开显示 94 条连线，编辑中心主题、等待保存后刷新仍显示全部连线，无需切换主题。
- 导入、布局、导出、批次和语言包相关单测共 30 文件 / 589 项通过；类型检查和生产构建通过。浏览器批次套件 15 项与原文件/文本入口套件 22 项通过。

## Consequences

原生 XMind 的节点边框与分支连线不再互相覆盖，导出也写入同一标准契约；带旧 wmind 标记的包仍能还原原来的视觉语义。已经导入并保存的 `.wmind` 不能可靠区分用户选择的 0 宽与旧错误映射，需从原 XMind 重新导入或主动重选样式。旧包兼容依赖 metadata 的 wmind 来源标记；去掉元数据的第三方重打包按标准 XMind 处理。
