# Agent Note: 管理概览接入真实导图与存储统计

Status: implemented

## Problem

管理概览沿用 M1 的占位统计，导图总数、今日新增、存储量固定为零，近 14 天趋势为空。数据库已有导图，开发版和正式版都受影响。

## Decision

独立的 AdminStatsRepo 在两种数据库中聚合相同口径，服务层补齐含今天的连续 14 个 UTC 自然日。返回原有字段，不让前端把未接入状态误认为零数据。接口错误保留错误状态，不吞错返回零。

- 用户总数与活跃用户沿用未软删除用户口径；活跃表示账号状态为 active，并非近期登录。
- 导图总数统计未进入回收站的导图；存储统计全部现存导图的 size_bytes（含回收站）加上传目录普通文件字节数。
- 趋势统计库中仍保留的用户和导图按创建日聚合，包含软删除记录，永久删除后无法追溯历史新增量。
- 存储不表示数据库物理文件大小，不含索引、WAL、历史快照或备份；上传临时文件和符号链接不计入。配置根目录允许为符号链接，仅解析入口，目录内链接仍跳过。目录扫描响应取消，遇到读取错误返回失败，遇到并发删除跳过。
- 界面仅在统计标签的悬停提示中说明口径，避免重新添加用户要求删除的页面说明。零值柱高为零。

已有[管理后台笔记](../../implemented/architecture/2026-10-17-wmind-admin-backend.md)的 M1 占位约定由本笔记部分取代，鉴权和审计约束继续有效。

## Alternatives considered

- 用数据库文件和上传目录的磁盘总大小最接近服务器磁盘占用；但 SQLite WAL 与 PostgreSQL 数据库共享空间口径不同，无法解释单张导图增删，选择业务文档字节和上传文件合计并明确范围。
- 用用户冗余 map_count 汇总不用新增查询；但该计数服务于配额且不覆盖全站存储和创建日期，独立聚合直接从业务记录读取。
- 让前端自行聚合列表无需新增仓储；但需要全站权限和全量分页读取，直接由管理员接口提供聚合更小且不暴露文档内容。

## Verification

- HTTP 复现先失败（创建后 mapCount=0），修复后 `TestAdminStatsReflectMapsTrashAndUploads` 验证新建、回收站、彻底删除及上传增量，未完成上传不计入。
- SQLite 与隔离 PostgreSQL 17 共用 `contracttest.AdminStats`，验证 UTC 起止边界、软删除记录、非活跃用户和存储求和；服务测试验证跨年及 UTC 转换、14 天补零、底层错误不伪装成零值。
- `TestUsage` 验证嵌套目录、临时文件、内部链接、配置根目录链接、取消和根目录消失；先复现根目录链接计为零再修复。
- `e2e/settings-cleanup.mjs` 验证零新增柱高为零；原有最小 2% 柱高的复现先失败，再调整为只对正值设置最小高度。

## Consequences

真实统计随业务数据变化，不再使用占位值。数据库总量、趋势聚合和文件扫描并非同一事务快照；并发写入时数值可能短暂跨时点。每次手动刷新扫描上传目录，文件很多时开销增加。跨日统计以 UTC 为准，并通过悬停提示告知。
