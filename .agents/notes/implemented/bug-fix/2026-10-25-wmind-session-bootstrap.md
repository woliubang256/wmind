# Agent Note: 页面启动主动恢复会话，避免无令牌的用户探测

Status: implemented

## Problem

访问令牌仅存内存，刷新网页后消失。当前启动先 GET /auth/me，必然得到 401，随后 POST /auth/refresh 再重试 /auth/me；有效会话也需要三次请求，且每次刷新都在控制台留下鉴权错误。

## Decision

将共享刷新操作改为返回完整 AuthSession。页面初始化在没有访问令牌时直接恢复 Cookie 会话并采用响应中的 user，不再先探测 /auth/me；已有令牌时仍通过 /auth/me 查询当前用户。启动与运行期间的刷新共用一个进行中的 Promise，迟到的旧令牌 401 优先复用已更新的令牌，避免再次轮换。

真实 401/403 视为无有效会话；断网、服务端错误和无效响应继续作为错误传播，不把临时失败解释成退出登录。RequireAuth 与 RequireAdmin 显示原地重试而非跳转登录；重试期间沿用 W 加载状态。令牌仍不落入 localStorage 或 sessionStorage，后端接口和 Cookie 安全属性不变。

## Alternatives considered

- **沿用 401 后恢复**：所有受保护请求都走同一个补救流程，实现简单；但启动时没有访问令牌是已知事实，仍发送 /auth/me 只增加必然失败的请求。
- **把访问令牌写入浏览器存储**：刷新后可以直接使用旧令牌，少一次恢复请求；但扩大脚本可读取令牌的持久时间，且依然要处理过期，因此保留内存存储。
- **先刷新再调用 /auth/me**：职责分明，用户查询入口唯一；但刷新响应已有服务端校验过的完整用户数据，启动再查一次没有必要。

## Verification

- 有效 Cookie 的冷启动仅发送一次 refresh，不发送 me；已有令牌直接查询 me。
- 并发启动与运行中刷新合并；迟到的旧 401 不触发第二次轮换，重试有上限。
- 无会话、过期和禁用账号返回未登录；网络、5xx 和格式错误不伪装成未登录。
- auth.test.ts 与 client.test.ts 锁定请求顺序、共享刷新、重试上限和异常传播；session-bootstrap.mjs 的 14 项浏览器断言覆盖真实刷新、HttpOnly Cookie、退出、401/403、503/断网原地重试。其他独立界面夹具同步完整刷新响应，避免只模拟 me 成功掩盖启动行为。
- `pnpm typecheck`、`pnpm test`（1300 项）与 `pnpm build` 通过。界面回归覆盖加载、用户菜单、导入、画布与面板、分享、概要、回收站和后台文案；旧菜单测试改为当前侧栏入口及真正受限的视口，加载完成仅检查可见动效，不把关闭弹窗中未启用查询的静态 DOM 当成残留。

## Consequences

有效会话冷启动由三次认证请求减为一次，正常刷新不再产生 me 401。临时故障保留目标页面并支持重试，但增加一个认证错误显示分支。匿名启动仍可能收到 refresh 401，这是实际无有效会话的结果，而不是健康会话的固定启动步骤。共享刷新响应的夹具必须包含 user，不能只模拟 accessToken。刷新合并仅限同一页面，多标签页仍由独立运行时处理。
