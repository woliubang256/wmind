# Agent Note: 管理端禁用和删除即时撤销全部会话

Status: implemented

## Problem

禁用和删除仅清理当前进程的用户缓存，其他实例可以继续接受旧访问令牌。禁用后重新启用没有改变会话版本，旧访问令牌会恢复有效。撤销刷新令牌失败被记录后忽略，状态变更和撤销不在同一事务，后台成功不能代表全部会话已失效。登录和第二因子验证在取安全行锁之前读用户，可能使用禁用前的对象签发新会话。

## Decision

认证每次从共享数据库读取当前用户和安全版本，不缓存授权状态。管理端以与登录、刷新相同的安全行锁顺序，在同一事务内修改状态或软删除、更新随机 SessionVersion、清理未完成的第二因子挑战、撤销全部刷新令牌；任一步失败全部回滚。重新启用保留已经推进的版本，旧访问令牌永不复活。

注册签发、登录、刷新和第二因子操作取得安全行锁后重新校验用户存在性、状态和密码快照，拒绝等待期间已经失效的身份。共用撤销入口的管理员重置密码也按相同事务协议处理，不再忽略撤销错误。

## Related decisions

按禁用、缓存、会话、安全版本检索后，[认证会话](../../implemented/architecture/2026-10-17-wmind-auth-session.md)和[管理后台](../../implemented/architecture/2026-10-17-wmind-admin-backend.md)部分重叠，本篇替代其进程内缓存主动失效的即时性前提，保留其密码、Cookie、审计和最后管理员保护决策。[双因素认证](../../implemented/feature/2026-10-23-wmind-two-factor.md)继续持有安全行和版本格式，本篇复用该契约。[启动恢复](../../implemented/bug-fix/2026-10-25-wmind-session-bootstrap.md)的内存令牌、单飞刷新及暂时故障不退出约束保持不变。其他备份、分享和限流笔记不决定账号令牌撤销，无需替代或归档。

## Alternatives considered

- 继续本地缓存并用广播通知其他进程，能减少用户读取，但广播掉线、消息丢失和缓存回填仍需可靠版本兜底；现有鉴权已经每次读安全状态，直接读取用户更简单且不引入分布式依赖。
- 仅推进数据库版本可复用现有缓存，但需要额外绑定缓存版本，确保新登录不会取到旧角色、状态或资料；本次去掉安全状态缓存，避免维护两套授权真相。
- 每个访问令牌建立撤销表可支持设备级精细控制，但本需求是账号级全部失效，复用已有会话版本即可，无需迁移或令牌增长表。

## Verification

- 两个独立服务实例访问同一数据库，禁用或删除成功后旧访问和刷新令牌均被拒绝。
- 重新启用不会恢复旧令牌，新登录正常；已有 2FA 保持设置，但旧挑战失效。
- 撤销或安全版本保存失败会回滚状态、删除、版本和令牌变更。
- 等待安全行锁的登录与刷新不能在禁用后签发有效会话。
- `go test ./internal/integration -run '^TestAdminSessions' -count=1`：真实临时 SQLite、两个独立连接和服务实例，覆盖多设备访问/刷新、重新启用、撤销和版本保存失败回滚、等待中的登录和刷新以及 2FA 配置保留与挑战清理。
- 受影响的 service、httpapi、backup 与 cmd/server 定向回归；集成测试另跑 race 检查。

## Consequences

全部设备和实例在下一次认证拒绝已撤销账号，重新启用不能恢复旧会话，失败不留下半完成状态。代价是每次认证增加一次用户读取；未发出请求的静止页面不会主动跳转，下一次接口请求才体现失效。已经通过鉴权的在途请求不做业务回滚。需要所有运行实例更新后端，不宣称旧二进制具有新锁协议。没有配置 PostgreSQL 测试数据库时，只验证其代码编译和共享锁协议，不宣称完成 PostgreSQL 实库竞态测试。
