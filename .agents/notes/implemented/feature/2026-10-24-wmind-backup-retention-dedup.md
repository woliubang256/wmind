# Agent Note: 后台备份保留份数与可选内容去重

Status: implemented

## Problem

后台每次捕获全部应用表并上传 ZIP，没有保留份数和内容去重。登录、分享浏览、备份作业自身也写数据库，直接哈希数据库或 ZIP 会制造无意义新版本。保留份数不能复用最近 20 条作业记录，否则手动、定时、失败和跳过混合后会遗漏实际对象。

## Decision

保留份数默认 30，范围 1–1000；手动和定时成功上传的完整 ZIP 共用每个目标的配额。新对象成功上传并持久登记后，按成功时间倒序保留最近 N 份，再删除登记中超额对象。清理失败显示警告，不冒充上传失败，保留登记以供重试。失败上传、跳过、恢复前本地安全副本不计数。降低份数在下一次备份执行后清理，不在保存设置时删除。旧配置缺字段使用新默认。

远端扩展精确对象存在检查和删除，不提供远端浏览或下载恢复。删除只能用成功上传登记中的严格本应用文件名，不能接受任意键或递归路径；登记保存目标身份摘要、文件名、时间、内容指纹，独立于作业历史并在重启后恢复。目标身份不含密码但包含协议、地址/桶/前缀和账号，切换目标不复用另一目标基线、不清理另一目标。未经登记的旧备份不自动删除。恢复保留当前运行的登记并使内容基线失效，防止历史数据库回滚导致错误跳过或清理其他目标。

去重开关默认关闭，关闭时每次生成和上传完整 ZIP。开启后，对捕获的规范化业务内容与 uploads 字节计算 SHA-256，只有与当前目标最近成功上传且仍存在的对象一致才标记 skipped；压缩前退出，不产生远端重复对象。首次执行、更换目标、远端对象丢失、恢复后或内容有变均生成完整 ZIP。无论开关状态都登记成功快照指纹，开启开关不改变业务指纹。

内容指纹包含脑图/附件、模板、主题、分享配置、账号角色与安全配置、普通站点配置。忽略登录时间、会话令牌、设备活跃状态、审计、分享访问统计、备份配置/历史/登记自身。用户安全设置仍计入，不能把已启用 2FA 的密钥或恢复码变动当作会话噪声。未知业务字段默认计入；表行和 JSON 属性规范排序、保留大整数，避免查询顺序和序列化差异制造版本。指纹只决定是否新增备份，不削减实际归档数据。

## Alternatives considered

- 对 ZIP/数据库文件整体哈希：实现最短且覆盖全部字节，但时间戳、会话和任务记录每次变化，不能满足“仅浏览不新建版本”。采用业务快照规范化摘要，归档仍完整。
- 对写操作维护版本计数：可在无变更时省去捕获，但所有写入口、自动清理、SQLite/PostgreSQL 和上传文件都要保证递增，遗漏会导致静默漏备。初期从一致捕获快照计算指纹，代价是重复备份仍需读取本地数据。
- 列举远端并按文件名删除最旧对象：能接管所有历史文件，管理员不用迁移；但同目录其他实例或手工文件无法仅靠前缀确认归属。采用成功上传清单，只删除本实例能证明所有权的文件，旧未登记对象保留。
- 增量备份链：存储更省，但保留与恢复要管理依赖，任一块丢失影响多个恢复点。每个保留对象都是独立完整 ZIP。

## Testing

- 旧配置与新安装均默认保留 30、去重关闭，范围校验拒绝无效值；UI/API 与中英文一致。
- 两种存储支持签名/认证精确删除、404 幂等、拒绝重定向/路径穿越；上传失败绝不清理旧对象。
- 手动与定时合计成功份数，重启、修改配额、删除失败重试、目标隔离、超过 20 次历史后仍准确。
- 开关关闭重复上传；开启后连续执行、登录和分享查看均跳过；脑图、文件、账号/安全/站点或分享配置变化会上传。
- 规范化覆盖行序、JSON 键序、大整数；远端缺失/错误、上传失败不推进基线，恢复后强制生成新副本。
- `go test ./internal/backup -count=1 -race`、相关 httpapi 与 cmd/server 测试通过；新增真实登录、读取脑图、匿名分享访问及分享权限变化的 HTTP 竞态测试通过。
- 前端全量 83 个文件/1266 项测试、类型检查和生产构建通过，隔离后端与真实浏览器 `e2e/backup.mjs` 29 项通过；包含恢复覆盖与旧会话撤销，中英文和 375px 截图已检查。
- `npm run test:release` 验证备份根接口精确代理与部署包一致；正式发布整栈冒烟要求根接口直接 401 且无 Location。

## Consequences

指纹投影必须随业务字段演进维护，采用未知字段默认包含避免漏备；重复内容仍需一致捕获和读取文件，不承诺零开销。登记持久化失败不能开始删旧文件。远端删除失败时实际份数暂时大于配额，并明确警告。未登记旧对象需管理员自行整理；单实例互斥边界不扩展为集群锁。去重忽略的审计/访问记录不会仅为其变化产生新备份，但下次业务变更时仍随完整 ZIP 进入归档。
