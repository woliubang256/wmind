# Agent Note: 用户自助 TOTP 双因素认证

Status: implemented

## Problem

密码登录直接签发会话，用户无法增加独立验证因子。新增认证步骤还必须防止旧刷新令牌、并发请求及恢复码重复使用绕过第二步。

## Decision

### 标准验证器与独立安全记录

TOTP 使用 SHA1、6 位、30 秒、前后一个窗口；已用计数器只能前进。设置密钥十分钟过期，验证成功才启用。user_two_factor 独立保存版本化 JSON 安全状态，不扩张 UserRepo 或向用户 DTO 暴露私密字段。双方言共用 sqlc 查询，事务内先 Ensure 行存在、锁定安全行，再以 revision 防止过期副本覆写。SQLite 使用既有 BEGIN IMMEDIATE，PostgreSQL 使用 FOR UPDATE。所有登录、刷新、设置操作按安全行后令牌的顺序取锁。

验证器密钥由 AES-256-GCM 加密，AAD 绑定用户 uid 和 pending/active 用途。专用 WMIND_2FA_ENCRYPTION_KEY 优先；未配置时从 JWT 密钥按用途派生以兼容现有部署。必须备份并保持有效加密密钥稳定；直接更换会使原验证器密钥无法解密。二维码在服务端本地生成，不发往第三方。两套 Compose 均透传该配置，配置摘要不输出密钥。

### 密码后只签发短期挑战

密码验证后生成五分钟、最多五次尝试的随机挑战，数据库只保留哈希，绑定用户、密码哈希及安全版本；每用户最多五个未过期挑战。挑战不能用于 RequireAuth 或刷新。完成第二步前不签发访问令牌或刷新 Cookie。错误尝试次数在事务提交后才返回错误，避免回滚把次数清零。已有服务锁定器额外按用户限制跨挑战重试，HTTP 按 IP 限制请求频率。

启用与停用更新随机安全版本，并撤销全部刷新令牌；当前设备获得新会话。JWT 的可选 sv 与数据库安全版本在每次认证时比较，不走用户状态缓存，因此旧访问令牌立即失效。启停、登录和刷新共享安全行锁，防止密码步骤和启用操作并发穿透。

### 恢复码与敏感操作

启用提供十个独立随机恢复码，仅保存 SHA256，消费与会话签发同事务。恢复码先独立验证，再尝试解密验证器密钥；加密密钥丢失时仍能凭密码及预先保存的恢复码登录、停用并重新登记。验证码本身遇到无效密文时失败关闭。

启用要求当前密码及新验证器验证码；停用和重新生成恢复码要求密码及有效第二因子。重新生成使旧恢复码全部失效，启停使旧挑战失效；修改密码使已签发挑战失效。账户页提供二维码、手输密钥、恢复码一次展示和文本下载；敏感值只保存在组件内存，不写本地存储或查询缓存。登录页支持验证器/恢复码切换和返回密码步骤，过期挑战要求重新验证密码。敏感 API 响应均 no-store，中英文和窄屏共用同一流程。

## Alternatives considered

- 短信或邮件验证码易于理解且无需安装验证器，但引入交付服务、运营成本与额外可用性依赖；本次采用离线 TOTP。
- 内存挑战实现简单且无迁移，但重启、多实例和并发消费难以保证一致；挑战归入持久化安全状态并用事务消费。
- 只撤销刷新令牌可复用现有实现，但旧访问令牌仍能使用十五分钟；增加随机安全版本并在认证时查验。
- 强制立即提供独立密钥能解耦 JWT 轮换，但会阻断现有部署启动；提供专用配置和用途隔离派生回退，明确持久化密钥要求。

## Verification

- SQLite/双方言仓储契约覆盖缺省状态、往返、过期写和事务回滚；sqlc 生成、迁移序列对等与方言边界检查通过。没有配置 WMIND_TEST_DATABASE_URL，PostgreSQL 实库契约及结构对比由 CI 验证。
- auth、service、config、httpapi、cmd/server 定向测试通过；OpenAPI 六个新增操作与路由对等，总数 55。独立集成测试覆盖设置与挑战过期、未确认不启用、旧访问/刷新与缓存失效、TOTP/恢复码重放、跨挑战锁定、改密失效及并发恢复码消费，race 检查通过。密文失效后的恢复码独立性回归通过。
- 浏览器 two-factor.mjs 8/8：二维码/手输密钥、恢复码下载、密码步骤无会话、错误码拒绝、真实 TOTP、恢复码重放、重新生成、停用、中英文与 390px 窄屏。前端错误和语言包 11 条测试及生产构建通过。

## Consequences

- 每次鉴权增加一次安全状态读取；单用户安全操作串行，挑战与恢复码均有固定上限。跨挑战锁定仍为进程内，单个挑战的次数和单次消费由数据库保证。
- 必须重启更新后的后端并应用迁移 0003 才能使用新接口；部署备份须包含实际使用的加密密钥。既有未启用用户仍保持密码登录。
- 同时丢失验证器及恢复码不提供自动重置，管理员改密不会绕过第二因子。恢复码离开显示页后不再返回明文，需通过密码和有效第二因子重新生成。
