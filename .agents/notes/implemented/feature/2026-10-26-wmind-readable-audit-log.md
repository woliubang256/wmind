# Agent Note: 可读操作日志、事件名称快照与完整查询

Status: implemented

## Problem

管理概览只显示最近八条审计记录，分享动作未翻译，设置键和随机对象 UID 成为主要内容。已有记录中的操作者、分享权限、期限及角色变化没有完整展示，无法回答谁对什么做了什么。

## Decision

后端提供安全事件上下文，前端统一语义摘要与中英文翻译，完整日志列表接通分页及操作/本地日期筛选。概览复用相同日志行，保留最近八条并提供完整列表入口。

新记录在现有 detail JSON 中保存 actor（uid、username、nickname）与 targetName 快照，不新增数据库列，不改写旧审计记录。分享同时记 mapUid、mapTitle、权限布尔值与期限；设置只记字段名，不记配置值、密码、密钥、分享令牌或原始请求。用户删除前捕获目标名称。读取时快照优先；旧记录仅补充仍存在实体的名称，缺失时用明确的未知对象文案与详情内的 ID，不编造历史值。DTO 增加 actor 与 targetName，原字段兼容。

主行显示操作者、翻译后的动作和对象，次行紧凑显示时间及来源 IP。超长摘要折叠为两行，展开后恢复全文。原始 ID、完整时间和可解释的变化放在按需展开详情中；详情仅渲染白名单字段，不把任意 JSON 或未知值直接转成文字。设置字段复用设置表单的名称映射，未知动作/字段有本地化兜底，查找只接受映射自有键。

完整列表复用现有管理员路由守卫与审计查询接口。每页二十条；操作类型与起止日期显式提交，筛选改变回到第一页。日期按浏览器本地日界线转 ISO，结束日期以最后一纳秒包含整日，支持夏令时变更日；非法及逆序区间不能静默忽略。原生日期控件的 badInput 必须阻止请求，重置通过原生 form reset 清除分段状态并同步清空 React 草稿。加载、失败重试、空结果和刷新均可见，窄屏不出现横向溢出。

## Alternatives considered

只补两个分享动作翻译最小、风险最低；但仍看不到操作者与对象名称，也无法查八条以前的记录，不能解决用户的追溯问题。

每次读取都联表显示最新名称，无需额外保存上下文；但改名或删除会改变甚至抹掉历史事件的意义，因此新记录保存名称快照，仅旧记录使用只读兼容查找。

把原始 detail JSON 全部展示，开发调试方便且不会漏字段；但大部分键对用户不可读，也可能在未来扩展时意外显示敏感值，因此采用明确字段白名单。

## Verification

- 后端新增七条上下文/日期回归及关联 Admin/Share/AI/OpenAPI 测试通过，验证操作者/对象改名删除后的快照、旧记录只读回退、属主隔离、凭据白名单与日期/分页。
- 前端七项语义、七项日期筛选与七项语言守卫通过；英文条数按真实数字选择单复数，日期覆盖上海、纽约夏令时及纳秒上界。
- 43 项浏览器回归先复现原码展示、长标题、部分日期及 reset 缺陷，再验证可读事件、中英文、详情、五项菜单、分页/筛选、加载/失败/空态、手机布局和普通用户隔离；开发服务与生产构建均通过。
- 浏览器使用独立内存接口，后端使用临时库，不读取开发配置或修改开发数据；类型、构建和笔记校验作为提交门禁。

## Consequences

日志可回答谁对什么做了什么，完整查询不再受概览八条限制。代价是每条新日志保存少量身份与名称信息；旧记录补充查询按本页唯一账号/对象数量增长，使用页内缓存且限制页长。

旧记录未保存的历史名称或设置旧值无法恢复，不能通过补译制造不存在的细节。旧记录读取补充的是仍存在实体的当前名称，新记录优先保留事件快照；设置不展示旧值或新值。来源 IP 延续既有受信代理配置，不为美化日志扩大转发头的信任范围。
