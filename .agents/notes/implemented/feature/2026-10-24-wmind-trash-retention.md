# Agent Note: 回收站全局保留期限与分批清理

Status: implemented

## Problem

回收站只支持手动恢复、删除和清空，已删除导图会永久保留；卡片还用 updatedAt 展示删除时间，不能表达全局保留期限。

## Decision

- 管理员设置 `trash.retention_days`，默认 30，允许 1–3650 个完整 24 小时；调整期限影响全部现存回收站内容，不另存每张图的期限。
- 使用 deleted_at 计算到期时间，恢复清除此时间，再次删除重新计时。回收站响应增加 deletedAt 和 expiresAt，卡片剩余天数向上取整，到期显示「即将删除」。
- 服务启动和每小时运行清理，每批最多 100 张，只删除 deleted_at 不为空且不晚于截止时间的记录。删除沿用数据库外键级联，不移除可能仍被其他导图引用的上传文件。
- 全局清理使用独立 TrashRepo，不给面向用户、必须含 ownerID 的 MapRepo 增加跨用户删除方法；每一批共用备份 Gate，维护期间跳过清理，恢复重载设置后按新快照继续。
- 后台清理可取消并在数据库关闭前等待结束；错误记录日志并在下一轮重试。
- 双方言迁移 0004 添加 partial `(deleted_at, id)` 索引，避免每批全表排序。新时间字段保留毫秒，倒计时每分钟更新并刷新列表；保存保留期限会使回收站查询失效。
- 剩余天数的中英文语言包保留相同基础键及 `_one`/`_other` 变体与相同 `count` 占位符；英文由 i18next 按数字选择 day/days，中文变体沿用「天」。语言包键与占位符的严格守卫继续生效，不为单个复数字段豁免跨语言契约。

## Alternatives considered

- 每张导图保存 expires_at 能固定删除时的承诺，也容易索引；但会使管理员修改全局保留天数无法覆盖旧内容，且引入不必要的双时间状态，采用现有 deleted_at 加当前策略计算。
- 访问回收站时顺便清理能省去后台任务；但没人访问就不清理，请求也承担删除开销，采用可取消的定时任务。
- 全局一次 DELETE 最简单；大量过期数据会长时间占用写锁和维护门，采用有界批次，每批重新检查维护状态。
- 按各语言的 CLDR 复数类别只存所需变体更精简，但当前语言包要求键和占位符完全对齐；补齐中文相同文案变体与英文基础键能保留有效守卫，也不把英文退化为 day(s) 或所有数量都用 days。

## Testing

- 设置、清理任务、SQLite 契约、HTTP 真实接口通过定向测试和 `-race`；毫秒精度 DTO 单测通过。覆盖默认30天、校验与持久化、全局跨用户分批、截止边界、恢复和再次计时、维护门暂停、错误释放、服务启动和周期及取消退出。
- PostgreSQL 17.11 隔离实库通过相同仓储契约和两项真实行锁竞态（恢复、恢复后再次删除），`-race` 无异常。测试观察 DELETE 已被 updater PID 阻塞再提交更新，清理均返回0，更新后的记录保留。
- 浏览器路由夹具 11/11：默认30天、向上取整、到期/未知状态、驻留刷新、恢复、管理员字段和校验、仅提交改动、修改期限影响旧内容及英文。前端4项倒计时单测、生产构建、静态双方言迁移对照及 service/handler 方言隔离门禁通过。
- 四项本批界面验收已纳入 run-all；各自脚本只使用接口夹具，不写开发库。
- `locales.test.ts` 先复现回收站基础键/变体缺项造成的键和占位符两项失败；补齐后继续验证严格语言包守卫，并用独立 i18next 实例覆盖 0/1/2/30 天的中英文实际输出。

## Consequences

回收站不再无限增长，管理员能统一调整期限，恢复与再次删除保持原来的软删除语义。期限缩短会使已有内容在下一次清理时永久删除，设置页明确显示这一影响。每小时清理意味着到期后可能最多等待一小时，维护、错误或并发恢复导致本批不足100行时会延至后续轮次。上传资源沿用现有手动删除语义，不自动清除共享文件；全局索引占用少量额外空间并增加删除时间更新时的写入成本。
