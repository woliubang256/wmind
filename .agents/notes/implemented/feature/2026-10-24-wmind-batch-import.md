# Agent Note: 文件按顺序批量导入并打开最后成功项

Status: implemented

## Problem

文件选择器没有 multiple，弹窗拖放和页面拖放均只取第一个文件，其他文件被丢弃。用户要求多个文件全部导入，处理完自动打开最后一个导图，同时保留既有 Markdown 文本入口、导入摘要与异步任务隔离。

## Decision

文件选择与两处拖放统一转换为有序来源队列。逐个检查单文件尺寸、读取、注册表解析和图片收尾，全部完成后显示逐文件摘要与错误；一次确认依次创建所有可用项，全部尝试结束才导航到最后一个成功 uid。解析或创建失败只影响当前项；创建失败逐项显示，部分成功导航时仍提示失败文件名。

队列串行运行，不同时读取多个 ZIP，不扩大既有单文件安全上限。任务编号在关闭、卸载、切换来源或开始新任务时失效，停止后续读取、上传和创建，旧完成回调不能导航或改写界面。创建入口使用同步 ref 互斥，防止同一渲染周期重复点击；已取得 uid 的项不能再次提交。未知网络结果不自动重放请求。

图片上传遇到 429 后，整个批次不再发出后续上传请求，后续文档仍继续解析，并在各自摘要中如实记录未还原图片。队列从对话框提取到 `import-batch.ts`，纯流程单测与浏览器交互测试分别守住顺序和入口行为。

## Related notes

[导入对话框](../architecture/2026-10-20-wmind-import-dialog.md)部分重叠，本篇扩展单文件输入为有序批次，保留先摘要再确认、文本入口和失效任务隔离；[导入框架](../architecture/2026-10-20-wmind-import-framework.md)保留每文件注册表和资源安全闸门。[XMind 连线修复](../bug-fix/2026-10-24-wmind-xmind-connection-mapping.md)使用同一浏览器套件验证首次打开与保存刷新。检索活跃笔记后，无其他同主题提案需要取代。

## Alternatives considered

- 并发解析和创建可缩短总等待，但多个大 ZIP 会同时占用解压内存，图片容易撞限流，完成顺序也不等于选择顺序，因此使用串行队列。
- 逐个文件弹确认沿用现有单文件界面，但需要多次操作且会在第一个创建后离开队列，因此所有摘要集中展示后一次确认。
- 一个文件失败就停止可减少错误处理代码，但后续有效文件会被遗漏，不符合多文件需求，因此隔离每项失败。

## Verification

- `import-batch.test.ts` 的 5 项测试通过：顺序与尺寸/格式错误隔离、取消读取、批次图片限流、创建失败及重试跳过成功项、卸载后停止后续创建。
- `e2e/import-batch.mjs` 使用匿名默认夹具与用户原 XMind 文件分别通过全部 15 项：多选、两处拖放、逐项摘要和警告、双击互斥、串行创建、最后成功项、部分/全部失败、显式重试、取消、中英与 375px 窄屏、连线首次显示及编辑保存刷新。
- 原 `e2e/import-tabs.mjs` 的 22 项通过，覆盖文本入口、键盘 Tab 与关闭后的读取/上传隔离。浏览器接口由夹具拦截，不写开发数据库；原文件不进入仓库。
- 导入、布局、导出、批次和语言包相关单测共 30 文件 / 589 项通过；类型检查和生产构建通过。

## Consequences

一次选择或拖入的文件全部保留，单项失败不再丢掉后续文件；一次确认完成后直接进入最后成功导图。串行处理耗时随文件数增加，多个解析后的文档在确认前仍占内存；单文件安全上限保持原值。取消不能撤回已经发出的单个上传或创建请求；离开时只阻止后续请求和旧 UI 回调。API 没有通用幂等键，响应丢失时不自动重试，避免主动重复创建。
