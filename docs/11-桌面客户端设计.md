## 1. 目标与边界

桌面客户端与 Web **并行交付**，不是 Web 的替代品，也不是「必须先部署服务器才能用」的浏览器壳。

| 需求 | 落地方式 |
| --- | --- |
| 与 Web 一样的功能体验 | 复用同一份前端 SPA 与同一套后端 API，桌面只换装配 |
| 任何情况下离线优先 | 默认本地模式：本机 SQLite，免登录，零出站即可完整使用 |
| 可连服务器 | 可选登录自托管地址，导图带「本地 / 云端」身份，本地可转云端 |
| 冲突不丢数据 | 一期整文档三选项（保留我的 / 放弃我的 / 另存副本）；二期三路合并 |
| AI 可离线配置 | 本机设置 → AI，API Key 本地加密，请求由本地 Go 直接发出 |
| 备份可离线配置 | 本地目录（默认）+ 复用现有 S3 / WebDAV 目标 |

**不在本设计范围**：iOS / Android、实时多人协作（见 [一期不做实时协作](../.agents/notes/proposed/feature/2026-10-16-wmind-collaboration-deferred.md)）、Linux 首发的打磨（随发布后补齐）。

## 2. 总体架构

```
┌──────────────────────────────────────────────────────────────┐
│ mygo 窗口（WKWebView / WebView2 / WebKitGTK）                  │
│  └─ 内嵌的现有 React SPA（web/dist，编译期 go:embed）      │
│        │ fetch http://127.0.0.1:<port>/api/v1/*  （同源）       │
├────────▼─────────────────────────────────────────────────────┤
│ 本地 Go 后端：复用现有 gin router / service / repository        │
│  ├─ 本地 SQLite（复用 db/migrations/sqlite）                   │
│  ├─ 本地 uploads（复用 storage.NewLocalStore）                 │
│  ├─ 同步引擎（新，M-D2）──▶ 远端服务器 /api/v1（JWT）           │
│  ├─ 本地 AI 配置（复用 internal/ai + 本地 settings）            │
│  └─ 本地备份（复用 internal/backup + folder 目标）              │
├──────────────────────────────────────────────────────────────┤
│ mygo 桌面能力：单实例、菜单、文件关联、原生对话框、自动更新       │
└──────────────────────────────────────────────────────────────┘
```

### 2.1 三种形态，同一份代码

| 形态 | 数据位置 | 登录 | 入口 |
| --- | --- | --- | --- |
| Web | 服务器 DB | 需要 | `backend/cmd/server`（现状不变） |
| 桌面 · 本地模式 | 本机 SQLite | 不需要 | `desktop`（默认） |
| 桌面 · 云端模式 | 服务器 + 本地缓存 | 需要 | `desktop` |

### 2.2 关键约束

1. **前端只访问本机回环后端**。云端的 HTTP 请求由本地 Go 后端代发，前端不知道也不关心对端是远端还是本机。因此：单源同源（无 CORS）、refresh cookie 照旧、`/uploads/:key` 的私有鉴权照旧、离线与在线共用同一段前端代码。
2. **本地后端就是同一个 gin router**。装配抽到 `backend/internal/bootstrap`，`cmd/server` 与桌面共用；差异只有配置来源、数据目录、身份来源。
3. **本机回环的边界**：监听 `127.0.0.1:0`（随机端口），启动时生成一次性访问令牌注入 `window.__WMIND__`，后端校验令牌与 `Origin`，避免本机其它进程读走接口。

## 3. 模块与目录布局

```
backend/
├── cmd/server/               # Web 入口（保持不变）
├── internal/bootstrap/       # 新：依赖装配，cmd/server 与桌面共用
├── internal/desktop/         # 新：本地模式专有逻辑（本地身份、目录、secrets、同步）
├── internal/sync/            # 新（M-D2）：拉取/推送/状态机/asset 映射
├── internal/backup/          # 改：新增 target = "folder"
├── internal/handler/maps.go  # 改：updated_since / include_deleted / 客户端 uid 幂等
└── desktop/                  # 新：嵌套 Go 模块（桌面入口与打包配置）
    ├── go.mod                # module .../desktop，go 1.27.3（mygo 要求）
    ├── main.go               # mygo 应用：窗口、单实例、菜单、生命周期
    ├── mygo.config.ts        # 应用名/标识/版本（版本取自 VERSION）/图标/打包
    ├── resources/icon.png
    └── frontend-dist/        # 构建产物，编译期嵌入（不入库）
```

**为什么桌面是嵌套模块**：mygo 要求 Go 1.27.3，而后端基线与发布镜像是 Go 1.26.10（安全基线，见[工具链笔记](../.agents/notes/implemented/process/2026-10-26-wmind-security-toolchain-baseline.md)）。把桌面做成 `module github.com/woliubang256/wmind/desktop`（模块路径仍在 `backend` 之下），既能把工具链隔离在桌面侧，又能直接复用 `backend/internal/*`（Go 的 internal 规则按导入路径前缀判定，不按 go.mod 边界）。代价是桌面构建需要 Go 1.27.3 的工具链，Web 侧不受影响。

## 4. 本地数据

```
macOS  ~/Library/Application Support/wmind/
Windows %APPDATA%\wmind\
Linux  ~/.local/share/wmind/
├── wmind.db        # SQLite（maps / templates / themes / settings / trash / map_sync）
├── uploads/        # 图片与缩略图，与服务器同构
├── backups/        # 本地备份默认目录
├── secrets         # 本地主密钥（0600）
├── logs/
└── cache/          # 云端模式的远端文档与图片缓存
```

- 数据库文件与服务器共用同一套迁移集（`db/migrations/sqlite`），升级时先自动备份一次再迁移。
- 本地模式固定一个 owner 身份（`local`），由中间件注入，保留 JWT 结构以复用 `service` / `handler`；不写登录页。
- 本地库不启用 `share_links`（分享需要服务器），列表页隐藏入口。

## 5. 同步模型（M-D2）

### 5.1 三层数据与状态

本地表 `map_sync`（仅桌面端存在）：

| 字段 | 说明 |
| --- | --- |
| `map_uid` | 本地导图 uid |
| `remote_uid` | 云端 uid；未上传时为空 |
| `base_version` / `base_hash` | 上次成功同步的远端版本与内容哈希 |
| `last_synced_at` | 上次同步时间（UTC） |
| `state` | `local-only` / `synced` / `local-dirty` / `remote-dirty` / `conflict` / `offline` |

### 5.2 流程

1. **拉取**：`GET /maps?updated_since=&include_deleted=1`（一期只设计了参数，**需要实现**）→ 与 `base_version` 比对。
2. **推送**：`PUT /maps/{uid}`（现有 `version` 乐观锁）→ 409 时重新拉取远端文档。
3. **冲突**：一期弹出现有三选项对话框（保留我的 / 放弃我的 / 另存副本），并展示节点数等最小差异信息。
4. **提交**：成功后更新 `base_version` / `base_hash` / `last_synced_at`。
5. **删除**：回收站删除状态双向同步，期限按真实 `deleted_at` 计算（与服务器同一套规则）。

### 5.3 范围与已知取舍

- 同步：导图文档（含多画布）、图片附件、缩略图、回收站删除状态。
- 暂不同步：自定义主题、用户模板。
- 图片：文档里存的是 URL，跨端 URL 不同，靠 `asset_map` 做 URL 重写（先上传拿远端地址再替换）。文档格式加稳定 `assetId` 需升 `formatVersion`，二期再做。

### 5.4 服务端需要补齐的接口

| 接口 | 变更 |
| --- | --- |
| `GET /maps` | 支持 `updated_since`、`include_deleted`；列表项带 `version` / `updatedAt` / `deleted` |
| `POST /maps` | 支持客户端指定 `uid`，同 uid 已存在时幂等返回既有资源 |
| `PUT /maps/{uid}` | 409 的 `details` 补 `documentHash`，便于判断是否真冲突 |

## 6. 本地 / 云端标识

- 列表页卡片徽标：`本地` / `云端` / `已同步` / `有本地修改` / `同步中` / `冲突`；顶部筛选：全部 / 本地 / 云端。
- 本地文件：`上传到云端`（幂等，重复点击不产生重复副本）、`在云端查看`。
- 云端文件：`下载为本地副本`、删除时区分`仅本地删除`与`云端也删除`。
- 编辑器保存状态扩展为：`已保存到本机 · 未上传` / `已同步` / `有冲突（点击处理）`。

## 7. AI 与备份

**AI**：复用 `internal/ai`（单 provider、AES-GCM 加密、固定提示词追加在素材之后）。本地模式把「管理员 AI 配置」变成「本机设置 → AI」，写入本地 `settings` 表同一 `ai.config` 键，密钥由本地主密钥派生；出站请求由本地 Go 直接发出。云端模式默认用服务器配置，允许本机覆盖。

**备份**：复用 `internal/backup`（cron、保留 30 份、去重开关、归档含数据库行 + uploads、恢复预览与暂存），新增 `target = "folder"`，默认目录 `userData/backups`；`s3` / `webdav` 保留。桌面「设置 → 备份」复用现有备份表单，去掉服务器运维术语。

## 8. 打包与发布

- 版本号**与 `VERSION` 同号**：`scripts/build-desktop.mjs` 从 `VERSION` 读版本，注入桌面入口与后端 `config.Version`，并**校验 `desktop/mygo.json` 的 `version` 与之一致**（不一致直接构建失败，避免「装的 1.0.1 报告自己是 1.0.0」让自动更新永远认为该更新）。
- 平台优先级：**macOS 与 Windows 首发**；Linux 适配（`libwebkit2gtk-4.1` 依赖与渲染性能）随发布后补齐。
- 产物：macOS `.app` + `.dmg`（ad-hoc 签名；公证需要 Developer ID，见下）、Windows `.exe` + `.zip` + NSIS 安装包、Linux 可执行 + `.deb` + tarball。
- **Linux 不出 AppImage**：它挂载为只读，mygo 的更新器需要写应用目录，应用内自动更新在 AppImage 里直接失效（`Enabled()` 为 false），而 `.deb` 与 tarball 解开的目录可以自更新。AppImage 另外还要单独的工具链（appimagetool 只能在 Linux 上跑），与「一台 macOS runner 出全部产物」的发布结构冲突。
- **每个平台都出 arm64 与 amd64 两个包**（macOS、Windows 各两份），用户按机器选择，不做 universal/双架构单包。
- 常用命令：`node scripts/build-desktop.mjs --package --platform darwin/universal`。
- 自动更新：mygo 签名更新源 + 增量更新；发布流程并入现有 `scripts/release.mjs`。
- 前端 `dist` 在构建时嵌入二进制，桌面端不需要额外静态资源目录。

**签名与公证（需要凭据，不在仓库里）**

| 平台 | 需要什么 | 怎么用 |
| --- | --- | --- |
| macOS | Developer ID Application 证书 + Apple ID 公证凭据 | `mygo.json` 的 `macos.signingIdentity`，或 `-sign` / `MYGO_SIGN_IDENTITY`；公证由 mygo 读取钥匙串里的 `notarytool` 凭据完成 |
| Windows | 代码签名证书（.pfx） | `mygo.json` 的 `windows.certificate` 与密码 |
| Linux | 无 | 只出 `.deb` 与 tarball；`.deb` 的维护者信息来自 `linux.maintainer` |

没有证书时构建照常完成，只是产物未签名（`MYGO_SKIP_DMG=1` 还能跳过本机 `ditto` 不支持 `--noclone` 的旧 macOS 出盘步骤）。

**CI**：`.github/workflows/ci.yml` 里的 `desktop` 作业用 Go 1.27.3（嵌套模块的要求）跑 `go vet` + `go test`，然后跑
`node scripts/build-desktop.mjs --platform darwin/arm64,darwin/amd64,windows/amd64,windows/arm64`
产出四个平台的安装包与更新清单，作为构建产物上传。

**发布工作流**：`.github/workflows/desktop-release.yml`，推 `desktop-v<版本>` 标签触发
（与 Web 版的 `v*` 发布完全分开，避免一次桌面发布顺手重推 Web 镜像）。

**按 runner 成本拆成三个作业**（macOS runner 比 ubuntu 贵一个数量级）：

| 作业 | runner | 干什么 |
| --- | --- | --- |
| `packages` | ubuntu-24.04 | 前端构建、`go test`、四平台交叉编译与打包（含 apt 装的 NSIS 出 Windows 安装包）、生成更新清单 |
| `dmg` | macos-14 | 只做三件事：下载 `.app` → ad-hoc 签名 → `hdiutil` 出 `.dmg`（约 2–4 分钟） |
| `publish` | ubuntu-24.04 | 汇总产物、建 Release、`--latest=false` |

两条关键约束写在这里，避免以后有人把 darwin 打包挪回 macOS：

1. **`.dmg` 只能在 macOS 上打**：`hdiutil` 是 macOS 独有的。所以 macOS 作业保留，但只做打盘这一步（`--dmg-only`，跳过前端与编译）。
2. **Linux 打出来的 `.app` 未签名**：`codesign` 也只有 macOS 有，而 Apple Silicon 上未签名的可执行文件会被直接 kill。所以 macOS 作业在出盘前补一次 ad-hoc 签名（与 mygo 默认的 `-` 身份一致）。

**发布私钥必须配成仓库 secret** `MYGO_UPDATER_PRIVATE_KEY`（`mygo keygen` 生成的
`mygo-update.key` 的内容）：有它 CI 才会写 `update-<平台>.json`；没有它照样能
构建，但产出的版本无法被已安装的客户端升级，发布前必须配好。公钥在
`desktop/mygo.json` 里入库，两者必须成对。

### 8.1 自动更新

客户端用 mygo 的签名更新源：`mygo.Updater.Check` 读 GitHub release 的更新清单，
`Update.Install` 下载（带进度回调）、校验 Ed25519 签名、替换应用，`App.Relaunch`
重启后生效。界面是我们自己的：启动后 3 秒自动检查一次，有新版弹窗显示发布说明
（来自 `desktop/CHANGELOG.md` 的 `## <版本>` 一节）与下载进度条，下载
完成后由用户点「立即重启」；个人设置里另有「检查更新」入口。

| 项 | 值 |
| --- | --- |
| 更新清单 | `update-darwin-arm64.json` / `update-darwin-amd64.json` 等，由 `mygo build` 生成 |
| 公钥 | `desktop/mygo.json` 的 `updates.publicKey`（入库） |
| 私钥 | `~/Library/Application Support/mygo/update-keys/mygo-update.key`（**不入库**，需另存备份并放进 CI secrets 的 `MYGO_UPDATER_PRIVATE_KEY`） |
| 发布渠道 | GitHub `woliubang256/wmind`，标签前缀 `desktop-v`（与 Web 的 `v*` 发布互不干扰） |
| 发布命令 | `MYGO_UPDATER_PRIVATE_KEY=… node scripts/build-desktop.mjs --package`，产物含清单与归档；`-upload` 由 mygo 直接传到草稿 release |

私钥丢失 = 已安装的客户端再也收不到更新（只能让用户手动重装），所以它必须
和代码分开保管。

**本地/自托管验证**：设置 `WMIND_UPDATE_FEED=http://<host>/<dir>` 可以让客户端
改从普通 HTTP 目录取清单（目录里放 `update-<os>-<arch>.json` 与归档），用于
本地把「检查 → 下载 → 替换 → 重启」整条链跑一遍，也给自托管更新源留了口子。发布顺序：先改 `VERSION` 与 `desktop/CHANGELOG.md`，
再出包，最后发布 release（`gh release edit desktop-v<版本> --draft=false --latest=false`，
避免把桌面版发布设成「最新」，否则 Web 版的 `v*` 发布会被盖掉）。

## 9. 里程碑

| 里程碑 | 内容 | 验收 |
| --- | --- | --- |
| M-D1 | bootstrap 抽取、`desktop` 模块、本地模式（SQLite/uploads/身份/回环令牌/内嵌前端）、三端出包 | 断网全功能可用、重启不丢数据、不出现登录页 |
| M-D2 | 云端登录、`map_sync`、增量拉取/推送、来源徽标、本地转云端、图片映射、删除状态同步、三选项冲突 | 两端修改不丢数据、上传幂等、断网恢复后自动补齐 |
| M-D3 | 本地 AI 设置、本地备份/恢复、secrets | 断网可配置与调用；Key 不明文落盘 |
| M-D4 | 签名/公证、NSIS、`.deb`、自动更新、CI 三端产物 | 安装包可安装运行、`.wmind` 双击可打开、更新校验通过 |
| 二期 | 三路合并 + 可视化合并面板、文档 `assetId`、主题/模板同步 | 合并逐项可选、撤销栈不受污染 |

**发布策略**：M-D1 ~ M-D4 一起发布，不单独发布纯离线版本。

（`docs/wmind_logo.png`，原位保留）派生——1024 画布、824 本体、圆角半径 185.4、
外加一层柔和投影，符合 macOS Big Sur 起的 squircle 规范。**系统不会自动裁圆角**，
所以图标文件本身必须带形状与边距。

出盘方式：`.dmg` 由 `scripts/build-desktop.mjs` 用 `hdiutil` 生成（内含 `wmind.app`
与指向 `/Applications` 的软链接），而不是交给 mygo 的 dmg 步骤——后者调用
`ditto --noclone`，该选项在 macOS 13 及更早的 `ditto` 上不存在，会直接失败。

**DMG 窗口外观**：`scripts/build-dmg-background.py` 生成 660×400 的品牌背景图
（渐变 + 光晕 + logo + 标题 + 图标之间的弧形箭头），出包时写入卷内
`.background/background.png`，并用 Finder 自动化（AppleScript）摆好图标、定好
窗口大小。两个硬约束：**Finder 不缩放背景图**（图必须与窗口同尺寸，否则只
显示左上角一块）；图标坐标与背景里的箭头必须对齐（应用 (200,300)、
Applications (460,300)）。无界面环境或 Finder 自动化被拒时回退朴素窗口，
不让出包失败。
卷图标以「挂载 → 写 `.VolumeIcon.icns` → `SetFile -a C` → 重新压缩」的方式设置
（macOS 13 的 `hdiutil create` 没有 `-volicon`）；拿不到 `SetFile` 时退回无卷图标的普通 dmg。
macOS 出 **arm64 与 amd64 两个包**（各自原生运行，用户按机器选择），不再出
universal 单包——那会让所有人多下载一倍体积；确有需要时仍可显式指定
`--platform darwin/universal`。

## 10. 风险

| 风险 | 缓解 |
| --- | --- |
| Linux 运行时依赖与渲染性能（`libwebkit2gtk-4.1`；mygo 默认关闭 DMA-BUF 渲染器） | Linux 排在发布后，先 macOS/Windows；真机压测大文档后决定 `App.SetDMABUFRenderer` 策略 |
| 图片以 URL 存储，跨端同步需 URL 映射 | 一期用 `asset_map`，二期引入 `assetId` |
| 双份文档模型（TS / Go）漂移 | 合并与校验只在 TS 实现；新增字段时两侧同步，纳入检查清单 |
| mygo 处于 0.x，API 演进快 | `go.mod` 用 `tool` 指令锁版本；桌面壳保持薄，前端始终可独立部署 |
| 本地 SQLite 单写者 + 高频保存 | 实测大文档保存耗时，必要时调整防抖与批量写 |
| 桌面与 Web 迁移集同源 | 升级前自动备份本地库；迁移失败即中止启动，不降级运行 |
