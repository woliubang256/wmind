## 2. M0 · 工程脚手架与基础设施

**目标**：任何人在 5 分钟内能把项目跑起来。

### 交付物

| 项 | 内容 |
| --- | --- |
| 仓库结构 | `backend/` `frontend/` `deploy/` `docs/` 四目录；根 `README.md` 写清启动步骤 |
| 后端骨架 | Go module、Gin 路由、配置加载、slog 日志、统一响应与错误码、健康检查、优雅退出 |
| 数据库 | PostgreSQL 迁移文件（初始 schema 全部表）、sqlc 配置与首次生成、连接池 |
| 前端骨架 | Vite + React + TS + Tailwind v4 + shadcn 初始化、路由骨架、API 客户端（含错误码映射）、TanStack Query Provider |
| 代码规范 | ESLint + Prettier + `go vet` + `gofmt`；Git hooks（pre-commit 格式化、commit-msg 校验 Conventional Commits） |
| 部署 | `deploy/docker-compose.yml` + 两个 Dockerfile + nginx.conf；`docker compose up -d` 可启动空壳系统 |
| 测试基建 | 后端 `testify` + `testcontainers-go` 跑通一个示例集成测试；前端 Vitest 跑通一个示例单测 |
| 笔记机制 | 建立 `.agents/notes/` 目录结构，配置 `npm run verify-notes` 等脚本（当前仓库尚无 `package.json`，需补齐） |

### 验收标准

1. `docker compose up -d` 后访问 `http://localhost` 看到前端页面，`/api/v1/health/ready` 返回 200。
2. 前端 `pnpm dev` + 后端本地启动，也能正常联调（CORS 已配）。
3. 提交一次代码，pre-commit 自动格式化，commit-msg 校验生效。
4. CI（GitHub Actions）跑通：lint + 单元测试 + 构建镜像。

### 依赖与风险

- 无前置依赖。
- 风险：**`.agents/notes/` 的 `verify-notes` 脚本依赖 `package.json`**，而当前仓库没有 Node 工程在根目录。需决定把 npm script 放在根目录（新增根 `package.json`）还是 `frontend/`。建议根目录新增极简 `package.json` 只承载工具链脚本。

## 3. M1 · 账号体系与管理后台

**目标**：管理员能管用户，用户能注册登录。

### 交付物

**后端**

| 模块 | 内容 |
| --- | --- |
| 认证 | 注册 / 登录 / 刷新 / 登出 / 改密 / 头像上传；bcrypt；JWT 双令牌；refresh token 持久化与撤销 |
| 中间件 | Recover / RequestID / Logger / CORS / RateLimit / RequireAuth / RequireRole |
| 用户 | `GET /auth/me`、`PATCH /users/me`、`POST /users/me/password`、`POST /users/me/avatar` |
| 站点配置 | `GET /site/config`（公开）、`GET/PUT /admin/settings`、设置内存缓存与失效 |
| 管理 | 用户列表（搜索 / 筛选 / 分页）、创建、编辑、禁用、重置密码、删除（含导图策略）、统计概览 |
| 审计 | 敏感操作写 `audit_logs` |

**前端**

| 页面 | 内容 |
| --- | --- |
| 登录 / 注册 | 表单校验（zod）、错误码映射文案、注册开关联动 |
| 应用外壳 | 侧边导航 + 顶部用户菜单（占位页面） |
| 个人设置 | 资料、改密、头像 |
| 管理后台 | 用户列表表格、用户编辑抽屉、站点设置分组表单、概览卡片 |
| 基础设施 | API 客户端含 401 自动刷新 + 并发刷新合并；路由守卫（登录态、管理员态） |

### 验收标准

1. 关闭注册后，注册页不可达，直接调接口返回 403 `REGISTRATION_CLOSED`。
2. 用户 A 构造请求访问用户 B 的导图 → 404。
3. 禁用用户后，其已签发 Access Token 立即失效（下一次请求返回 403）。
4. 管理员不能删除自己，也不能降级/删除最后一个管理员。
5. Access Token 过期后，前端静默刷新，用户无感知；多个并发请求只触发一次刷新。
6. 连续 5 次密码错误后账号锁定 15 分钟。

### 风险

- **刷新令牌并发**：多个请求同时 401 会触发刷新风暴，必须在前端做单例 Promise 合并。这是常见坑，需专门写测试。

## 4. M2 · 编辑器内核（关键里程碑）

**目标**：能新建一张导图，用键盘和鼠标完成结构化编辑，并可靠保存。

### 4.1 交付物拆分

| 子阶段 | 内容 | 工作量 |
| --- | --- | --- |
| M2.1 文档模型与状态 | TS 类型、遍历工具、校验、Zustand store、命令接口与撤销栈 | 3 人日 |
| M2.2 文本测量与布局（mindmap） | Canvas 测量 + 缓存；`mindmap` 结构布局（左右平衡）；几何输出 | 4 人日 |
| M2.3 SVG 渲染 | 分层渲染、`TopicNode`、连线、选区、编辑态输入框 | 4 人日 |
| M2.4 交互 | 命中测试、平移缩放、键盘映射、双击编辑、折叠展开 | 5 人日 |
| M2.5 拖拽与多选 | 拖拽改父级/排序、自由主题、框选、批量操作 | 4 人日 |
| M2.6 持久化 | 自动保存状态机、乐观锁冲突处理、本地草稿、离开保护 | 3 人日 |
| M2.7 其余结构布局 | `logic-right` `org-chart` `tree-right` | 2 人日 |

### 4.2 验收标准

1. **纯键盘完成**：新建根节点下 3 个子节点 → 改名 → 加粗变色 → 折叠 → 撤销全部 → 重做全部，全程不碰鼠标。
2. 撤销/重做 100 步后文档与初始状态完全一致（快照比对）。
3. 1000 节点导图打开 < 1.5s；拖拽保持 60fps。
4. 编辑后刷新页面内容完整；断网编辑 30 秒后恢复网络，内容自动补存。
5. 两个标签页同时编辑同一导图，后保存者收到 409 冲突提示，三个处理选项行为正确。
6. 折叠节点显示被隐藏的后代数量。
7. 拖拽时非法落点（拖到自己的后代）被拒绝且有视觉反馈。

### 4.3 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 「像不像 XMind」难以量化 | 反复返工 | 建立**对照清单**：把截图 3 的每一项交互列成 checklist，逐项打勾；每 2~3 天演示一次 |
| SVG 在 2000+ 节点时卡顿 | 大导图不可用 | 提前做性能基线测试（M2.3 结束时用 2000 节点压测），不达标就上视口裁剪 |
| 文本测量精度导致布局错位 | 视觉瑕疵 | 测量结果做四舍五入到 0.5px；布局常量集中管理便于统一微调 |
| 撤销栈内存膨胀 | 长时间编辑后 OOM | 依赖 immer 结构共享；栈深上限 200；定期在 1000 节点场景下测内存 |
| Safari 的 `foreignObject` 兼容问题 | 编辑器在 Safari 不可用 | 编辑态直接用绝对定位 `div` 叠加，不用 `foreignObject` |

## 5. M3 · 样式与主题系统

**目标**：主题、颜色、形状与 XMind 一致。

### 交付物

| 项 | 内容 |
| --- | --- |
| 样式解析引擎 | `resolveStyle` 纯函数 + 记忆化；样式继承链；调色板按 `branchIndex` 分配 |
| 样式面板 | 形状 / 填充 / 边框 / 宽度 / 文本（字体、字号、字重、颜色、B/I/U/S、对齐）/ 结构 / 分支（线条、端点、粗细）/ 彩虹分支 |
| 配色面板 | 缤纷 5 套 + 经典 5 套；背景色；全局字体；分支线粗细；彩虹分支开关与取色 |
| 布局开关 | 自动平衡、紧凑型、同级对齐 |
| 结构切换 | 补齐 `timeline` `fishbone` `brace` `tree-table` 四种布局 |
| 主题数据 | 10 套配色的**校准后**色值落库为内嵌 JSON；对比度校验脚本 |
| 自定义主题 | 用户保存/复用自定义主题（后端 `themes` CRUD + 前端入口） |
| 画布面板 | 「样式 / 演说 / 画布」三 Tab（演说 Tab 一期占位） |

### 验收标准

1. 逐项比对截图 3 与截图 4 的 UI 控件，全部存在且生效。
2. 10 套配色方案切换后，分支填充、线条、中心主题配色同步改变，内容零丢失。
3. 手动改过颜色的节点，在切换配色方案后**保持**手动颜色。
4. 8 种结构均可正确渲染，无节点重叠、无连线穿越节点。
5. 所有配色的文字与填充对比度 ≥ 4.5:1（脚本校验通过）。
6. 用同一份导图在 XMind 与 wmind 中应用同一配色导出 SVG，视觉对比容差 ≤ 2%。

### 风险

- **色值校准**是本阶段最大不确定性。必须在阶段开始时先完成采样与校准（见 [06-导入导出与主题系统](./06-导入导出与主题系统.md) §5.4），否则后续返工面很大。
- **字体许可**：XMind 默认字体 `NeverMind` 不可分发，需确认替代方案（建议思源黑体），并在导入时做字体名映射。

## 6. M4 · 导入导出

**目标**：三种格式进得来，六种格式出得去。

### 交付物

| 项 | 内容 | 工作量 |
| --- | --- | --- |
| 导入框架 | 适配器接口 + 注册表 + 导入对话框（拖拽上传、解析摘要、警告列表） | 2 人日 |
| XMind 导入 | 现代格式（content.json）+ XMind 8（content.xml + styles.xml）+ 图片上传 + 降级策略 | 6 人日 |
| Markdown 导入 | 标题模式 + 列表模式自动判定 + 元素映射 | 2 人日 |
| OPML 导入 | XML 解析 + 属性映射 | 1 人日 |
| 导出框架 | 导出上下文构建 + 独立 SVG 构建 + 导出对话框（含实时预览） | 2 人日 |
| 图片导出 | SVG / PNG / JPEG + 边框预设 + 缩放 + 透明背景 + 日期与品牌标识 | 1.5 人日 |
| PDF 导出 | jsPDF + svg2pdf + 字体内嵌/文字转路径 | 2 人日 |
| 文本导出 | Markdown + OPML | 0.5 人日 |
| 服务端导出（可选） | chromedp 兜底 | 3 人日（可延后） |

### 验收标准

1. [06-导入导出与主题系统](./06-导入导出与主题系统.md) §6 的 IE-01 ~ IE-20 全部通过。
2. 导入 50MB 以内的真实 XMind 文件不崩溃，内存峰值 < 500MB。
3. 伪造的 zip 炸弹在 200MB 处被中止。
4. 导出的 PNG 与画布所见一致（像素级对比，容差 1%）。
5. 导出的 PDF 中文正常显示。
6. 导出对话框所有选项（截图 7/8）可用且生效。

### 风险

| 风险 | 对策 |
| --- | --- |
| XMind 格式无公开文档 | 准备 5+ 真实样本作为测试夹具；先做样本驱动开发，不凭推测 |
| `styles.xml` 版本差异 | 解析失败时降级为「只导入内容 + 默认主题」，不阻断导入 |
| PDF 中文字体 | 默认文字转路径；若仍不达标，切服务端 chromedp 方案 |
| Canvas 尺寸上限 | 导出前预计算，超限时明确提示并引导服务端导出 |

## 7. M5 · 模板与导图管理

**目标**：完成「最近 → 新建 → 编辑 → 保存 → 回收站」的完整产品闭环。

### 交付物

| 项 | 内容 |

| 模板选择 | 对话框、分类筛选、8 个内置模板（含骨架内容与默认主题） |
| 模板管理 | 另存为模板、我的模板列表、重命名、删除 |
| 回收站 | 列表、恢复、彻底删除、清空 |
| 缩略图 | 前端渲染首屏后上传；列表与模板卡片复用 |
| 多画布 | 底部 Map Tab 栏：新增、重命名、删除、排序、切换 |
| 大纲视图 | 缩进列表编辑整棵树，与画布双向同步 |
| ZEN 模式 | 隐藏全部面板的全屏编辑 |
| 导图内其他能力 | 备注、标签、超链接、标记面板、联系、外框、概要 |

### 验收标准

1. 从 8 个内置模板各创建一次导图，结构符合模板定义。
2. 删除导图 → 回收站可见 → 恢复 → 内容完整。

4. 搜索标题能正确过滤；列表分页/滚动加载正常。
5. 大纲视图与画布编辑实时同步。
6. 多画布切换不丢失未保存内容。

**目标**：可交付给真实用户使用。

4. 在干净机器上按部署文档操作，30 分钟内完成上线。
5. 需求文档第 7 节「验收标准」全部通过。

## 9. 关键路径与依赖

```
M0 ─▶ M1 ─▶ M2 ─┬─▶ M3 ─┐
                │       ├─▶ M6
                └─▶ M4 ─┤
                        │
                   M5 ──┘
```

| 依赖关系 | 说明 |
| --- | --- |
| M2 是硬关键路径 | M3（样式）与 M4（导出）都依赖 M2 的文档模型与渲染层。M2 延期会整体延期 |
| M3 的色值校准可提前 | 校准工作不依赖代码，可在 M1 期间并行开展 |
| M4 的导入解析可提前 | XMind 样本收集与格式逆向可在 M2 期间并行开展 |
| M5 依赖 M2 + M3 | 模板需要结构与主题；缩略图需要渲染层 |
| 服务端导出可延后 | 属于 M6 的可选优化项，不阻塞交付 |

## 10. 并行建议

若有 2 人：

- **A（前端内核）**：M2 全程 → M3 → M4 导出
- **B（后端 + 产品外壳）**：M1 → M5 的后端与页面 → M4 导入 → M6 部署

若只有 1 人：严格按 M0 → M1 → M2 → M3 → M4 → M5 → M6 顺序，**不要**在中途插入样式微调或功能扩展。

## 11. 一期之后的候选方向

按价值排序（供二期立项参考）：

| 优先级 | 方向 | 前置条件 |
| --- | --- | --- |
| 1 | 分享链接与公开只读预览 | 只需新增 `share_tokens` 表与只读路由，成本低、价值高 |
| 2 | 历史版本与回滚 | `map_revisions` 表已设计，实现成本中等 |
| 3 | 客户端 App（iOS / Android / 桌面） | 需要设备注册、增量同步、离线存储 |
| 4 | 团队空间与细粒度权限 | 需要 `workspace` + ACL 模型 |
| 5 | 实时多人协作 | 需要 WebSocket + CRDT/OT，改动最大 |
| 6 | AI 一键生成导图 | 需要 LLM 接入与提示词工程 |
| 7 | 甘特图 / 演说模式 | 依赖现有文档模型的扩展字段 |
| 8 | 图库（贴纸、图标素材） | 相对独立，可独立排期 |
