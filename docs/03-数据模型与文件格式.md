本文档是**跨端契约文档**：前端文档模型、后端存储、导入导出适配器、未来的客户端 App 都以此为唯一真相源。任何字段改动都属于破坏性变更，需同步更新本文档并升级 `formatVersion`。

---

## 1. 存储格式决策

### 1.1 候选方案

| 方案 | 说明 | 优势 | 劣势 |
| --- | --- | --- | --- |
| A. 直接以 **XMind 格式**（`.xmind` zip + `content.json`）为内部存储 | 原样保存用户的 XMind 文件 | 与 XMind 100% 互通，导入导出零转换 | ① 格式由厂商私有演进，随时可能变；② 无法表达 wmind 自己的扩展（权限、版本、协作元数据）；③ XMind 的样式属性体系庞大且未公开文档化，跟随成本极高；④ 数据库里存 zip 二进制，无法做 JSONB 查询与局部更新 |
| B. 以 **OPML** 为内部存储 | XML 大纲 | 格式极简、通用性好 | 只表达「层级 + 文本」，**无法表达样式、主题、形状、联系、外框、概要、标记**——而本项目一半的价值在样式 |
| C. 以 **Markdown** 为内部存储 | 标题/列表大纲 | 人类可读、Git 友好 | 同 B，且更弱（连节点 ID 都没有，无法稳定标识节点） |
| D. **自有 JSON 格式（`.wmind`）**，结构对齐 XMind `content.json`，第三方格式只作进出口适配器 ✅ | 自有 schema + 适配层 | ① 完全掌控演进；② 可扩展；③ JSONB 可查询、可局部更新；④ 字段命名与结构尽量贴近 XMind，使导入导出转换成本最低；⑤ 语言无关，客户端 App 可直接复用 | 需要自己维护一份 schema 与转换器 |

### 1.2 结论

**采用方案 D。** 具体约定：

1. 内部唯一真相源是 `.wmind` JSON 文档，存入 `maps.document`（PostgreSQL `JSONB`）。
2. `.xmind` / `.opml` / `.md` 只在**导入**时解析为 `.wmind`，在**导出**时从 `.wmind` 生成，内核不感知第三方格式。
3. `.wmind` 的结构（`sheets[].rootTopic.children.attached`、`notes`、`labels`、`markers`、`relationships`、`boundaries`、`summaries`、`extensions`）刻意与 XMind `content.json` 对齐；样式键名与 XMind 的 SVG 风格属性名做一对一映射表，使转换是「改名」而非「翻译」。
4. 预留 `extensions` 数组与 `formatVersion`，用于承载未来能力而不破坏旧文件解析。

## 2. `.wmind` 文档格式规范

### 2.1 顶层结构

```jsonc
{
  "format": "wmind",              // 固定值，用于文件识别
  "formatVersion": "1.0",         // 语义化版本，破坏性变更时升 major
  "id": "01JFA8Z3K5N7Q2R9T4V6W8X0Y1",
  "title": "未命名导图",
  "theme": { /* Theme，见 2.5 */ },
  "sheets": [ /* Sheet[]，至少 1 个 */ ],
  "meta": {
    "createdAt": "2026-10-16T02:00:00Z",
    "updatedAt": "2026-10-16T02:30:00Z",
    "app": "wmind/1.0.0"
  },
  "extensions": []                // 保留扩展位
}
```

### 2.2 Sheet（画布）

```jsonc
{
  "id": "sh-01",
  "title": "Map 1",
  "structure": "mindmap",         // 默认结构，Topic 可覆盖
  "rootTopic": { /* Topic */ },
  "floatingTopics": [ /* Topic[]，自由主题 */ ],
  "relationships": [ /* Relationship[] */ ],
  "boundaries": [ /* Boundary[] */ ],
  "summaries": [ /* Summary[] */ ],
  "themeOverride": null,          // 该画布独立主题，null 表示继承文档级 theme
  "extensions": []
}
```

### 2.3 Topic（主题 / 节点）

```jsonc
{
  "id": "tp-01",                  // 文档内唯一，导入时生成，导出 XMind 时原样写出
  "title": "中心主题",
  "titleFormat": "plain",         // plain | rich（rich 时 title 为受限 HTML）
  "structure": null,              // 该节点子树使用的结构，null 表示继承
  "style": { /* Style，见 2.4 */ },
  "collapsed": false,
  "href": "",                     // 超链接
  "notes": {
    "plain": "",
    "html": ""
  },
  "labels": ["标签 A", "标签 B"],
  "markers": [
    { "groupId": "priority", "markerId": "priority-1" },
    { "groupId": "task", "markerId": "task-done" }
  ],
  "image": null,                  // { "src": "/api/v1/files/xxx", "width": 120, "height": 80 }
  "children": {
    "attached": [ /* Topic[]，挂在树上的子主题 */ ],
    "detached": [ /* Topic[]，该节点的浮动子主题 */ ]
  },
  "summaries": [ /* Summary[]，作用于此节点子集 */ ],
  "boundaries": [ /* Boundary[]，作用于此节点子集 */ ],
  "extensions": []
}
```

**约束**：

- `id` 在单文档内必须唯一；导入外部文件时若原 ID 冲突则重新生成。
- 树深度不设硬上限，但 UI 在深度 > 30 时给出性能提示。
- `children.attached` 的顺序即渲染顺序，是文档的一部分（排序变更需进撤销栈）。
- 叶子节点 `children.attached` 为空数组，而非省略字段——保持结构同构，简化遍历代码。

### 2.4 Style（样式）

样式采用**扁平键值对**，键名与 XMind 的 SVG 风格属性一一对应（映射表见 §5.3）。`null` 或缺失表示「继承主题」。

```jsonc
{
  "shape": "rounded-rect",        // 见 2.4.1
  "fill": "#FFFFFF",              // 填充色，null 表示无填充
  "fillPattern": "solid",         // solid | none | gradient
  "borderColor": "#000000",
  "borderWidth": 2,
  "borderStyle": "solid",         // solid | dash | dot | none
  "fontFamily": "NeverMind",
  "fontSize": 30,
  "fontWeight": 700,              // 100..900
  "fontStyle": "normal",          // normal | italic
  "textDecoration": "none",       // none | underline | line-through
  "textColor": "#000000",
  "textAlign": "center",          // left | center | right
  "width": 178,                   // 固定宽度，px
  "autoWidth": true,              // true 时忽略 width，按内容自适应
  "lineStyle": "curve",           // 分支线：straight | curve | elbow | none
  "lineEnd": "none",              // 端点：none | arrow | dot
  "lineWidth": 2,
  "lineColor": "#000000",
  "rainbowBranch": false,         // 该分支启用彩虹色
  "backgroundColor": null
}
```

#### 2.4.1 形状枚举

| 值 | 对应 XMind shape-class | 说明 |
| --- | --- | --- |
| `rect` | `org.xmind.ui.rect` | 矩形 |
| `rounded-rect` | `org.xmind.ui.roundedRect` | 圆角矩形（默认） |
| `capsule` | `org.xmind.ui.capsule` | 胶囊形 |
| `ellipse` | `org.xmind.ui.ellipse` | 椭圆 |
| `circle` | `org.xmind.ui.circle` | 圆形 |
| `diamond` | `org.xmind.ui.diamond` | 菱形 |
| `hexagon` | `org.xmind.ui.hexagon` | 六边形 |
| `parallelogram` | `org.xmind.ui.parallelogram` | 平行四边形 |
| `underline` | `org.xmind.ui.underline` | 仅下划线 |
| `none` | `org.xmind.ui.none` | 无形状 |

### 2.5 Theme（主题 / 配色方案）

```jsonc
{
  "id": "classic-rainbow",
  "name": "彩虹",
  "category": "classic",          // vivid（缤纷） | classic（经典） | custom
  "palette": {
    "colors": ["#E53935", "#FB8C00", "#FDD835", "#43A047", "#1E88E5", "#8E24AA"],
    "lineColors": ["#E53935", "#FB8C00", "#FDD835", "#43A047", "#1E88E5", "#8E24AA"],
    "backgroundColor": "#FFFFFF"
  },
  "global": {
    "fontFamily": "NeverMind",
    "fontSize": 14,
    "lineWidth": 2,
    "backgroundColor": "#FFFFFF"
  },
  "centralTopic": { /* Style 覆盖，仅含差异字段 */ },
  "mainTopic": { /* Style 覆盖 */ },
  "subTopic": { /* Style 覆盖 */ },
  "floatingTopic": { /* Style 覆盖 */ },
  "summaryTopic": { /* Style 覆盖 */ },
  "boundary": { "borderColor": "#999999", "borderStyle": "dashed", "fill": "#F5F5F5" },
  "relationship": { "lineColor": "#999999", "lineWidth": 1, "lineEnd": "arrow" },
  "rainbowBranch": true,
  "rainbowColors": ["#E53935", "#FB8C00", "#FDD835", "#43A047", "#1E88E5", "#8E24AA"],
  "layout": {
    "autoBalance": true,
    "compact": false,
    "alignSiblings": false,
    "freeBranch": false,
    "flexibleFloating": false,
    "topicOverlap": false
  }
}
```

**样式解析顺序**（后写覆盖前写）：

```
内置默认样式
  → 文档级 theme.global
  → 文档级 theme.{centralTopic|mainTopic|subTopic}
  → 画布级 sheet.themeOverride（若存在，整链替换）
  → 节点级 topic.style（显式非 null 字段）
  → 调色板分配（同级分支按 index 取 palette.colors[i % n]）
```

> **关键规则**：调色板颜色**不写入** `topic.style`。只有当用户手动指定颜色时，才把颜色固化到节点样式里。这样切换配色方案才能整体生效——这是「一份导图随时换主题不丢内容」的实现基础。

### 2.6 附属结构

```jsonc
// Relationship：两个主题间的自由连线
{
  "id": "rel-01",
  "end1Id": "tp-03",
  "end2Id": "tp-07",
  "title": "依赖",
  "style": { "lineColor": "#999999", "lineEnd": "arrow", "lineStyle": "curve" }
}

// Boundary：圈住一组主题
{
  "id": "bnd-01",
  "title": "第一阶段",
  "range": ["tp-03", "tp-04"],       // 目标主题 ID 列表
  "style": { "borderColor": "#8E24AA", "borderStyle": "dashed", "fill": "#F3E5F5" }
}

// Summary：对一组同级主题的汇总
{
  "id": "sum-01",
  "topicId": "tp-03",                // 汇总节点挂载的父主题
  "range": ["tp-04", "tp-05"],       // 被汇总的兄弟主题
  "title": "小结",
  "style": { /* Style 覆盖 */ }
}
```

### 2.7 文件与 MIME

| 项 | 值 |
| --- | --- |
| 扩展名 | `.wmind` |
| MIME | `application/vnd.wmind+json` |
| 编码 | UTF-8，无 BOM |
| 格式 | 纯 JSON（不压缩）。如需体积优化，二期可引入 `.wmindz`（zip + 同名 JSON） |

## 3. 数据库设计

数据库：PostgreSQL 16。迁移文件位于 `backend/db/migrations/`。

### 3.1 ER 概览

```
users ──┬── maps ──┬── map_revisions
        │          └── files (缩略图)
        ├── templates
        ├── themes
        ├── files
        ├── refresh_tokens
        ├── user_devices      （预留）
        └── audit_logs
settings （全局键值）
```

### 3.2 表结构

#### users

```sql
CREATE TABLE users (
  id            BIGSERIAL PRIMARY KEY,
  uid           TEXT        NOT NULL UNIQUE,          -- 对外暴露的 ULID，避免自增 ID 泄露规模
  username      TEXT        NOT NULL UNIQUE,
  email         TEXT        NOT NULL UNIQUE,
  password_hash TEXT        NOT NULL,
  nickname      TEXT        NOT NULL DEFAULT '',
  avatar_url    TEXT        NOT NULL DEFAULT '',
  role          TEXT        NOT NULL DEFAULT 'user',  -- user | admin
  status        TEXT        NOT NULL DEFAULT 'active',-- active | disabled | pending
  map_count     INTEGER     NOT NULL DEFAULT 0,       -- 冗余计数，避免列表页 N+1
  last_login_at TIMESTAMPTZ,
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  deleted_at    TIMESTAMPTZ
);
CREATE UNIQUE INDEX uq_users_email_lower ON users (lower(email)) WHERE deleted_at IS NULL;
```

#### maps

```sql
CREATE TABLE maps (
  id            BIGSERIAL PRIMARY KEY,
  uid           TEXT        NOT NULL UNIQUE,
  owner_id      BIGINT      NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  title         TEXT        NOT NULL DEFAULT '未命名导图',
  document      JSONB       NOT NULL,                 -- 完整 .wmind 文档
  version       INTEGER     NOT NULL DEFAULT 1,       -- 乐观锁
  thumbnail_url TEXT        NOT NULL DEFAULT '',
  node_count    INTEGER     NOT NULL DEFAULT 0,
  size_bytes    INTEGER     NOT NULL DEFAULT 0,
  deleted_at    TIMESTAMPTZ,                          -- 软删除 = 回收站
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_maps_owner_updated ON maps (owner_id, updated_at DESC) WHERE deleted_at IS NULL;
CREATE INDEX idx_maps_owner_deleted ON maps (owner_id, deleted_at)     WHERE deleted_at IS NOT NULL;
CREATE INDEX idx_maps_title_trgm    ON maps USING gin (title gin_trgm_ops);
```

#### templates

```sql
CREATE TABLE templates (
  id            BIGSERIAL PRIMARY KEY,
  uid           TEXT        NOT NULL UNIQUE,
  owner_id      BIGINT      REFERENCES users(id) ON DELETE CASCADE,  -- NULL = 内置
  name          TEXT        NOT NULL,
  category      TEXT        NOT NULL,                 -- basic | user
  structure     TEXT        NOT NULL,
  document      JSONB       NOT NULL,                 -- 模板骨架（一份合法 .wmind）
  thumbnail_url TEXT        NOT NULL DEFAULT '',
  sort_order    INTEGER     NOT NULL DEFAULT 0,
  is_builtin    BOOLEAN     NOT NULL DEFAULT false,
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_templates_owner ON templates (owner_id);
```

#### themes

```sql
CREATE TABLE themes (
  id         BIGSERIAL PRIMARY KEY,
  uid        TEXT        NOT NULL UNIQUE,
  owner_id   BIGINT      REFERENCES users(id) ON DELETE CASCADE,     -- NULL = 内置
  name       TEXT        NOT NULL,
  category   TEXT        NOT NULL,                    -- vivid | classic | custom
  config     JSONB       NOT NULL,                    -- Theme 对象
  is_builtin BOOLEAN     NOT NULL DEFAULT false,
  sort_order INTEGER     NOT NULL DEFAULT 0,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

#### settings

```sql
CREATE TABLE settings (
  key        TEXT        PRIMARY KEY,
  value      JSONB       NOT NULL,
  updated_by BIGINT      REFERENCES users(id) ON DELETE SET NULL,
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

#### refresh_tokens

```sql
CREATE TABLE refresh_tokens (
  id         BIGSERIAL PRIMARY KEY,
  user_id    BIGINT      NOT NULL REFERENCES users(id) ON DELETE CASCADE,
```

#### user_devices（本期建表，暂不写入）

```sql
CREATE TABLE user_devices (
```

```sql
CREATE TABLE files (
  id          BIGSERIAL PRIMARY KEY,
  uid         TEXT        NOT NULL UNIQUE,

  kind        TEXT        NOT NULL,                   -- avatar | map-image | thumbnail

);
```

#### audit_logs

```sql
CREATE TABLE audit_logs (
  id          BIGSERIAL PRIMARY KEY,
  actor_id    BIGINT      REFERENCES users(id) ON DELETE SET NULL,
  action      TEXT        NOT NULL,                   -- user.disable / settings.update / user.delete ...
  target_type TEXT        NOT NULL DEFAULT '',
  target_id   TEXT        NOT NULL DEFAULT '',
  detail      JSONB       NOT NULL DEFAULT '{}',
  ip          INET,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_audit_created ON audit_logs (created_at DESC);
```

#### map_revisions（P2，可先建表不启用）

```sql
CREATE TABLE map_revisions (
  id         BIGSERIAL PRIMARY KEY,
  map_id     BIGINT      NOT NULL REFERENCES maps(id) ON DELETE CASCADE,
  version    INTEGER     NOT NULL,
  document   JSONB       NOT NULL,
  created_by BIGINT      REFERENCES users(id) ON DELETE SET NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (map_id, version)
);
```

### 3.3 设计说明

- **为什么用 `uid` 而非自增 ID 对外**：自增 ID 会暴露系统规模与创建顺序，且不利于将来分库。对外接口一律使用 `uid`。
- **为什么 `document` 整存 JSONB 而不拆表**：导图是一棵整体树，拆成 `topics` 表会导致「打开导图 = 一次递归查询」和「保存 = 全量 diff 写回」，复杂度与性能都更差。JSONB 支持局部路径更新（`jsonb_set`）与 GIN 索引，满足将来的服务端检索需求。
- **为什么列表页需要 `node_count` / `size_bytes` 冗余**：列表与统计页需要展示节点数，实时从 JSONB 统计代价高，保存时顺带写入。
- **软删除**：`maps.deleted_at` 非空即视为回收站内容；所有查询默认带 `deleted_at IS NULL`。

## 4. 站点设置项

存于 `settings` 表，后台可改，接口 `/api/v1/admin/settings`。

| key | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `site.name` | string | `wmind` | 站点名称，显示于浏览器标题与登录页 |
| `site.logo` | string | `""` | Logo 图片 URL |
| `site.description` | string | `""` | 站点描述 |
| `site.icp` | string | `""` | ICP 备案号，显示于页脚 |
| `auth.registration_enabled` | bool | `true` | **是否开放注册**（核心开关） |
| `auth.email_verification_required` | bool | `false` | 注册是否需邮箱验证（依赖 SMTP） |
| `auth.default_role` | string | `"user"` | 新注册用户默认角色 |
| `auth.password_min_length` | int | `8` | 密码最小长度 |
| `auth.login_max_attempts` | int | `5` | 连续登录失败上限 |
| `auth.login_lock_minutes` | int | `15` | 触发上限后的锁定时长 |
| `limit.maps_per_user` | int | `0` | 单用户导图数量上限，`0` = 不限 |
| `limit.upload_max_mb` | int | `10` | 单文件上传上限（MB） |
| `feature.import_enabled` | bool | `true` | 是否允许导入 |
| `feature.export_enabled` | bool | `true` | 是否允许导出 |
| `feature.user_template_enabled` | bool | `true` | 是否允许用户保存自定义模板 |
| `feature.share_link_enabled` | bool | `false` | 分享链接（预留，二期） |

**读取策略**：公开配置（`site.*`、`auth.registration_enabled`、`feature.*`）通过 `/api/v1/site/config` 暴露给未登录用户；敏感配置（`auth.login_max_attempts`、`limit.*`）仅管理员可读。

**缓存**：设置项在后端内存缓存，`settings` 表更新时失效，TTL 60s 兜底。

## 5. 格式映射

### 5.1 结构映射

| wmind `structure` | XMind `structureClass` | 说明 |
| --- | --- | --- |
| `mindmap` | `org.xmind.ui.map.unbalanced` | 思维导图（左右分布） |
| `logic-right` | `org.xmind.ui.logic.right` | 逻辑图（向右） |
| `logic-left` | `org.xmind.ui.logic.left` | 逻辑图（向左） |
| `org-chart` | `org.xmind.ui.org-chart.down` | 组织结构图 |
| `tree-right` | `org.xmind.ui.tree.right` | 树形图 |
| `timeline` | `org.xmind.ui.timeline.horizontal` | 时间轴 |
| `fishbone` | `org.xmind.ui.fishbone.rightHeaded` | 鱼骨图 |

### 5.6 Markdown 映射

**导入**（两种识别模式，自动判定）：

1. **标题模式**：`#` 为第 1 层，`##` 为第 2 层，依此类推。第一个 `#` 之前的正文作为中心主题的备注。
2. **列表模式**：以无序列表缩进（2 或 4 空格为一档）推断层级；文档中第一个非列表行作为中心主题。

| Markdown 元素 | wmind 映射 |
| --- | --- |
| 标题 / 列表项 | `title` |
| 行内代码 `` `标签` `` | `labels` |
| 引用块 `> ...` | `notes.plain` |
| 链接 `[文本](url)` | `title` + `href` |
| 图片 `![alt](url)` | `image` |
| 任务列表 `- [x]` | `markers`：`task-done` / `task-start` |
| 加粗 / 斜体 | 忽略（不进入样式，避免过度映射） |

**导出**：

```markdown
# 中心主题

> 中心主题的备注（若有）

## 分支主题 1

- 子主题 A
- 子主题 B `标签`

## 分支主题 2
```

- 中心主题 → `#`，一级分支 → `##`，二级 → `###`……超过 6 层时统一用 `######` 并加缩进列表。
- 备注 → 引用块。
- 标签 → 行内代码。
- 超链接 → `[标题](url)`。

## 7. 版本演进约定

| 变更类型 | 处理方式 |
| --- | --- |
| 新增可选字段 | `formatVersion` minor +1，旧文件可读，新文件旧版忽略未知字段 |
| 字段语义变更 / 删除字段 | `formatVersion` major +1，提供迁移函数 `migrate(v1 → v2)` |
| 未知字段 | 解析器**必须保留**未知字段并在回写时原样输出（`extensions` 机制），避免第三方格式往返丢数据 |

解析器实现要求：读取到 `formatVersion` major 大于当前支持版本时，拒绝打开并提示「该文件由更新版本创建，请升级」；major 相同、minor 更大时正常打开。
