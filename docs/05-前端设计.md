## 4. 编辑器内核

### 4.1 分层

```
┌─ UI 层（React） ──────────────────────────────────┐
│  工具栏 / 面板 / 对话框 / 状态栏                     │
│  只读 store，通过 dispatch(command) 修改            │
└────────────────┬─────────────────────────────────┘
                 │
┌─ Store 层（Zustand + immer） ─────────────────────┐
│  doc · selection · viewport · history · saveState  │
└────────────────┬─────────────────────────────────┘
                 │
┌─ 内核层（纯 TS，无 React / 无 DOM） ───────────────┐
│  model    文档结构、遍历、校验、ID 生成              │
│  measure  文本测量（唯一允许接触 DOM 的地方，见 4.3） │
│  layout   文档 + 结构 → 几何                        │
│  theme    主题 + 节点上下文 → 计算样式               │
│  export   文档 → SVG 字符串 / Markdown / OPML       │
└──────────────────────────────────────────────────┘
```

> `measure` 是唯一的例外：文本测量必须借助 Canvas 2D 的 `measureText`，因此单独成模块并做结果缓存，其余内核模块保持纯净。

### 4.3 文本测量（`measure`）

```ts
const ctx = document.createElement('canvas').getContext('2d')!;

export function measureText(text: string, font: FontSpec, maxWidth: number): { width: number; height: number; lines: string[] }
```

- 缓存键：`${text}|${font.family}|${font.size}|${font.weight}|${maxWidth}`，LRU 容量 5000。
- 换行规则：按空格与 CJK 字符边界折行；`\n` 强制换行。
- 主题宽度为 `autoWidth: true` 时，宽度 = `max(最小宽度 60, min(内容宽度, 320))` + 左右内边距。

### 4.4 布局引擎

**统一输入输出**：

```ts
interface LayoutInput {
  sheet: Sheet;
  theme: Theme;
  measure: (t: Topic) => { width: number; height: number };
  options: { compact: boolean; alignSiblings: boolean; ... };
}

interface LayoutResult {
  boxes: Map<string, NodeBox>;   // topicId → 盒子
  edges: EdgePath[];             // 父子连线
  bounds: Rect;                  // 内容包围盒
}

interface NodeBox {
  id: string;
  x: number; y: number;          // 左上角坐标（画布坐标系）
  width: number; height: number;
  depth: number;
  branchIndex: number;           // 一级分支序号，决定调色板取色
  side: 'left' | 'right' | 'none';
  collapsed: boolean;
  hiddenChildren: number;        // 折叠时被隐藏的后代数
}
```

**各结构算法**：

| structure | 算法 |
| --- | --- |
| `mindmap` | 把根的一级子节点按「交替 + 平衡」分成左右两组（按子树高度贪心分配以平衡两侧）；每组用 `d3.tree` 的 `nodeSize` 模式生成横向树；两侧垂直居中于根 |
| `logic-right` / `logic-left` | 单向横向树，`d3.tree` + 旋转；同层节点垂直堆叠 |
| `org-chart` | 标准自上而下树，`d3.tree`；父节点水平居中于子节点跨度 |
| `tree-right` | 横向树，与 `logic-right` 布局相同，仅连线样式改为折线 |
| `timeline` | 主轴水平居中；一级子节点沿主轴等距分布并上下交替；二级及以下挂在一级节点下方（上方节点则向上展开） |
| `fishbone` | 主骨为水平线；一级子节点作为支骨以固定夹角（±45°）斜向附着，交替上下；二级挂在支骨末端 |
| `brace` | 根在左，一级子节点纵向排列，父与子之间绘制花括号路径；二级继续右移 |
| `tree-table` | 网格布局：列 = 深度，行 = 节点顺序；每列等宽（取该列最宽节点）；表头行为一级子节点 |

**间距常量**（可被主题的 `layout.compact` 覆盖）：

| 常量 | 默认 | 紧凑 |
| --- | --- | --- |
| 同级垂直间距 | 24 | 12 |
| 父子水平间距 | 48 | 28 |
| 画布内边距 | 80 | 40 |

**性能**：节点数 > 1000 时把布局计算搬进 Web Worker（`layout.worker.ts`），主线程仅接收 `LayoutResult`；`LayoutResult` 中的 `Map` 在 postMessage 时转为 `Array<[string, NodeBox]>` 传输。

### 4.5 渲染层

SVG 结构：

```html
<svg class="wmind-canvas">
  <defs><!-- 渐变、阴影、箭头 marker、图案 --></defs>
  <g class="viewport" transform="translate(tx,ty) scale(k)">
    <g class="layer-boundaries">…</g>
    <g class="layer-edges">…</g>
    <g class="layer-summaries">…</g>
    <g class="layer-relationships">…</g>
    <g class="layer-topics">…</g>
    <g class="layer-overlay"><!-- 选区框、拖拽指示线 --></g>
  </g>
</svg>
```

- **分层渲染**：按 z-order 拆成独立 `<g>`，避免重排时整树 diff。
- **`TopicNode` 组件**：`React.memo` + 自定义比较器（仅比较 `box` 引用、`style` 引用、`selected`、`editing`）。
- **样式内联**：颜色、字体、线宽一律通过 `style` 属性内联输出到元素上，**不用 CSS class** —— 这样 SVG 序列化导出时样式自动携带，无需额外注入 `<style>`。
- **形状渲染**：`rounded-rect` / `rect` / `capsule` / `ellipse` 等用 `<rect rx>` / `<ellipse>` / `<path>` 表达；`underline` 只画底部线条；`none` 不画容器。
- **文本渲染**：`<text>` + `<tspan>` 逐行输出；`text-anchor` 由 `textAlign` 决定。
- **连线**：`curve` 用三次贝塞尔（控制点取父子中点），`straight` 用 `<line>`，`elbow` 用 `<path>` 折线，`none` 不渲染。
- **编辑态**：双击主题后，在其位置叠加一个绝对定位的 `contenteditable` div（或 `<foreignObject>` 内嵌 textarea），编辑结束回写模型。选择 `div` 叠加方案以规避 Safari 对 `foreignObject` 的兼容问题。

**虚拟化**：节点数 > 2000 时，只渲染视口内 + 200px 缓冲区内的节点；`bounds` 之外的主题不生成 DOM。

#### 4.6.3 拖拽

1. `pointerdown` 记录起始主题与指针位置（阈值 4px 才进入拖拽态，避免误触）。
2. `pointermove` 更新幽灵元素位置；每帧做一次「落点计算」：
   - 找到距离指针最近的节点（用 `boxes` 做粗筛 + 精确距离）。
   - 根据指针相对该节点的位置决定落点语义：落在节点**中心区域** → 成为其子节点；落在节点**上/下边缘 25% 区域** → 成为其同级（插到前/后）。
   - 校验合法性：目标不能是被拖拽节点的后代。
3. 绘制指示：目标节点高亮 + 插入位置竖线/横线。
4. `pointerup` 提交 `MoveTopicCommand`。
5. 拖到画布空白处 → `DetachTopicCommand`，变为自由主题。

#### 4.6.4 多选

`selection: Set<string>`。框选：在空白处按下并拖拽，绘制选框，`pointerup` 时用包围盒与 `boxes` 求交。多选后支持批量改样式、批量删除、批量移动。

### 4.7 命令与撤销栈

**命令定义**：

```ts
export interface EditorCommand {
  type: string;                       // 'topic.add' | 'topic.rename' | ...
  label: string;                      // 撤销提示文案，如「新建主题」
  apply(draft: WmindDocument, ctx: CommandContext): void;   // immer draft，原地修改
  coalesceWith?: (prev: EditorCommand) => boolean;          // 连续输入合并
}
```

**历史栈**：

```ts
interface HistoryEntry { label: string; doc: WmindDocument; selection: string[] }
history: { past: HistoryEntry[]; future: HistoryEntry[] }
```

- 每次命令执行：`past.push(当前快照)`，`future = []`。
- 依赖 immer 的**结构共享**，快照只复制变更路径，1000 节点导图单个快照增量通常 < 10KB。
- 栈深上限 200，超出丢弃最旧的。
- `coalesceWith`：连续 `topic.rename` 在 800ms 内且同一主题时合并为一条历史记录，避免逐字入栈。

**命令清单**（一期）：

| 分组 | 命令 |
| --- | --- |
| 主题 | `topic.add` `topic.remove` `topic.rename` `topic.move` `topic.detach` `topic.collapse` `topic.paste` |
| 样式 | `style.update`（批量）`style.reset` |
| 结构 | `structure.change`（sheet 级 / topic 级） |
| 主题色 | `theme.apply` `palette.change` `background.change` `rainbow.toggle` |
| 附属 | `relationship.add` `relationship.remove` `boundary.add` `boundary.remove` `summary.add` `summary.remove` `marker.toggle` `label.update` `note.update` `href.update` `image.set` |
| 画布 | `sheet.add` `sheet.remove` `sheet.rename` `sheet.reorder` |
| 文档 | `title.change` `document.replace`（导入 / 版本回滚） |

> 视图变换（缩放、平移）与面板开合**不进**撤销栈。

## 5. 主题系统（前端）

### 5.1 样式解析链

```ts
export function resolveStyle(
  topic: Topic,
  ctx: { depth: number; branchIndex: number; isRoot: boolean; isFloating: boolean; isSummary: boolean },
  theme: Theme
): ComputedStyle
```

解析顺序（后覆盖前）：

```
内置兜底默认值
  → theme.global（字体、字号、线宽、背景）
  → 角色样式 theme.centralTopic / mainTopic / subTopic / floatingTopic / summaryTopic
  → 调色板分配：palette.colors[ctx.branchIndex % palette.colors.length]
                 （仅当该字段未被显式指定时）
  → topic.style 的显式非 null 字段
```

**关键点**：调色板颜色是**计算得出**而非写入文档。用户手动改色时才把颜色固化进 `topic.style`。这样切换配色方案能整体生效。

`rainbowBranch` 为 true 时，`branchIndex` 对应的一级分支使用 `theme.rainbowColors` 循环取色，且该分支下所有后代继承同一色系。

### 5.2 计算样式类型

```ts
export interface ComputedStyle {
  shape: ShapeClass;
  fill: string | null;
  fillPattern: 'solid' | 'none' | 'gradient';
  borderColor: string;
  borderWidth: number;
  borderStyle: 'solid' | 'dash' | 'dot' | 'none';
  fontFamily: string;
  fontSize: number;
  fontWeight: number;
  fontStyle: 'normal' | 'italic';
  textDecoration: 'none' | 'underline' | 'line-through';
  textColor: string;
  textAlign: 'left' | 'center' | 'right';
  width: number;
  autoWidth: boolean;
  lineStyle: 'straight' | 'curve' | 'elbow' | 'none';
  lineEnd: 'none' | 'arrow' | 'dot';
  lineWidth: number;
  lineColor: string;
  rainbowBranch: boolean;
}
```

`resolveStyle` 必须是纯函数并带记忆化（键 = `topic.id + JSON.stringify(topic.style) + theme.id + branchIndex`），避免每次重渲染重复计算。

### 5.3 字体

- 内置字体族：`NeverMind`（默认，随应用分发 WOFF2 子集）、`Inter`、`Source Han Sans SC`（思源黑体）、系统字体栈。
- 字体子集：仅打包常用汉字（GB2312 一级字库 ≈ 3755 字）+ 拉丁字母 + 标点，控制体积在 1.5MB 以内。
- 导出 SVG/PDF 时需**内嵌字体**或降级为路径，详见 [06-导入导出与主题系统](./06-导入导出与主题系统.md) 第 3 节。

### 5.4 配色面板 UI

对应截图 4：Tab 切换「缤纷 / 经典」两栏，每栏 5 个色带预览（渐变缩略图）；点击即应用；「背景颜色」「全局字体」「分支线粗细」为独立控件；「彩虹分支」为开关 + 颜色选择器。

## 6. 状态管理

### 6.1 Zustand Store 划分

| Store | 内容 | 是否进撤销栈 |
| --- | --- | --- |
| `useDocStore` | `document`、`dirty`、`version` | ✅（通过 history 管理） |
| `useEditorStore` | `selection`、`editingTopicId`、`viewport`、`activeSheetId`、`panelState`、`mode`（普通/ZEN/大纲） | ❌ |
| `useHistoryStore` | `past`、`future` | — |
| `useSaveStore` | `status`、`lastSavedAt`、`error`、`conflict` | — |

**订阅粒度**：组件使用选择器订阅最小切片，例如：

```ts
const selected = useEditorStore((s) => s.selection);
const boxes = useLayoutStore((s) => s.boxes);   // 由 layout 计算结果派生
```

**布局结果不入 doc store**：布局是派生的，通过 `useMemo` 从 `document + theme + measure` 计算，避免布局数据被误写入撤销栈。

### 6.2 服务端状态（TanStack Query）

| Query Key | 接口 | 失效时机 |
| --- | --- | --- |
| `['maps', filters]` | `GET /maps` | 创建/删除/重命名导图后 |
| `['map', uid]` | `GET /maps/{uid}` | 保存成功后 `setQueryData` 局部更新，不整体失效 |
| `['templates']` | `GET /templates` | 模板增删后 |
| `['themes']` | `GET /themes` | 主题增删后 |
| `['site-config']` | `GET /site/config` | `staleTime: Infinity`，登录态变化时手动失效 |
| `['admin','users', filters]` | `GET /admin/users` | 用户增删改后 |
| `['admin','settings']` | `GET /admin/settings` | 保存设置后 |

全局配置：`retry: 1`、`refetchOnWindowFocus: false`（避免编辑器误刷新）。

## 7. 自动保存与冲突处理

### 7.1 状态机

```
        ┌──────── 编辑 ────────┐
        ▼                      │
     idle ──(dirty)──▶ dirty ───┘
                        │ 防抖 800ms / 最长 5s
                        ▼
                     saving ──成功──▶ saved ──(编辑)──▶ dirty
                        │
                        ├──网络错误──▶ error ──(重试 3 次，指数退避)──▶ saving
                        └──409──────▶ conflict
```

### 7.2 保存实现

```ts
const save = useDebouncedCallback(async () => {
  if (!docStore.dirty) return;
  const snapshot = docStore.document;
  const version = docStore.version;
  try {
    const res = await api.saveMap(uid, { version, title: snapshot.title, document: snapshot });
    docStore.markSaved(res.version);        // 仅当期间无新编辑时才置为干净
  } catch (e) {
    if (e.code === 'MAP_VERSION_CONFLICT') { saveStore.setConflict(e.details.currentVersion); }
    else { saveStore.setError(e); }
  }
}, 800, { maxWait: 5000 });
```

**「仅当期间无新编辑时才置为干净」**：保存请求发出后用户可能继续编辑，此时 `document` 引用已变。比较发起时的 `snapshot` 引用与当前引用是否相同，相同才清除 `dirty`，否则立即再排一次保存。

### 7.3 冲突处理

检测到 `MAP_VERSION_CONFLICT` 时弹出对话框，提供三个选项：

| 选项 | 行为 |
| --- | --- |
| **保留我的版本**（覆盖） | 拉取最新 `version` 后重试保存，覆盖服务端内容 |
| **放弃我的修改** | 拉取服务端最新文档替换本地 |
| **另存为副本** | 用当前内容创建一份新导图，保留服务端版本 |

同时提供「查看差异」入口（一期仅展示节点数差异，二期做树 diff）。

### 7.4 本地草稿

- 每 3 秒把 `document` 写入 `localStorage['wmind:draft:{uid}']`（含 `updatedAt`）。
- 保存成功后删除草稿。
- 打开导图时：若草稿的 `updatedAt` 晚于服务端 `updatedAt` 且内容不同，弹出「发现未保存的本地修改，是否恢复？」。
- 草稿超过 7 天自动清理；localStorage 写入失败（配额）时静默降级并只在控制台告警。

### 7.5 离开保护

- `beforeunload`：`dirty` 时提示。
- 路由切换：拦截并提示。
- 保存失败且用户强行离开时，草稿保证内容不丢。

## 8. 性能策略

| 手段 | 说明 |
| --- | --- |
| 布局记忆化 | `useMemo` 依赖 `[document, theme, activeSheetId]`；主题变更不重算布局（布局只依赖结构与尺寸） |
| 组件记忆化 | `TopicNode` / `EdgePath` 用 `React.memo` + 稳定引用；`boxes` 中未变化的节点保持同一对象引用（布局引擎负责复用） |
| 事件节流 | `pointermove` 用 `requestAnimationFrame` 节流；缩放时先应用 CSS transform，空闲后再重算布局 |
| 视口裁剪 | 节点数 > 2000 时只渲染可见区域 + 缓冲区 |
| 降级渲染 | 节点数 > 2000 时关闭阴影/渐变，线条简化为 2px 直线 |
| Web Worker | 节点数 > 1000 时布局在 Worker 中计算 |
| 代码分割 | 编辑器内核、导入导出、管理后台分别 `React.lazy` 动态导入 |
| 虚拟滚动 | 导图列表与管理后台表格使用虚拟滚动 |
| 字体加载 | WOFF2 + `font-display: swap`；测量前 `await document.fonts.ready` |

**性能预算**：编辑器首屏 JS（gzip）≤ 350KB；首屏到可交互 ≤ 1.5s（本地网络）。
