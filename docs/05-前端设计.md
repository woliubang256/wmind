## 2. 路由设计

| 路径 | 页面 | 权限 |
| --- | --- | --- |
| `/login` | 登录 | 游客 |
| `/register` | 注册（注册关闭时重定向到登录页并提示） | 游客 |
| `/s/:token` | **公开只读分享页** | 任何人（可能需密码） |
| `/` | 最近（导图卡片列表，首格为新建入口） | 登录 |
| `/maps/:uid` | 编辑器 | 登录 + 属主 |
| `/templates` | 模板库（内置 + 我的模板） | 登录 |
| `/shares` | 我的分享（管理自己创建的分享链接） | 登录 |
| `/trash` | 回收站 | 登录 |
| `/account` | 个人设置（资料、密码、登录设备、外观偏好） | 登录 |
| `/admin/users` | 用户管理 | 管理员 |
| `/admin/settings` | 站点设置 | 管理员 |
| `/admin/overview` | 数据概览 | 管理员 |
| `/admin/logs` | 操作日志 | 管理员 |
| `*` | 404 | — |

布局：`AuthLayout`（居中卡片）、`AppLayout`（**顶部导航 + 内容区**）、`PublicLayout`（分享页专用：无导航，仅顶部站点标识）。

**应用外壳是顶栏，不是侧栏。** 导航搬到顶栏（`h-14`：logo + 站点名 → 导航 → 用户名 / 汉堡 / 主题 / 退出），
因为左侧固定侧栏在每个页面都吃掉 224px，而它最该让位的正是编辑器。具体做法：

| 断点 | 表现 |
| --- | --- |
| `≥ xl` | 图标 + 文字 |
| `md` – `xl` | 只有图标（带 `title` 与 `aria-label`）。八条链接带文字在 768px 上必然折行，折行后顶栏变高、画布跟着跳一下 |
| `< md` | 收进汉堡按钮，点开是左侧抽屉 |

抽屉用原生 `<dialog>` + `showModal()`：焦点陷阱、Esc 关闭、`::backdrop` 都由浏览器负责。
原生 dialog 靠 `margin: auto` 居中，而 Tailwind preflight 已把 margin 清零，所以
`m-0 h-svh w-72` 直接落到左上角，天然就是一条侧栏。`location.pathname` 变化时自动收起。

**内容区按路径分两种版式**：`/maps/*` 满宽（编辑器自己管高度 `100svh - 3.5rem`），
其余页面居中 `max-w-7xl`。只把导航搬到顶栏、内容区还留着 `max-w-7xl`，等于只还了
一半空间——1280 的封顶照样卡在画布中间。

**编辑器不再隐藏外壳**：顶栏留着（退出、主题、切页面都在那儿），只是内容区满宽。
隐藏外壳的代价是用户失去「我在哪」的锚点，而误触导航导致丢失编辑状态这件事由
自动保存 + 离开保护解决，不该靠拆掉导航来回避。

**分享页是独立入口**：`/s/:token` 不要求登录，不加载应用外壳与用户态数据（不请求 `/auth/me`），首屏尽量轻。页面结构从 `index.html` 同一入口加载，但路由层单独懒加载 `ShareViewer` 组件，避免把编辑器内核之外的管理后台代码打进分享页的 chunk。

**复用渲染层，关闭编辑能力**：

| 能力 | 编辑器中 | 分享页 |
| --- | --- | --- |
| 布局 / 渲染 / 主题解析 | ✅ | ✅（完全复用 `layout` + `theme` + `render`） |
| 缩放 / 平移 / 缩放到适应 | ✅ | ✅ |
| 折叠 / 展开 | ✅ | ✅ |
| 多画布切换 | ✅ | ✅ |
| 大纲视图 | ✅ | ✅ |
| 文本编辑 / 拖拽 / 快捷键建节点 | ✅ | ❌（不注册交互层，键盘映射表整体禁用） |
| 右侧样式面板 | ✅ | ❌ |
| 备注查看 | ✅ | 受 `showNotes` 控制 |
| 导出 | ✅ | 受 `allowDownload` 与站点 `feature.export_enabled` 双重控制 |
| 分享按钮 | ✅ | ❌ |

**实现方式**：把编辑器内核抽出一个 `MindMapViewer` 组件，接收 `document + 只读配置`，内部只挂载「视图变换 + 折叠」两个交互插件。编辑器的 `MindMapCanvas` 也基于同一个 `MindMapViewer`，通过传入不同的交互插件集合来区分。这样分享页与编辑器共用同一套布局与渲染代码，不会出现「分享页显示不一致」的问题。

**密码保护流程**：

```
加载 /s/:token
  → sessionStorage 中是否有该 token 的 accessToken？
      ├─ 有 → 带 X-Share-Access 头请求
      └─ 无 → 直接请求
  → 响应 401 SHARE_PASSWORD_REQUIRED
      → 展示密码输入页（居中卡片 + 站点 Logo）
      → POST /public/shares/{token}/verify
          ├─ 成功 → accessToken 存 sessionStorage → 重新请求
          └─ 失败 → 显示错误，超过 3 次提示「请稍后再试」
```

**失效状态页**：`SHARE_NOT_FOUND` 与 `SHARE_DISABLED` 分别展示不同的友好页面（「链接已失效或不存在」/「站点已关闭分享功能」），并提供「返回首页」按钮。

**SEO 与元信息**：页面 `<head>` 注入 `<meta name="robots" content="noindex, nofollow">` 与 `<title>{导图标题} - {站点名}</title>`；`og:title` / `og:description` 供社交平台预览（**不**生成 `og:image`，避免导出能力绕过）。

### 3.4 登录页的「忘记密码」引导（二期补充邮件页面）

一期不提供自助找回，因此**没有** `/forgot-password` / `/reset-password` / `/verify-email` 三个路由。替代方案是登录页在密码输入框下方展示一行静态引导文案：

> 忘记密码？请联系站点管理员为你重置。

该文案在 `/site/config` 返回的站点信息可用时一并渲染，无需额外接口；管理员重置后由管理员线下告知新密码。这条引导是本期账号找回流程的**唯一用户可见入口**，不可省略——否则用户会卡在登录页找不到出路。

> **二期实现**（归档设计，见 [09-技术决策记录](./09-技术决策记录.md) ADR-012）：新增 `/forgot-password`（邮箱输入 + 防枚举统一文案）、`/reset-password`（读取 `?token=`，实时校验强度）、`/verify-email`（进入即自动提交，失败给「重新发送」入口）。三者均属 `AuthLayout`，不要求登录。届时登录页的静态文案替换为指向 `/forgot-password` 的链接。

**与初版草图的差异（多画布 / 大纲 / ZEN / 顶栏导航落地后）**：

| 草图 | 实际 | 原因 |
| --- | --- | --- |
| 底部 `[Map 1 ▾]` 下拉切画布 | 一行画布标签（`role="tablist"`）+ 「＋」 | 下拉看不见「还有哪几张图」，而多画布的价值恰恰在于一眼看到全部；标签还顺手承载了改名（双击）与排序（拖动 / `Alt+←→`） |
| 底部右侧 `[大纲]` | 顶栏的列表图标（`aria-pressed`） | 大纲是**整块换掉画布**的视图，不是浮层；放在页脚会让人以为它只是个小开关。切回画布时画布是重新挂载的，`ResizeObserver` 与适配视野都跟着重跑 |
| 顶栏 `[ZEN]` 与 `[格式]` 并列 | 独立按钮，且只在大纲关闭时出现 | ZEN 的全部意思是「只留画布」，和大纲视图互斥；大纲下按 ZEN 会得到一块空屏 |
| 大纲可停靠左侧 | 未实现 | 停靠要处理拖拽分隔条、宽度持久化、窄屏折叠三件事，收益是「边看边改」；一期先给全屏切换，够用且没有布局回归 |
| 画布名 = 中心主题名 | 两个字段，互不联动 | 导图标题已经等于第一张画布的中心主题（`changeTitleCommand`）；如果每张画布再联动，改画布名就会悄悄改掉图里的字，而「重命名画布」听起来不像内容编辑 |
| 右侧面板 `样式 │ 演说 │ 画布` | `样式 │ 配色 │ 标记 │ 结构 │ 演说` | 新增的「结构」页管概要 / 边界 / 联系的新建、改名、删除——这三件事都是**反复**发生的，只给工具栏按钮的话用户建完就再也找不到入口 |
| 画布区套在居中内容列里 | `/maps/*` 走满宽分支，高度 `100svh - 顶栏` | 画布越宽越有用，而列表页太宽反而不好读；`max-w-7xl` 的封顶会卡在画布中间，等于把「导航搬到顶栏」省下的空间又还回去一半 |

**概要 / 边界 / 联系（三种「画在节点之间」的附属结构）**：

数据一直存在（`Sheet.summaries` / `boundaries` / `relationships`，XMind 导入会写进来），
缺的是渲染与编辑入口。实现上分成三层，几何单独一层：

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 几何 | `editor/layout/annotations.ts` | 输入「算好的主题布局 + 文档」，输出 `AnnotationLayout`（三个数组 + 一个总包围盒）。不测量、不算并集以外的东西 |
| 命令 | `editor/commands/annotation.ts` | 新建 / 改名 / 删除，**同时写 `sheet` 级与 `topic` 级** |
| 渲染 | `editor/viewer/decorations.tsx` | 只把坐标画出来；导出与缩略图复用同一份 `AnnotationLayout` |

三者共用「区间并集」这一个原语：边界是并集外扩 16 的虚线框；概要是并集右缘的括号
（开口朝左、圆角 `min(12, 高度/2)`）加一个挂在 `右缘 + 26` 的节点；联系是两端中心
之间的二次贝塞尔，控制点从弦中点沿法线外推 `min(60, 弦长/4)`——**取中点会退化成
直线**，横向相邻的两个节点之间那条直线正好穿过中间那个节点。

图层顺序定死：边界 → 连线 → 联系 → 概要 → 主题。边界在连线下面（它是背景区域），
联系在连线上面（否则被密集的分支线盖住），概要在主题之前（括号的横臂会伸进节点
之间）。概要、边界以及联系路径、箭头、标题均计入包围盒。编辑插件的控制柄绘制在主题之上，只出现在可编辑的选中状态。

**为什么 XMind 的双份存储要读写对称**：`topic.summaries` 与 `sheet.summaries` 都可能
有内容，导入的文件两种写法都见过。读取侧 `collectSummaries` / `collectBoundaries`
合并后按 id 去重；写入侧新建 / 改名 / 删除**同时写两级**。只写 `sheet` 级的话，
`topic` 级的旧副本会在合并时赢，表现为「改完名字，刷新又变回去」。

### 3.8 管理后台

`/admin/*` 复用 `AppLayout`（管理员登录时顶栏导航多出「管理概览 / 用户管理 / 网站设置」三项），不另建 `AdminLayout`——两套外壳会让「顶栏、导航、登出」各维护一遍。三个页面按路由懒加载，普通用户不下载这部分代码。

- **用户管理**：原生 `<table>` + 手写分页（`keepPreviousData` 保证翻页不塌），含搜索框、角色/状态筛选、行操作（编辑、重置密码、删除）。行操作对当前登录管理员自己禁用（后端另有 409 兜底）。
- **站点设置**：分组表单，字段描述在 `features/admin/settings-schema.ts`（键与 `internal/settings/schema.go` 一一对应）。底部 `sticky` 保存栏显示未保存项数；提交时用 `diffSettings` 只发送改动过的键（后端是部分更新语义）。数值项先按 schema 的 `min`/`max` 本地校验，越界不跑网络。分组：
  1. 站点信息（名称、Logo、描述、ICP、外部访问地址）
  2. 注册与登录（开放注册、默认角色、密码策略、登录锁定）
  3. 资源限制（导图数量上限、上传大小上限）
  4. 功能开关（导入、导出、用户模板）
  5. 分享设置（是否允许分享、默认有效期、默认是否允许导出、是否强制密码、单图链接上限）
- **重置密码的交互细节**（用户管理页行操作）：
  - 点击后弹出对话框，提供「随机生成强密码」与「手动指定」两种方式；手动指定时按站点设置里的最小长度校验。
  - 提交成功后用一个**只读且不可关闭的对话框**展示新密码，附「复制」按钮与醒目提示「此密码仅显示一次，请立即告知用户」；用户点「我已保存」才关闭。
  - 对当前登录的管理员自己，该操作禁用并提示「不能重置自己的密码」。
- **危险操作**：删除用户走确认对话框，并提供「一并删除其导图 / 保留导图（转为无主）」单选。

> **已知偏差**：删除用户目前没有「输入用户名」二次确认（`ConfirmDialog` 组件尚未抽出）。理由：M1 没有导图数据，误删的后果仅限于账号本身；等 M2 引入导图与回收站后再统一做输入确认。
>

> **二期站点设置会新增分组**：`邮件服务（SMTP）`——启用开关、主机、端口、加密方式、账号、密码、发件人、跳过 TLS 校验；含「保存并测试 / 仅测试」双按钮（仅测试时把当前表单值作为 `config` 传给 `POST /admin/mail/test`，无需先保存），失败时按 `details.stage` 给出针对性提示。一期不渲染该分组，也不引入对应表单 schema。

### 4.3 文本测量（`measure`）

```ts
const ctx = document.createElement('canvas').getContext('2d')!;

export function measureText(text: string, font: FontSpec, maxWidth: number): { width: number; height: number; lines: string[] }
```

- 缓存键：`${text}|${font.family}|${font.size}|${font.weight}|${maxWidth}`，LRU 容量 5000。
- 换行规则：按空格与 CJK 字符边界折行；`\n` 强制换行。
- 主题宽度为 `autoWidth: true` 时，宽度 = `max(最小宽度 60, min(内容宽度, 320))` + 左右内边距。

**带图片的节点**：`measureTopic` 在文本之外再算一块图片区域（`IMAGE_METRICS`：宽 ≤ 320、高 ≤ 240、最小 16），节点高度 = 文本高 + 间距 6 + 图片高 + 上下内边距；宽度取「文本宽」与「图片宽」的较大者。图片**只等比缩小，不放大**——小图放大只会糊，且会让布局尺寸取决于原图像素而非用户拖出的尺寸。

`TopicSize.image` 只给尺寸、不给坐标：坐标依赖盒子最终位置，而测量发生在盒子摆好之前。渲染层用「盒子 + 尺寸」自己算位置，两边不会因为各算一遍而错位。

`image.width/height` 可能缺失或为 0（XMind 允许只写一边）。缺一边时按 4:3 补另一边，两边都缺时用 120×80；`Number.isFinite` 之外还要挡住负数与 `Infinity`——这些值来自用户文件，不是自己写的。

### 4.4 布局引擎

**统一输入输出**：

```ts
interface LayoutInput {
  sheet: Sheet;
  theme: Theme;
  measure: (t: Topic) => { width: number; height: number };
  options: { compact: boolean; alignSiblings: boolean; ... };
}

interface LayoutResult {
  boxes: Map<string, NodeBox>;   // topicId → 盒子
  edges: EdgePath[];             // 父子连线
  bounds: Rect;                  // 内容包围盒
}

interface NodeBox {
  id: string;
  x: number; y: number;          // 左上角坐标（画布坐标系）
  width: number; height: number;
  depth: number;
  branchIndex: number;           // 一级分支序号，决定调色板取色
  side: 'left' | 'right' | 'none';
  collapsed: boolean;
  hiddenChildren: number;        // 折叠时被隐藏的后代数
}
```

**各结构算法**：

| structure | 算法 |
| --- | --- |
| `mindmap` | 把根的一级子节点按「交替 + 平衡」分成左右两组（按子树高度贪心分配以平衡两侧）；每组用 `d3.tree` 的 `nodeSize` 模式生成横向树；两侧垂直居中于根 |
| `logic-right` / `logic-left` | 单向横向树，`d3.tree` + 旋转；同层节点垂直堆叠 |
| `org-chart` | 标准自上而下树，`d3.tree`；父节点水平居中于子节点跨度 |
| `tree-right` | 横向树，与 `logic-right` 布局相同，仅连线样式改为折线 |
| `timeline` | 主轴水平居中；一级子节点沿主轴等距分布并上下交替；二级及以下挂在一级节点下方（上方节点则向上展开） |
| `fishbone` | 主骨为水平线；一级子节点作为支骨以固定夹角（±45°）斜向附着，交替上下；二级挂在支骨末端 |
| `brace` | 根在左，一级子节点纵向排列，父与子之间绘制花括号路径；二级继续右移 |
| `tree-table` | 网格布局：列 = 深度，行 = 节点顺序；每列等宽（取该列最宽节点）；表头行为一级子节点 |

**间距常量**（可被主题的 `layout.compact` 覆盖）：

| 常量 | 默认 | 紧凑 |
| --- | --- | --- |
| 同级垂直间距 | 24 | 12 |
| 父子水平间距 | 48 | 28 |
| 画布内边距 | 80 | 40 |

**性能**：节点数 > 1000 时把布局计算搬进 Web Worker（`layout.worker.ts`），主线程仅接收 `LayoutResult`；`LayoutResult` 中的 `Map` 在 postMessage 时转为 `Array<[string, NodeBox]>` 传输。

### 4.5 渲染层

SVG 结构：

```html
<svg class="wmind-canvas">
  <defs><!-- 渐变、阴影、箭头 marker、图案 --></defs>
  <g class="viewport" transform="translate(tx,ty) scale(k)">
    <g class="layer-boundaries">…</g>
    <g class="layer-edges">…</g>
    <g class="layer-summaries">…</g>
    <g class="layer-relationships">…</g>
    <g class="layer-topics">…</g>
    <g class="layer-overlay"><!-- 选区框、拖拽指示线 --></g>
  </g>
</svg>
```

- **分层渲染**：按 z-order 拆成独立 `<g>`，避免重排时整树 diff。
- **`TopicNode` 组件**：`React.memo` + 自定义比较器（仅比较 `box` 引用、`style` 引用、`selected`、`editing`）。
- **样式内联**：颜色、字体、线宽一律通过 `style` 属性内联输出到元素上，**不用 CSS class** —— 这样 SVG 序列化导出时样式自动携带，无需额外注入 `<style>`。
- **形状渲染**：`rounded-rect` / `rect` / `capsule` / `ellipse` 等用 `<rect rx>` / `<ellipse>` / `<path>` 表达；`underline` 只画底部线条；`none` 不画容器。
- **文本渲染**：`<text>` + `<tspan>` 逐行输出；`text-anchor` 由 `textAlign` 决定。
- **图片渲染**：文本块与图片作为**一个整体**在盒子里竖直居中（`contentHeight = 文本高 + 间距 + 图片高`），不能沿用「文本中心对齐盒子中心」——那会把文字压到图片上。图片用 `<image href>` 输出，水平居中，`preserveAspectRatio` 保持默认的等比。导出 SVG 时 `<image>` 的 `href` 必须是服务端绝对 URL，`xap:resources/...` 这类包内引用在画布外没有任何意义。
- **连线**：`curve` 用三次贝塞尔（控制点取父子中点），`straight` 用 `<line>`，`elbow` 用 `<path>` 折线，`none` 不渲染。
- **编辑态**：双击主题后，在其位置叠加一个绝对定位的 `contenteditable` div（或 `<foreignObject>` 内嵌 textarea），编辑结束回写模型。选择 `div` 叠加方案以规避 Safari 对 `foreignObject` 的兼容问题。

**虚拟化**：节点数 > 2000 时，只渲染视口内 + 200px 缓冲区内的节点；`bounds` 之外的主题不生成 DOM。

**大纲视图**是另一张键位表（`features/editor/outline-view.tsx`），因为它编辑的是「行」而不是「几何」：

| 快捷键 | 行为 |
| --- | --- |
| `↑` / `↓` / `Home` / `End` | 在行间移动（选区跟着走，画布同步高亮） |
| `Enter` / `F2` | 改这一行的文字 |
| `Delete` / `Backspace` | 删除这一行（根节点不可删） |
| `Ctrl/Cmd + ]` / `Ctrl/Cmd + [` | 降一级（挂到上一个兄弟下）/ 升一级 |
| `Ctrl/Cmd + .` | 折叠 / 展开这一行 |
| `Ctrl/Cmd + Enter` | 在这一行下新建子主题 |
| `Tab` / `Shift + Tab` | **不拦**：离开这个控件 |

大纲**不用 `Tab` 缩进**（XMind 是这么做的）：`Tab` 是浏览器里唯一的「离开这个控件」的键，被列表吃掉之后键盘用户就出不去了。`Ctrl/Cmd + ]` 在浏览器里没有默认行为，也不会和画布的 `Tab`（新建子主题）打架。

同理，行内那两个按钮（折叠、加子主题）都设了 `tabIndex={-1}`：整棵树只保留「活动行」一个 Tab 停靠点。每行挂两个可 Tab 的按钮，意味着 50 行的导图要按 100 次 `Tab` 才能离开——那和键盘陷阱只差一步。它们的动作改由 `Ctrl/Cmd + .` 与 `Ctrl/Cmd + Enter` 承担，读屏的浏览模式照样能找到按钮。

`Alt` 组合在画布键位表里一律不拦（`Alt+←` 是系统级「后退」），所以画布标签的 `Alt+←/→` 由标签自己的 `keydown` 处理并 `preventDefault`。

`Ctrl/Cmd + F`（查找主题）**尚未接线**：查找需要先有「搜索结果列表」这个可键盘操作的落点，否则找到第 7 个结果之后无法继续。已从 M3 挪到 M6 打磨阶段。

实现：单个 `useHotkeys` hook 挂在**编辑器根节点**（画布 + 画布面板，不含侧栏与页头之外的区域），按 `mod+key` 查表派发命令；编辑态（`editingTopicId != null`）时整张表关掉。

事件到达后做两级过滤：

1. 焦点在**文本输入框**里（`input` / `textarea` / `select` / `contenteditable`）→ 一个键都不拦，连 `⌘Z` 也留给浏览器做文字撤销；
2. 焦点在**按钮、链接、选项卡、复选开关**上 → 只拦**不带修饰键**的键（`Tab` 要走焦点、方向键要在下拉里选值），`⌘Z` / `⌘S` 照常作用于导图。

第二级是画布面板出现之后补的：面板里全是按钮和下拉，焦点停在色块上按 `⌘Z` 却什么也不发生，用户会以为撤销坏了；反过来，裸 `Tab` 在面板里必须走焦点切换，不能被「新建子主题」吃掉。

两处按键冲突值得记下来：

- **折叠不能用空格**。`Space + 拖拽` 已经是平移画布（pan-zoom 插件在 `window` 上监听空格），一个键干两件事，用户按住空格准备平移时节点会莫名其妙收起来。改用 `Ctrl/Cmd + .`——浏览器里没有默认行为。
- **变色是「循环调色板」而不是取色器**。原生 `<input type="color">` 的取色面板只能点，而「纯键盘完成加粗变色」是 M2 的验收标准。循环只写 `topic.style.fill` 一个字段，其余仍继承主题，换配色方案时这些节点不会卡在旧色上。

#### 4.6.3 拖拽

1. `pointerdown` 记录起始主题与指针位置（阈值 4px 才进入拖拽态，避免误触）。
2. `pointermove` 更新幽灵元素位置；每帧做一次「落点计算」：
   - 找到距离指针最近的节点（用 `boxes` 做粗筛 + 精确距离）。
   - 根据指针相对该节点的位置决定落点语义：落在节点**中心区域** → 成为其子节点；落在节点**上/下边缘 25% 区域** → 成为其同级（插到前/后）。
   - 校验合法性：目标不能是被拖拽节点的后代。
3. 绘制指示：目标节点高亮 + 插入位置竖线/横线。
4. `pointerup` 提交 `MoveTopicCommand`。
5. 拖到画布空白处 → `DetachTopicCommand`，变为自由主题。

#### 4.6.4 多选

`selection: Set<string>`。框选：在空白处按下并拖拽，绘制选框，`pointerup` 时用包围盒与 `boxes` 求交。多选后支持批量改样式、批量删除、批量移动。

### 4.7 命令与撤销栈

**命令定义**：

```ts
export interface EditorCommand {
  type: string;                       // 'topic.add' | 'topic.rename' | ...
  label: string;                      // 撤销提示文案，如「新建主题」
  apply(draft: WmindDocument, ctx: CommandContext): void;   // immer draft，原地修改
  coalesceWith?: (prev: EditorCommand) => boolean;          // 连续输入合并
}
```

**历史栈**：

```ts
interface HistoryEntry { label: string; doc: WmindDocument; selection: string[] }
history: { past: HistoryEntry[]; future: HistoryEntry[] }
```

- 每次命令执行：`past.push(当前快照)`，`future = []`。
- 依赖 immer 的**结构共享**，快照只复制变更路径，1000 节点导图单个快照增量通常 < 10KB。
- 栈深上限 200，超出丢弃最旧的。
- `coalesceWith`：连续 `topic.rename` 在 800ms 内且同一主题时合并为一条历史记录，避免逐字入栈。

**命令清单**（一期）：

| 分组 | 命令 |
| --- | --- |
| 主题 | `topic.add` `topic.remove` `topic.rename` `topic.move` `topic.detach` `topic.collapse` `topic.paste` |
| 样式 | `style.update`（批量）`style.reset` |
| 结构 | `structure.change`（sheet 级 / topic 级） |
| 主题色 | `theme.apply` `palette.change` `background.change` `rainbow.toggle` |
| 附属 | `relationship.add` `relationship.remove` `boundary.add` `boundary.remove` `summary.add` `summary.remove` `marker.toggle` `label.update` `note.update` `href.update` `image.set` |
| 画布 | `sheet.add` `sheet.remove` `sheet.rename` `sheet.reorder` |
| 文档 | `title.change` `document.replace`（导入 / 版本回滚） |

> 视图变换（缩放、平移）与面板开合**不进**撤销栈。

## 5. 主题系统（前端）

### 5.1 样式解析链

```ts
export function resolveStyle(
  topic: Topic,
  ctx: { depth: number; branchIndex: number; isRoot: boolean; isFloating: boolean; isSummary: boolean },
  theme: Theme
): ComputedStyle
```

解析顺序（后覆盖前）：

```
内置兜底默认值
  → theme.global（字体、字号、线宽、背景）
  → 角色样式 theme.centralTopic / mainTopic / subTopic / floatingTopic / summaryTopic
  → 调色板分配：palette.colors[ctx.branchIndex % palette.colors.length]
                 （仅当该字段未被显式指定时）
  → topic.style 的显式非 null 字段
```

**关键点**：调色板颜色是**计算得出**而非写入文档。用户手动改色时才把颜色固化进 `topic.style`。这样切换配色方案能整体生效。

`rainbowBranch` 为 true 时，`branchIndex` 对应的一级分支使用 `theme.rainbowColors` 循环取色，且该分支下所有后代继承同一色系。

### 5.2 计算样式类型

```ts
export interface ComputedStyle {
  shape: ShapeClass;
  fill: string | null;
  fillPattern: 'solid' | 'none' | 'gradient';
  borderColor: string;
  borderWidth: number;
  borderStyle: 'solid' | 'dash' | 'dot' | 'none';
  fontFamily: FontFamily;        // 标识符，非字体名；见 5.3
  fontSize: number;
  fontWeight: number;
  fontStyle: 'normal' | 'italic';
  textDecoration: 'none' | 'underline' | 'line-through';
  textColor: string;
  textAlign: 'left' | 'center' | 'right';
  width: number;
  autoWidth: boolean;
  lineStyle: 'straight' | 'curve' | 'elbow' | 'none';
  lineEnd: 'none' | 'arrow' | 'dot';
  lineWidth: number;
  lineColor: string;
  rainbowBranch: boolean;
}
```

`resolveStyle` 必须是纯函数并带记忆化（键 = `topic.id + JSON.stringify(topic.style) + theme.id + branchIndex`），避免每次重渲染重复计算。

### 5.3 字体

**默认字体是思源黑体**（Noto Sans SC，SIL OFL 1.1）——`NeverMind` 是 XMind 自有字体，不可分发。完整决策与被否方案见 [09-技术决策记录](./09-技术决策记录.md) ADR-016。

#### 5.3.1 字体注册表

文档里只存标识符，渲染时才解析为 CSS 字体栈。注册表是**唯一**的解析入口：

```ts
export type FontFamily = 'sans' | 'serif' | 'mono' | 'system';

export const FONT_REGISTRY: Record<
  FontFamily,
  { label: string; stack: string; cssPath: string | null; weights: number[] }
> = {
  sans: {
    label: '思源黑体',
    stack: "'Noto Sans SC', 'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', system-ui, sans-serif",
    cssPath: '/fonts/sans.css',
    weights: [300, 400, 600, 700, 800],
  },
  serif: {
    label: '思源宋体',
    stack: "'Noto Serif SC', 'Songti SC', SimSun, Georgia, serif",
    cssPath: '/fonts/serif.css',
    weights: [400, 700],
  },
  mono: {
    label: '等宽',
    stack: "'JetBrains Mono', 'SF Mono', Menlo, Consolas, 'Liberation Mono', monospace",
    cssPath: '/fonts/mono.css',
    weights: [400, 700],
  },
  // 不随包分发：cssPath 为 null、weights 为空，ensureFonts 直接放行。
  system: {
    label: '跟随系统',
    stack: "system-ui, -apple-system, 'Segoe UI', Roboto, 'Helvetica Neue', sans-serif",
    cssPath: null,
    weights: [],
  },
};

export function fontStack(f: FontFamily | null | undefined): string {
  return FONT_REGISTRY[f ?? 'sans'].stack;
}
```

- `cssPath` / `weights` 必须与 `frontend/public/fonts/manifest.json` 一致，由 `npm run check:fonts` 逐项核对——注册表说「sans 有 600 字重」而分片里没有，浏览器会合成假粗体。

- `null` / 缺失 → 按 `sans` 处理（与文档格式的「继承」语义一致，继承在 `resolveStyle` 阶段已经解完，到这里不该再是 `null`）。
- **禁止把标识符直接当 CSS `font-family` 用**；所有取值都必须过 `fontStack()`。未知值（如来自旧版本或损坏文档）回退 `sans` 并上报一次埋点，不抛错。

#### 5.3.2 分发与加载：`unicode-range` 分片

随应用分发 **三个字体族**的分片（`sans` 思源黑体 300/400/600/700/800、`serif` 思源宋体 400/700、`mono` JetBrains Mono 400/700），并**按 `unicode-range` 切片**。实现细节与决策见 [09-技术决策记录](./09-技术决策记录.md) ADR-018。

- **不做硬子集截断**。放弃「只打包 GB2312 一级字库 3755 字」的设想——导图内容完全任意（人名、术语、生僻字），截断会让常用但不在该表内的汉字显示成方框。改为全量 CJK 覆盖 + 分片，浏览器只下载**当前文档实际用到**的分片。
- **分片取自 Google Fonts 的可变字体**（`scripts/fetch-fonts.mjs` 生成、产物入库），不是自己 `pyftsubset` 切静态实例：同一组分片文件跨字重共享，三族 9 个字重面合计 **208 个分片 / 10.10 MB**。产物由本站源提供，**不依赖任何外部 CDN**（私有化部署必须离线可用）。
- **每族一份 CSS**（`/fonts/{sans,serif,mono}.css`），由 `ensureFonts()` 首屏按需注入 `<link>`，**不放进 `index.html`**。原因不是省请求：sans 的 CSS 就有 514 KB（gzip 156 KB），阻塞渲染会让骨架屏根本画不出来。一张导图通常只用一族，也没必要让所有人替另外两族付带宽。
- 体积实测：单页传输约 **315 KB 分片**（9 个汉字的默认文档、五个字重，命中 13 个分片）+ 一族 CSS。字体不计入「首屏 JS ≤ 350KB」的预算（字体是独立资源，且按分片按需取）。
- **CI 校验分片产物完整**（`npm run check:fonts`，六项：文件与字节数、CSS 与 manifest 逐段一致、覆盖率下限、重叠报告、`font-display: block`、前端注册表与 manifest 一致）。缺分片不会报错，只会静默显示方框，属于最难排查的一类线上问题。

#### 5.3.3 加载顺序：字体 → 测量 → 布局

**这个顺序不可颠倒。** 布局引擎用 Canvas 测量文本宽度来决定节点尺寸，如果先用回退字体测量、等 webfont 到达后再重排，整张导图的节点尺寸都会变、画面明显跳一下。因此：

1. 首屏**显式等待**所需分片加载完成，等待期间显示骨架屏。等待分三步，顺序不能换：**注入该族的 `@font-face` 样式表 → 等它 `load` → 才 `document.fonts.load(font, text)`**。直接 `await document.fonts.load()` 会拿到「假就绪」：对一个还没注册任何 face 的字体族，它立刻 resolve 并返回空数组，代码接着就用回退字体量了宽度。
2. **不使用 `font-display: swap`** 的可见回退（用 `block`）——宁可等一下，也不要跳一下。
3. 测量结果按「字体 + 字号 + 字重 + 文本」做记忆化缓存；字体就绪后才进布局，所以首帧不会写入回退字体的宽度。
4. 用户中途切换字体族时，需清空测量缓存并整体重新布局（已实现：`clearMeasureCache()` + 布局依赖 `generation`）。「用到哪些族」包含节点级 `style.fontFamily`——否则节点级覆盖会因为样式表没被注入而静默退回系统字体。

> **测量缓存的键必须包含字体标识符**。只按文本缓存会在切换字体后命中过期结果，导致节点宽度与实际渲染不符——这是上一版设计里埋着的隐患。

#### 5.3.4 导出时的字体

- SVG：内嵌 WOFF2 分片，或按需「文字转路径」；见 [06-导入导出与主题系统](./06-导入导出与主题系统.md) §4。
- PNG / JPEG：由浏览器栅格化，导出前必须 `await document.fonts.ready`。
- PDF：默认「文字转路径」（`opentype.js`），关闭时用 jsPDF 子集内嵌 TTF。
- 未被字体覆盖的字符（生僻字、emoji）走回退栈，可能由系统字体渲染；导出时若命中回退字体，在导出结果说明里提示，避免用户误以为导出有 bug。

### 5.4 画布面板 UI

编辑器右侧的面板，三个 Tab：**样式 / 画布 / 演说**（演说为一期占位）。只读预览时整块不挂载——验收标准要求只读页面上不存在可编辑元素，藏起来不算。

**样式 Tab**（改选中节点，写 `topic.style`）：形状、结构、填充、边框颜色/宽度/样式、字体族、字号、字重、B/I/U/S、文字颜色、对齐、分支线样式/端点/线宽/线条颜色、自适应宽度与固定宽度。

**画布 Tab**（改整份主题，写 `doc.theme`）：配色方案（缤纷 5 套 / 经典 5 套，每张卡片显示 6 段色带）、背景颜色、全局字体、分支线粗细、彩虹分支开关与序列取色、三个布局开关（自动平衡 / 紧凑型 / 同级主题对齐）。

与截图 4 的差异：

| 截图 4 | 本实现 | 原因 |
| --- | --- | --- |
| 配色缩略图是渐变 | 6 段纯色带 | 配色本身就是 6 个离散色，渐变缩略图会让人以为是渐变填充 |
| 「分支线粗细」只有细/中/粗 | 同左（1/2/3 px） | — |
| 取色器为自绘色板弹层 | 预设色块 + 原生 `<input type="color">` | 自绘弹层要补焦点陷阱、方向键、Esc 关闭；原生控件在键盘与读屏上本来就是对的 |
| 无 | 「继承主题」「无填充」两个显式按钮 | 颜色字段有三种状态（继承 / 显式值 / 无），界面上必须能表达，否则用户改完颜色没法退回跟随主题 |

**回显用解析后的样式**（`resolveStyle` 的结果）而不是 `topic.style`：一级分支的填充色是渲染期按 `branchIndex` 算出来的，`topic.style.fill` 通常是 `undefined`，拿它当显示值会出现「面板写着继承、画布上明明是红色」。

面板里的控件分两类。**外观自绘、语义走 ARIA**：下拉是 `components/ui/select.tsx` 的 `role="combobox"` + `role="listbox"`，复选是 `role="checkbox"`，互斥按钮组是 `aria-pressed`——原生控件的外观改不动（弹层由操作系统绘制，深色主题下会在面板上盖一块系统色的方角面板），所以画法自己来、键盘与读屏语义按 WAI-ARIA 补全（方向键、Home/End、首字母跳转、`aria-activedescendant`）。**仍然原生的只有 `<input type="color">`**：自己造 HSV 取色盘要处理色域、触屏拖拽与无障碍，代价远大于收益，旁边永远并排放着预设色块。`Field` 用 `role="group"` + `aria-labelledby` 关联标签，色块的 `aria-label` 直接写色值——「浅蓝」「深红」在 60 个色值里根本区分不开。Tab 列表实现了方向键切换，只标 ARIA 不实现方向键是个常见的半成品。

## 6. 状态管理

### 6.1 Zustand Store 划分

| Store | 内容 | 是否进撤销栈 |
| --- | --- | --- |
| `useDocStore` | `document`、`dirty`、`version` | ✅（通过 history 管理） |
| `useEditorStore` | `selection`、`editingTopicId`、`viewport`、`activeSheetId`、`panelState`、`mode`（普通/ZEN/大纲） | ❌ |
| `useHistoryStore` | `past`、`future` | — |
| `useSaveStore` | `status`、`lastSavedAt`、`error`、`conflict` | — |

**订阅粒度**：组件使用选择器订阅最小切片，例如：

```ts
const selected = useEditorStore((s) => s.selection);
const boxes = useLayoutStore((s) => s.boxes);   // 由 layout 计算结果派生
```

**布局结果不入 doc store**：布局是派生的，通过 `useMemo` 从 `document + theme + measure` 计算，避免布局数据被误写入撤销栈。

### 6.2 服务端状态（TanStack Query）

| Query Key | 接口 | 失效时机 |
| --- | --- | --- |
| `['maps', filters]` | `GET /maps` | 创建/删除/重命名导图后 |
| `['map', uid]` | `GET /maps/{uid}` | 保存成功后 `setQueryData` 局部更新，不整体失效 |
| `['templates']` | `GET /templates` | 模板增删后 |
| `['themes']` | `GET /themes` | 主题增删后 |
| `['site-config']` | `GET /site/config` | `staleTime: Infinity`，登录态变化时手动失效 |
| `['admin','users', filters]` | `GET /admin/users` | 用户增删改后 |
| `['admin','settings']` | `GET /admin/settings` | 保存设置后 |
| `['shares', {mapUid}]` | `GET /maps/{uid}/shares` | 创建/撤销/修改分享后 |
| `['shares', 'mine', filters]` | `GET /shares` | 同上 |
| `['public-share', token]` | `GET /public/shares/{token}` | `retry: false`（失效不应重试），`staleTime: Infinity`（分享内容在单次会话内不变） |

**分享页的访问令牌不进入 TanStack Query 缓存键**：`X-Share-Access` 令牌存在 `sessionStorage['wmind:share-access:{token}']`，由 API 客户端在请求该 token 的公开接口时自动附带。密码验证成功后调 `queryClient.invalidateQueries(['public-share', token])` 重新拉取。

全局配置：`retry: 1`、`refetchOnWindowFocus: false`（避免编辑器误刷新）。

## 7. 自动保存与冲突处理

### 7.1 状态机

```
        ┌──────── 编辑 ────────┐
        ▼                      │
     idle ──(dirty)──▶ dirty ───┘
                        │ 防抖 800ms / 最长 5s
                        ▼
                     saving ──成功──▶ saved ──(编辑)──▶ dirty
                        │
                        ├──网络错误──▶ error ──(重试 3 次，指数退避)──▶ saving
                        └──409──────▶ conflict
```

### 7.2 保存实现

```ts
const save = useDebouncedCallback(async () => {
  if (!docStore.dirty) return;
  const snapshot = docStore.document;
  const version = docStore.version;
  try {
    const res = await api.saveMap(uid, { version, title: snapshot.title, document: snapshot });
    docStore.markSaved(res.version);        // 仅当期间无新编辑时才置为干净
  } catch (e) {
    if (e.code === 'MAP_VERSION_CONFLICT') { saveStore.setConflict(e.details.currentVersion); }
    else { saveStore.setError(e); }
  }
}, 800, { maxWait: 5000 });
```

**「仅当期间无新编辑时才置为干净」**：保存请求发出后用户可能继续编辑，此时 `document` 引用已变。比较发起时的 `snapshot` 引用与当前引用是否相同，相同才清除 `dirty`，否则立即再排一次保存。

### 7.3 冲突处理

检测到 `MAP_VERSION_CONFLICT` 时弹出对话框，提供三个选项：

| 选项 | 行为 |
| --- | --- |
| **保留我的版本**（覆盖） | 拉取最新 `version` 后重试保存，覆盖服务端内容 |
| **放弃我的修改** | 拉取服务端最新文档替换本地 |
| **另存为副本** | 用当前内容创建一份新导图，保留服务端版本 |

同时提供「查看差异」入口（一期仅展示节点数差异，二期做树 diff）。

### 7.4 本地草稿

- 每 3 秒把 `document` 写入 `localStorage['wmind:draft:{uid}']`（含 `updatedAt`）。
- 保存成功后删除草稿。
- 打开导图时：若草稿的 `updatedAt` 晚于服务端 `updatedAt` 且内容不同，弹出「发现未保存的本地修改，是否恢复？」。
- 草稿超过 7 天自动清理；localStorage 写入失败（配额）时静默降级并只在控制台告警。

### 7.5 离开保护

- `beforeunload`：`dirty` 时提示。
- 路由切换：拦截并提示。
- 保存失败且用户强行离开时，草稿保证内容不丢。

## 8. 性能策略

| 手段 | 说明 |
| --- | --- |
| 布局记忆化 | `useMemo` 依赖 `[document, theme, activeSheetId]`；主题变更不重算布局（布局只依赖结构与尺寸） |
| 组件记忆化 | `TopicNode` / `EdgePath` 用 `React.memo` + 稳定引用；`boxes` 中未变化的节点保持同一对象引用（布局引擎负责复用） |
| 事件节流 | `pointermove` 用 `requestAnimationFrame` 节流；缩放时先应用 CSS transform，空闲后再重算布局 |
| 视口裁剪 | 节点数 > 400 时只渲染视口附近（`editor/viewer/cull.ts`）。矩形按「半屏 + 240 世界单位」外扩，选中的与被编辑的节点**无条件保留**（否则 `aria-activedescendant` 会指向不存在的 id）。实测 2001 节点：渲染数 2001 → 137，按方向键从 22.6ms 降到 16.5ms（单帧，即额外开销归零） |
| 面板降级 | 右侧面板的**显示**用 `useDeferredValue` 降一档优先级，画布的选中框先落地；动作仍走即时选区，避免「选中 A 后立刻点色块却作用到 B」 |
| 降级渲染 | 节点数 > 2000 时关闭阴影/渐变，线条简化为 2px 直线（**未实现**：当前主题本身就不画阴影，收益不明） |
| Web Worker | 节点数 > 1000 时布局在 Worker 中计算（**未实现**，理由见下） |
| 代码分割 | 编辑器内核、导入导出、管理后台分别 `React.lazy` 动态导入 |
| 虚拟滚动 | 导图列表与管理后台表格使用虚拟滚动 |
| 字体加载 | WOFF2 `unicode-range` 分片按需加载；**首屏阻塞等待所需分片就绪**（`document.fonts.load()` + `await document.fonts.ready`），**不用 `font-display: swap`**——顺序必须是「字体就绪 → 测量 → 布局」，否则节点尺寸会跳（见 §5.3.3） |

**性能预算**：编辑器首屏 JS（gzip）≤ 350KB；首屏到可交互 ≤ 1.5s（本地网络）。

**为什么没做 Web Worker 布局**：2000 节点的 `layoutMindmap` 实测 27–30ms（5 次取中位）。而 `LayoutResult` 是 `Map<string, NodeBox>` + `Map<string, TopicSize>` + `Map<string, ComputedStyle>` + 边数组，2000 个节点来回结构化克隆的开销与这 30ms 同量级——很可能得不偿失。真正的首屏大头是网络、JS 解析与字体分片（约 1.5s 里的绝大部分），布局只占 2%。等哪天出现「单张图 1 万节点」的真实需求，再连同「布局结果用 typed array 传」一起做。

**降级渲染（阴影/渐变）也没做**：当前主题系统里节点本来就不画阴影与渐变，没有可关的东西。这条是从草图里继承下来的，留着当备忘。

## 9. 无障碍与国际化

### 9.1 无障碍

- 画布提供 `role="tree"` / `role="treeitem"` 语义，配合 `aria-level`、`aria-expanded`、`aria-selected`。
- 完整键盘操作（见 4.6.2），不依赖鼠标。
- 焦点可见：当前选中主题显示明显描边；画布容器在**键盘**聚焦时显示内嵌焦点环（`focus-visible`，鼠标点击不显示）。
- 颜色对比度 ≥ 4.5:1（主题配色在校准时需校验文字与填充的对比度）。
- 所有图标按钮带 `aria-label`；图标本身 `aria-hidden="true"`，名字由按钮的 `aria-label` 提供。

#### 9.1.1 画布怎么变成一棵可读的树

SVG 里的 `<g>` 拿不到真正的焦点，所以焦点留在画布容器（一个 `tabIndex={0}` 的 `div`）上，容器声明 `role="tree"`，活动项靠 **`aria-activedescendant`** 指过去——方向键一动，读屏就念出新节点。三个细节：

- **`aria-level` 用 `depth + 1`**：ARIA 从 1 开始，布局的 `depth` 从 0 开始。
- **`aria-expanded` 只给有子节点的节点**：给叶子加 `aria-expanded="false"` 会让读屏念「已折叠」，而它没有可折叠的东西。
- **`aria-label` 用未折行的原始标题**：`lines` 是测量产物，拿它当名字会读出「分支⏎A」。

**选中播报**走一个 `aria-live="polite"` 的隐藏区域，文案由 `features/editor/canvas-a11y.ts` 的纯函数产出（未选中 / 叶子 / 有子节点 / 已折叠 / 多选五种）。只用 `polite`：连按三下方向键时 `assertive` 会互相打断，`polite` 只念最后一句，正是想要的行为。**只播报选中变化**，不播报「已删除」「已加粗」——那会让读屏变成一台不停说话的收音机，而选中就是导航本身。

**只读预览**（`preview` 开关、公开分享页、模板预览）整张图是一个 `role="img"`，里面**不挂 treeitem**：那里没有任何编辑能力，冒出一棵无名树比不报还糟。导出路径同理。

#### 9.1.2 键盘不能被困住（WCAG 2.1.2）

M6 打磨时验收脚本抓到两个真实的键盘陷阱，都已修：

- **画布的 `Shift+Tab` 被当成了「新建子主题」**。`keymap` 初版只判 `key === 'Tab'`，于是按 `Tab` 进画布（加了个节点）、再按 `Shift+Tab` 想退回去（又加了个节点），焦点永远出不去。现在 `Shift+Tab` 直接返回 `null`，交还给浏览器。
- **大纲视图的裸 `Tab` 被全局快捷键吃掉**。大纲本身没处理 `Tab`，但监听挂在编辑器根节点上，于是 `Tab` 变成了「新建子主题」——与本节「大纲不用 Tab 缩进」的约定正好相反。现在行内 `keydown` 对 `Tab` 只 `stopPropagation()`、不 `preventDefault()`，焦点照常移走；行内的折叠 / 加子主题按钮改为 `tabIndex={-1}`，动作由 `Ctrl/Cmd + .` 与 `Ctrl/Cmd + Enter` 承担，整棵树只剩一个 Tab 停靠点。

这两条都只有**真的按一遍键**才会暴露——`tsc` 与单测都不会报。

### 9.2 国际化

- `i18next` + `react-i18next`，语言包 `src/lib/i18n/locales/{zh-CN,en-US}.json`，约 860 个键。
- 语言包是**混合形状**：顶层是命名空间对象（`common` / `editor` / `admin`…），命名空间**内部**的键已经是扁平的点号键（`"panel.style.shape"`），个别命名空间还嵌一层对象（`share.badge`）。守卫测试必须递归摊平，否则会在第一层就停下。
- 三档偏好：跟随浏览器 / 中文 / English，存 `localStorage['wmind:locale']`，入口在「个人设置 → 界面语言」。`<html lang>` 跟着切换（`lib/i18n/preference.ts` 的 `applyLocale`）。
- 错误码 → 文案映射表维护在 `src/lib/api/errors.ts`（`errorMessageKeys`），避免后端 message 直接上屏；三级兜底：本地文案 → 后端 message → 「请求失败」。
- 日期与数字：**没有用 `date-fns`**，走 `Intl.DateTimeFormat` / `Intl.NumberFormat` / `Intl.ListFormat`，按语言缓存实例（`lib/format.ts`）。三条踩过的坑：
  - 模块级的 `new Intl.*('zh-CN')` 常量永远不跟着语言变，必须按 `i18n.language` 建并缓存；
  - `formatDateTime(...).slice(5, 11)` 这种定宽截取在 `en-US` 下切出的是 `2026, `，改用 `formatDayMonth`；
  - `join('、')` 在英文下会变成 `avatar、email、password`，改用 `Intl.ListFormat`。
- **模块级常量表只能存 key，不能存文案**：`settings-schema.ts`、`ROLE_LABEL` / `STATUS_META`、`WEIGHTS`、`FONT_DEFINITIONS.labelKey`、`ACTION_LABEL`、`REASON_KEY` 都是模块加载时求值一次的，写死中文就永远不会跟着切换。
- 非 React 代码（请求层、校验、导出、自动保存）走 i18next 单例 `i18n.t(...)`。
- **守卫测试** `src/lib/i18n/locales.test.ts`：中英 key 完全对齐、值不为空且不等于 key、占位符一一对应、源码里出现的每个 `t('a.b')` 都真的有翻译、没有缺命名空间的 `t('...')`。扫描源码前先剥注释——`import-present.ts` 的文档注释里就有一句反例 `t('import.error.WHATEVER')`。
- 如实保留：`e2e/` 脚本与导入解析器的提示仍是中文（前者不进产品包，后者是格式适配层的诊断信息）。

## 10. 暗色模式

### 10.1 方案

采用 **CSS 变量 + `class` 切换**，与 shadcn/ui 的既有约定一致。

```ts
type ThemeMode = 'light' | 'dark' | 'system';
```

- 偏好存 `localStorage['wmind:theme']`，默认 `system`。
- `system` 档监听 `window.matchMedia('(prefers-color-scheme: dark)')` 的 `change` 事件，实时切换。
- 应用到 `<html>` 的 `class="dark"`（而非 `data-theme`），与 shadcn 默认配置对齐。
- **首屏防闪烁**：在 `index.html` 的 `<head>` 内联一段同步脚本，在 React 挂载前根据 `localStorage` + `matchMedia` 设置 `html.dark`。这段脚本必须内联且同步执行，不能用 Vite 打包的模块（否则会晚于首次绘制）。

```html
<script>
  (function () {
    try {
      var m = localStorage.getItem('wmind:theme') || 'system';
      var dark = m === 'dark' ||
        (m === 'system' && matchMedia('(prefers-color-scheme: dark)').matches);
      document.documentElement.classList.toggle('dark', dark);
    } catch (e) {}
  })();
</script>
```

### 10.2 变量层

所有颜色必须通过语义化 CSS 变量引用，**禁止在组件里写死十六进制色值**（编辑器画布除外，见 10.3）。

```css
:root {
  --background: 0 0% 100%;
  --foreground: 240 10% 3.9%;
  --card: 0 0% 100%;
  --muted: 240 4.8% 95.9%;
  --border: 240 5.9% 90%;
  /* ... shadcn 标准变量集 ... */
}

.dark {
  --background: 240 10% 3.9%;
  --foreground: 0 0% 98%;
  --card: 240 10% 5.9%;
  --muted: 240 3.7% 15.9%;
  --border: 240 3.7% 15.9%;
  /* ... */
}
```

**画布区域例外**：编辑器的画布背景由导图主题的 `theme.global.backgroundColor` 决定，**不**跟随界面暗色模式。理由：导图是用户创作的内容，其背景色是文档数据的一部分；若跟随界面变暗，用户在暗色下编辑、在浅色下导出会得到不一致的结果。

但为了暗色模式下不刺眼，在画布容器外层加一层 `--canvas-surround` 变量（暗色下为深灰），画布本身保持主题色——形成「深色工作台 + 白纸」的观感。

### 10.3 影响范围

| 区域 | 处理 |
| --- | --- |
| 应用外壳、侧边栏、顶栏 | 走语义变量，自动适配 |
| 编辑器右侧面板、工具栏、状态栏 | 走语义变量 |
| 对话框、下拉菜单、Toast | 走语义变量（shadcn 组件已内置） |
| 画布背景 | 由导图主题决定，不跟随（见 10.2） |
| 画布上的主题配色 | 不跟随。但需在暗色下校验对比度：主题填充色与画布背景的对比度需 ≥ 3:1，不足时在样式面板给出提示 |
| 分享页 | 跟随访问者的系统偏好（不读创建者的偏好），保证访客体验自然 |
| 导出图片/PDF | **不**跟随界面暗色模式，永远使用主题配置的背景色 |

### 10.4 主题配色在暗色下的可用性

浅色填充（如「薄荷」配色）在深色画布周围会显得突兀，但这是用户内容的正确呈现。为避免「暗色模式下导图看起来奇怪」的困惑，在样式面板的画布设置区增加一行提示：

> 画布背景由导图主题决定，不随界面明暗变化。

并提供「一键设为深色背景」的快捷入口（写入 `theme.global.backgroundColor`，属于文档数据，会进撤销栈）。

### 10.5 测试用例

1. 三档切换后刷新页面，偏好保持。
2. `system` 档下改变系统外观，界面实时响应（Playwright 用 `emulateMedia` 覆盖）。
3. 首屏加载无「白闪」（暗色偏好下截图首帧应为深色）。
4. 导出图片的背景色与主题配置一致，与界面明暗无关。
5. 遍历所有页面与对话框，无「深色背景上出现深色文字」的对比度问题（可用 axe 自动化检查）。
