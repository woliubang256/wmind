## 1. 总体设计

### 1.1 适配器模式

导入导出全部实现为**适配器**，通过注册表管理，内核（文档模型、布局、渲染）不感知任何第三方格式。

```ts
// 导入适配器
export interface ImportAdapter {
  id: string;                                  // 'xmind' | 'markdown' | 'opml'
  name: string;                                // 显示名
  extensions: string[];                        // ['.xmind']
  mimeTypes: string[];
  maxSizeBytes: number;
  /** 嗅探文件类型（读魔术字节或结构特征） */
  detect(buffer: ArrayBuffer, fileName: string): boolean;
  /** 解析为 .wmind 文档 */
  parse(buffer: ArrayBuffer, options: ImportOptions): Promise<ImportResult>;
}

export interface ImportResult {
  document: WmindDocument;
  stats: { sheetCount: number; nodeCount: number; maxDepth: number };
  warnings: ImportWarning[];                   // 降级 / 忽略项
  unsupported: string[];                       // 无法还原的特性名
}

// 导出适配器
export interface ExportAdapter {
  id: string;                                  // 'png' | 'jpeg' | 'svg' | 'pdf' | 'markdown' | 'opml'
  name: string;
  extension: string;
  mimeType: string;
  /** 该格式支持的导出选项，用于动态渲染导出对话框 */
  optionsSchema: ExportOption[];
  render(ctx: ExportContext): Promise<Blob>;
}

export interface ExportContext {
  document: WmindDocument;
  sheetIds: string[];
  layouts: Map<string, LayoutResult>;
  options: Record<string, unknown>;
  theme: Theme;
}
```

**注册表**：

```ts
importRegistry.register(xmindImporter);
importRegistry.register(markdownImporter);
importRegistry.register(opmlImporter);

exportRegistry.register(pngExporter);
exportRegistry.register(jpegExporter);
exportRegistry.register(svgExporter);
exportRegistry.register(pdfExporter);
exportRegistry.register(markdownExporter);
exportRegistry.register(opmlExporter);
```

新增格式（如 FreeMind `.mm`、TextBundle）只需新增一个适配器文件并注册，不改任何现有代码。后端 `convert/` 包采用相同的接口设计，保证前后端行为一致。

### 1.2 为什么导入在前端、导出也以前端为主

| 决策 | 理由 |
| --- | --- |
| 导入放前端 | ① 避免上传大文件与解析过程占用服务端资源；② 解析产出的模型与渲染层共用同一套 TS 类型，无需跨语言序列化；③ 服务端仍保留同构实现，供未来的 API 导入与客户端复用 |
| 导出以前端为主 | ① 零网络往返、零服务端负载；② 导出内容就是屏幕上渲染的 SVG，所见即所得；③ 服务端导出（Headless Chrome）作为超大导图兜底 |
| 一致性保证 | 服务端导出复用前端构建的同一份 SVG 模板（导出模块编译为独立 ESM 产物，服务端页面加载它），避免两套渲染逻辑漂移 |

## 2. 导入

### 2.1 XMind 导入

#### 2.1.1 文件结构

`.xmind` 本质是一个 zip 包，两个大版本内部结构不同：

**XMind 2020+ / 2021+ / 2022+**

```
document.xmind (zip)
├── content.json          ← 主内容（sheet / topic / theme / relationships ...）
├── metadata.json         ← 文档元信息
├── manifest.json         ← 包清单
├── Thumbnails/
│   └── thumbnail.png
├── resources/            ← 内嵌图片等资源
└── ...
```

**XMind 8（经典版）**

```
document.xmind (zip)
├── content.xml           ← 主内容
├── styles.xml            ← 样式与主题定义
├── meta.xml
├── META-INF/manifest.xml
├── Thumbnails/thumbnail.png
└── resources/
```

#### 2.1.2 解析流程

```
读入 ArrayBuffer
  → JSZip 解压
  → 探测：存在 content.json ⇒ 走现代格式解析器
          存在 content.xml  ⇒ 走 XMind 8 解析器
          都不存在        ⇒ 抛 IMPORT_PARSE_FAILED
  → 解析为中间结构
  → 按 §5.2 / §5.3 映射表转换为 .wmind
  → 校验（docmodel.Validate）
  → 返回 ImportResult（含 warnings）
```

**安全防护**：

| 风险 | 防护 |
| --- | --- |
| zip 炸弹 | 解压前检查压缩包大小（≤ 50MB）；解压时逐条累计已解压字节数，超过 200MB 立即中止 |
| 路径穿越 | 只按固定文件名读取（`content.json` / `content.xml` / `styles.xml`），不遍历目录 |
| 超大 JSON | `content.json` 超过 50MB 时拒绝 |
| 节点爆炸 | 解析过程中节点数超过 20000 时中止并提示 |
| XML 实体注入 | `fast-xml-parser` 关闭外部实体解析（`processEntities: false` 用于 DTD，仅保留标准实体） |
| XSS | 主题标题中的 HTML 经白名单清洗后才写入 `notes.html`；`title` 一律按纯文本处理并转义 |

#### 2.1.3 XMind 2020+（content.json）解析要点

- `content[]` 数组，每项是一个 sheet；无 `content` 字段时尝试 `sheets`。
- 每个 sheet 的 `rootTopic` 递归转换为 `Topic`。
- **节点 ID**：优先沿用原 `id`，但需检测文档内冲突，冲突时生成新 ID 并记录映射（供 `relationships` / `boundaries` 引用修正）。
- **主题（Theme）**：XMind 的 `theme` 对象包含 `map` / `centralTopic` / `mainTopic` / `subTopic` / `floatingTopic` / `summaryTopic` / `boundary` / `relationship` 等分组，每组下是 `properties` 键值对。按 §5.3 映射到 wmind 的 `Style`。
  - 若 `theme` 中的调色板无法对应到 10 套内置配色，则**保留能映射的显式样式，调色板回退到「缤纷-活力」**，并在 `warnings` 中提示「配色方案已回退」。
- **图片**：`resources/` 中的图片通过 `image.src` 的相对路径引用，需读取 zip 内对应条目并上传到服务端（`POST /files`），把 `src` 替换为服务端 URL。
- **未识别字段**：原样存入 `extensions`，导出时可回写，减少往返损失。

#### 2.1.4 XMind 8（content.xml + styles.xml）解析要点

- `content.xml` 命名空间 `urn:xmind:xmap:xmlns:content:2.0`。
- 结构：`<xmap-content><sheet><topic>...`。
- 节点文本在 `<title>` 子元素中；子节点在 `<children><topics type="attached">` / `type="detached"`。
- 备注在 `<notes><plain>` / `<notes><html>`。
- 标记在 `<marker-refs><marker-ref marker-id="..."/>`。
- 标签在 `<labels><label>`。
- 节点可通过 `style-id` 引用 `styles.xml` 中的 `<style id="..." type="topic">`，该 style 内含 `<topic-properties>` 与 `<text-properties>`。
- sheet 通过 `theme` 属性引用主题；主题定义同样在 `styles.xml` 中。
- 转换时先解析 `styles.xml` 建立 `styleId → Style` 映射表，再解析 `content.xml` 并套用。

> **实现前置**：XMind 8 的 `styles.xml` 内部结构在不同小版本间有差异，且未公开文档化。开发前必须准备 3~5 个真实样本（含自定义主题、图片、联系、外框、概要各一）作为测试夹具，以样本为准实现，不凭推测编码。

#### 2.1.5 不支持项的降级策略

| XMind 特性 | wmind 处理 |
| --- | --- |
| 贴纸（Sticker） | 忽略，计入 `unsupported` |
| 音频 / 附件 | 忽略，在备注中追加一行「原文件包含附件：xxx」 |
| 录音 | 忽略 |
| 智能配色 / 渐变填充 | 取渐变起始色作为 `fill`，计入 `warnings` |
| 自定义标记 | 忽略，计入 `unsupported` |
| 导图密码 | 无法打开，提示「该文件已加密，请先在 XMind 中移除密码」 |
| 甘特图数据 | 忽略 |
| 画布壁纸 / 水印 | 忽略 |

导入完成后向用户展示摘要对话框：

```
导入完成
├─ 画布：1 个
├─ 主题：42 个（最大层级 4）
├─ 已还原：结构、样式、备注、标签、标记、超链接、图片
└─ 未能还原（2 项）
   · 贴纸 × 3
   · 自定义标记 × 1
```

### 2.2 Markdown 导入

**模式判定**：

```ts
function detectMarkdownMode(text: string): 'heading' | 'list' {
  const headingCount = (text.match(/^#{1,6}\s+/gm) ?? []).length;
  const listCount    = (text.match(/^(\s*)([-*+]|\d+\.)\s+/gm) ?? []).length;
  return headingCount >= 2 && headingCount >= listCount / 2 ? 'heading' : 'list';
}
```

**标题模式规则**：

| Markdown | 映射 |
| --- | --- |
| 第一个 `#` 标题 | 中心主题 |
| `##` / `###` … | 逐级子主题 |
| 标题层级跳跃（如 `#` → `###`） | 按实际深度差补中间层级？**否** —— 直接挂到最近的上级，不补空节点 |
| 代码块 | 作为该标题下第一个子主题，内容整体放入其备注 |
| 引用块 `>` | 归属于最近的上一个主题，写入 `notes.plain` |
| 列表项 | 作为最近标题的子主题，按缩进继续嵌套 |
| 图片 | 写入 `image`，同时尝试上传到服务端 |
| 链接 | 写入 `href` |
| 行内代码 | 写入 `labels` |
| 任务列表 `- [x]` / `- [ ]` | 写入 `markers`（`task-done` / `task-start`） |
| 表格 | 转为「表格标题 + 各行作为子主题」的降级形式，计入 `warnings` |
| 加粗 / 斜体 / 高亮 | 忽略 |

**列表模式规则**：以首个非列表非空行为中心主题（若文件直接以列表开头，则中心主题取文件名）；列表项缩进每 2 或 4 空格为一层，混合缩进时按「缩进量分桶」推断层级。

### 2.3 OPML 导入

```ts
const parsed = parser.parse(xmlText);          // fast-xml-parser
const outlines = parsed.opml.body.outline;     // 可能是对象或数组，需归一化
```

- `<outline>` 的 `text` → `title`；缺失时回退 `title` 属性，再缺失用 `(未命名)`。
- 递归 `outline.outline` 作为 `children.attached`。
- 属性映射见 [03-数据模型与文件格式](./03-数据模型与文件格式.md) §5.4。
- 根 `<outline>` 多于 1 个时：第一个作为中心主题，其余作为 `floatingTopics`。

## 3. 导出

### 3.1 导出上下文准备（所有格式共用）

```
1. 取 sheet 列表（按「内容」选项：当前画布 / 全部画布）
2. 对每个 sheet 重新执行布局（纯函数，不受当前视口缩放平移影响）
3. 计算内容包围盒 bounds
4. 应用导出选项：
   ├─ padding（默认 40px，按缩放比例缩放）
   ├─ 边框样式（描边 / 填充背景 → 生成外层 rect）
   ├─ 品牌标识（右下角「由 wmind 生成」文字）
   └─ 当前日期（左下角 YYYY-MM-DD）
5. 生成独立 SVG（见 3.2）
6. 交给具体格式适配器
```

### 3.2 独立 SVG 构建

导出的 SVG 与画布渲染共用同一套元素生成函数，但**排除**编辑器专属节点（选区框、拖拽指示、折叠徽标、编辑中的输入框）。

```ts
function buildExportSvg(ctx: ExportContext, sheetId: string, scale: number): SVGElement
```

要点：

| 项 | 处理 |
| --- | --- |
| 命名空间 | `xmlns="http://www.w3.org/2000/svg"`，`xmlns:xlink` |
| 尺寸 | `width` / `height` = 内容尺寸 × scale；同时写 `viewBox` 保持矢量可缩放 |
| 样式 | 全部内联到元素属性（`fill` / `stroke` / `font-family` / `font-size`），不依赖外部 CSS |
| 字体 | 见 §4 |
| 图片 | 内嵌为 `data:` base64（跨域图片需先 fetch 转 base64，失败则跳过并告警） |
| 背景 | `transparent: true` 时不绘制背景 rect |
| 转义 | 文本内容做 XML 转义（`& < > " '`），防止破坏 SVG 结构 |

### 3.3 SVG 导出

直接序列化：`new XMLSerializer().serializeToString(svg)` → `Blob` → 下载。

- 文件名：`{导图标题}.svg`
- 附带 `<?xml version="1.0" encoding="UTF-8"?>` 声明。

### 3.4 PNG / JPEG 导出

```ts
async function rasterize(svg: SVGElement, opts: { scale: number; mime: 'image/png' | 'image/jpeg'; transparent: boolean }) {
  const svgText = new XMLSerializer().serializeToString(svg);
  const svgBlob = new Blob([svgText], { type: 'image/svg+xml;charset=utf-8' });
  const url = URL.createObjectURL(svgBlob);

  const img = await loadImage(url);                 // new Image() + decode()
  const canvas = document.createElement('canvas');
  canvas.width  = Math.round(img.naturalWidth  * opts.scale);
  canvas.height = Math.round(img.naturalHeight * opts.scale);

  const c = canvas.getContext('2d')!;
  if (opts.mime === 'image/jpeg' || !opts.transparent) {
    c.fillStyle = '#FFFFFF';                        // JPEG 无 alpha 通道
    c.fillRect(0, 0, canvas.width, canvas.height);
  }
  c.drawImage(img, 0, 0, canvas.width, canvas.height);

  URL.revokeObjectURL(url);
  return await new Promise<Blob>((res, rej) =>
    canvas.toBlob((b) => (b ? res(b) : rej(new Error('toBlob failed'))), opts.mime, 0.92)
  );
}
```

**容量保护**：Canvas 单边上限（Chrome 16384px、Safari 4096~8192px 视设备）与总面积上限各不相同。导出前计算目标像素尺寸：

| 情况 | 处理 |
| --- | --- |
| 单边 ≤ 8192 且总像素 ≤ 268M | 前端直接栅格化 |
| 超出但 ≤ 16384 | 提示「图片尺寸较大，可能导致浏览器卡顿」，允许继续 |
| 超出 16384 | 禁用前端导出，提示改用 **服务端导出** 或降低缩放比例 |

### 3.5 PDF 导出

采用 `jsPDF` + `svg2pdf.js`：

```ts
const pdf = new jsPDF({ orientation, unit: 'pt', format: [w, h] });
await svg2pdf(svgElement, pdf, { x: 0, y: 0, width: w, height: h });
pdf.save(`${title}.pdf`);
```

| 项 | 处理 |
| --- | --- |
| 页面尺寸 | 默认「适应内容」（单页 = 内容尺寸）；提供 A4 / A3 / 自动选项 |
| 多画布 | 每个画布一页；A4 等固定尺寸时按比例缩放居中 |
| 字体 | 必须内嵌 TTF（`pdf.addFileToVFS` + `addFont`），否则中文在阅读器中可能显示为空白 |
| 文字转路径 | **默认开启**：用 `opentype.js` 把文本转为路径后绘制。代价是文本不可搜索/不可复制，收益是字体绝对不丢失。提供「保留可选中文字」开关 |
| 超大内容 | 超过 5080pt（PDF 单页上限 14400 单位）时提示改用 A4 分页或降低缩放 |

> **备选方案**：服务端 `chromedp` 渲染 → `Page.printToPDF`，保真度最高、字体处理最省心，但需在容器内装 Chromium（镜像体积 +400MB）。一期优先前端方案；若中文 PDF 质量不达标，M6 阶段再切服务端。

### 3.6 Markdown / OPML 导出

两者都是**纯文本序列化**，从文档模型直接生成，不依赖布局与渲染。

**Markdown**（规则见 [03-数据模型与文件格式](./03-数据模型与文件格式.md) §5.6）：

```markdown
# 产品规划

> 2026 年度产品路线

## 一期

- 账号体系
- 导图编辑器 `核心`

## 二期

- 客户端 App
```

**OPML**（规则见 [03-数据模型与文件格式](./03-数据模型与文件格式.md) §5.4）：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<opml version="2.0">
  <head><title>产品规划</title></head>
  <body>
    <outline text="产品规划" _note="2026 年度产品路线">
      <outline text="一期">
        <outline text="账号体系"/>
      </outline>
    </outline>
  </body>
</opml>
```

**导出前必须提示**：Markdown 与 OPML **不承载样式信息**，导出后重新导入会丢失配色、形状、线条。导出对话框在这两个格式下显示醒目的提示条。

### 3.7 导出对话框

对应截图 6、7、8。

| 分组 | 选项 | 取值 | 适用格式 |
| --- | --- | --- | --- |
| 内容 | `scope` | 当前画布 / 全部画布 | 全部 |
| 选中 | `sheetId` | 画布下拉（`scope = current` 时启用） | 全部 |
| 缩放 | `scale` | 75% / 100% / 150% / 200% / 自定义 | png / jpeg / pdf |

**边框预设**（对应截图 7/8 的 6 个预览方块）：

| id | 名称 | 实现 |
| --- | --- | --- |
| `none` | 无边框 | 不绘制外层；`transparent` 决定是否有白底 |
| `stroke-thin` | 细描边 | 外层 rect，`stroke-width: 1px`，黑色 |

| `fill-blue` | 蓝色背景 | 外层 rect，填充 `#4FC3F7`，无描边 |

> 预览色值需按截图采样校准。

**对话框布局**：左侧实时预览（用同一套导出渲染函数生成小尺寸 SVG），右侧选项表单。选项变更后 200ms 防抖重绘预览。

**按主分支拆分**：对每个一级子主题，生成一份只包含「根 + 该分支」的临时文档并单独导出，打包为 zip 下载（`{标题}-分支名.png`）。

### 3.8 分享页的导出控制

分享页（`/s/:token`）复用同一套导出能力，但入口与权限受三重控制：

| 控制点 | 来源 | 行为 |
| --- | --- | --- |
| 站点级 | `feature.export_enabled` | 关闭时所有位置（含编辑器）都不允许导出 |
| 分享级 | `share.allow_download` | 关闭时分享页**隐藏导出按钮**，且服务端拒绝该 token 的导出请求 |
| 页面级 | — | 分享页的导出对话框**不提供** Markdown / OPML 选项（这两种格式导出的是内容而非渲染结果，与「只读展示」的定位不符），仅提供 PNG / JPEG / SVG / PDF |

**服务端导出接口的鉴权**：`POST /export` 接受可选的 `shareToken` + `X-Share-Access`。当以分享身份调用时：

```
1. 解析 shareToken，按分享失效规则校验（撤销/过期/导图删除 → 404）
2. 校验 share.allow_download，为 false 时返回 403 EXPORT_DISABLED
3. 校验请求的 mapUid 必须等于 share.map_id（防止借分享身份导出其他导图）
4. 服务端渲染时同样应用 show_notes 剥离规则
```

> **能力边界重申**：分享页必须把文档结构下发给浏览器才能支持折叠、缩放等交互，因此 `allow_download = false` **无法**阻止有技术能力的访问者通过开发者工具获取数据。它降低的是门槛，不是访问控制。真正的访问控制应使用访问密码。

## 4. 字体处理

字体是导出保真度的最大风险点，尤其 PDF 与中文。**默认字体为思源黑体（Noto Sans SC，SIL OFL 1.1）**，完整决策见 [09-技术决策记录](./09-技术决策记录.md) ADR-016。

| 格式 | 策略 |
| --- | --- |
| SVG | 在 `<defs><style>` 中写入 `@font-face`，字体以 base64 WOFF2 内嵌。**只内嵌该导图实际用到的分片**（按 `unicode-range` 挑），而非全量字体；提供「文字转路径」选项进一步规避体积与字体缺失问题 |
| PNG / JPEG | 由浏览器栅格化，字体已加载即可正常渲染。导出前必须 `await document.fonts.ready`，否则会用回退字体栅格化 |
| PDF | 默认「文字转路径」（`opentype.js`）；关闭该选项时用 `jsPDF.addFileToVFS` 内嵌 TTF 子集。选 TTF 静态实例而非 OTF/可变字体，正是因为这条链路对前者的支持最稳 |
| Markdown / OPML | 不涉及字体 |

### 4.1 分发的字体

随应用分发 **Noto Sans SC 的 TTF 静态实例，4 个字重**（300 / 400 / 700 / 800），按 `unicode-range` 切片后由本站源提供，**不依赖外部 CDN**：

| 字体 | 用途 | 字重 | 许可 |
| --- | --- | --- | --- |
| Noto Sans SC（思源黑体） | **默认**，中文无衬线 | 300 / 400 / 700 / 800 | SIL OFL 1.1 |
| Noto Serif SC（思源宋体） | 中文衬线（`serif`，P1） | 400 / 700 | SIL OFL 1.1 |
| JetBrains Mono | 等宽（`mono`，P1） | 400 / 700 | SIL OFL 1.1 |
| 系统字体栈 | `system` 选项，零字节 | — | — |

> **已解决**：`NeverMind` 为 XMind 自有字体、不可分发，已由 ADR-016 决定改用思源黑体。文档里 `fontFamily` 存**标识符**（`sans` / `serif` / `mono` / `system`），导入时按 [03](./03-数据模型与文件格式.md) §5.3.1 的映射表把 XMind 的字体名归一——**不再需要「同名替换」这一层**。
>
> **不做硬子集截断**：不采用「只打包 GB2312 一级字库 3755 字」的做法。导图内容任意，截断会让常用但不在该表内的汉字显示为方框；改为全量 CJK 覆盖 + 分片按需加载。

### 4.2 字体缺失与回退的可见性

导出时必须能回答「这次导出有没有用到回退字体」：

- 导出前遍历文档全部可见文本，用 `document.fonts.check()` 逐字符（按码点抽样）确认覆盖情况。
- 命中回退字体时，在导出结果里给出提示（「有 N 个字符使用了系统字体渲染，在其他设备上可能显示不同」），而不是静默出图。用户看到差异却不知道为什么，是比差异本身更糟的体验。
- 服务端兜底导出（chromedp）的容器必须预装同一套字体到 `/usr/share/fonts`，否则服务端渲染结果与浏览器不一致——**同一个导图在不同路径导出得到不同结果，是最难排查的一类 bug**。

## 5. 主题系统（配色与形状还原）

### 5.1 主题构成

一套主题（Theme）= **配色方案（Palette）** + **角色样式（Role Styles）** + **全局设置（Global）** + **布局开关（Layout）**。结构定义见 [03-数据模型与文件格式](./03-数据模型与文件格式.md) §2.5。

### 5.2 还原清单

对标截图 4 的「画布」面板，逐项列出实现要求：

| UI 项 | 数据字段 | 说明 |
| --- | --- | --- |
| 配色方案（缤纷 / 经典 各 5 套） | `theme.palette` | 每套含 `colors`（分支填充）、`lineColors`（线条）、`backgroundColor` |
| 背景颜色 | `theme.global.backgroundColor` | 默认白；提供预设色板 + 取色器 |
| 全局字体 | `theme.global.fontFamily` | 下拉选择内置字体族；存**标识符**（`sans` / `serif` / `mono` / `system`），不存字体名（见 [03](./03-数据模型与文件格式.md) §2.4.2） |
| 分支线粗细 | `theme.global.lineWidth` | 下拉：细 / 中 / 粗（1 / 2 / 3 px） |
| 彩虹分支 | `theme.rainbowBranch` + `theme.rainbowColors` | 开关 + 颜色选择器（预设彩虹 + 自定义） |
| 自动平衡布局 | `theme.layout.autoBalance` | 思维导图结构下左右分支自动均衡 |
| 紧凑型布局 | `theme.layout.compact` | 缩小同级与父子间距 |
| 同级主题对齐 | `theme.layout.alignSiblings` | 同深度节点水平/垂直对齐 |
| 分支自由布局 | `theme.layout.freeBranch` | 允许手动拖动单个节点位置（P2） |
| 灵活自由主题 | `theme.layout.flexibleFloating` | 自由主题不参与自动布局（P2） |
| 主题叠放 | `theme.layout.topicOverlap` | 允许节点重叠（P2） |

### 5.3 配色方案数据

10 套内置配色方案的主色序列见 [03-数据模型与文件格式](./03-数据模型与文件格式.md) §6.2。

**每套配色还需定义**：

```ts
interface Palette {
  id: string;
  name: string;
  category: 'vivid' | 'classic';
  colors: string[];        // 分支填充色，按 branchIndex 循环
  lineColors: string[];    // 分支线条色，通常与 colors 一致
  textColors: string[];    // 对应填充色上的文字色（保证对比度 ≥ 4.5:1）
  backgroundColor: string;
  centralTopic: Partial<Style>;   // 中心主题的填充/文字色
  mainTopic: Partial<Style>;
  subTopic: Partial<Style>;
}
```

> **对比度约束**：`textColors[i]` 必须与 `colors[i]` 满足 WCAG AA（4.5:1）。深色填充配白字，浅色填充配深字。校准脚本需自动校验并在不达标时告警。

### 5.4 色值校准方法

本文档与 03 文档中的色值均为**依截图观感给出的近似值**，必须校准后才能进入实现。校准流程：

1. **采样**：在 XMind 中依次应用 10 套配色方案，导出 SVG（XMind 的 SVG 导出会写出真实色值），从 SVG 中提取 `fill` / `stroke` 属性。
2. **补全**：截图中的色带缩略图只有 6 段，实际主题可能有更多色。以 SVG 中实际出现的颜色序列为准。
3. **对比度校验**：跑校验脚本，不达标时微调明度而非换色相（保持视觉一致性）。
4. **落库**：把校准结果写入 `backend/themes/*.json`（内嵌资源），并同步更新 03 文档的表格。
5. **回归**：用同一份导图在 XMind 与 wmind 中分别导出 SVG，做像素级对比（容差 2%），作为主题还原的验收手段。

**XMind 形状（shape-class）还原**：XMind 的形状体系包含约 20 种（矩形、圆角矩形、胶囊、椭圆、圆形、菱形、六边形、平行四边形、梯形、星形、云形、下划线、无边框、双向箭头等）。一期实现 §2.4.1 表中列出的 10 种，其余在导入时降级为最接近的形状并计入 `warnings`，二期补齐。

### 5.5 主题与模板的关系

| 概念 | 作用范围 | 关系 |
| --- | --- | --- |
| **主题（Theme）** | 一份导图的整体视觉 | 可随时切换，不改变内容 |
| **模板（Template）** | 新建导图时的初始状态 | 一个模板**包含**一份默认主题 + 结构 + 示例内容 |

创建导图时，模板的 `document.theme` 被复制到新导图中，此后两者解耦：改模板不影响已创建的导图，改导图主题不影响模板。
