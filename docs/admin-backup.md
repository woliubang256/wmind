# 后台备份与恢复

管理员在网站设置的「备份与恢复」中配置。定时备份默认关闭；Cron 为五段、分钟精度，默认 Asia/Shanghai 每天 03:00。可视化字段与原始表达式双向编辑，显示未来五次运行。进程停机期间错过的任务不补跑，同一时间仅执行一项备份、恢复或连接测试。当前维护互斥适用于单个后端实例；多实例部署请使用已有运维脚本协调停写与备份。

WebDAV 填完整目标目录 URL、用户名与密码，缺少的目录会尝试创建。S3 支持 AWS 和兼容服务，配置 endpoint（AWS 可留空）、region、bucket、prefix、Access Key/Secret Key，按服务选择 Path Style；临时凭据支持 Session Token。连接测试会创建并删除一个随机临时文件，因此需要写入和删除权限；实际备份只上传，不清理远端已有备份。凭据加密入库，界面留空表示保留已有凭据。

每次生成一个 ZIP，包含当前数据库的全部应用数据、上传图片/头像和校验清单，不含 `.env`。恢复只接受此后台生成的 ZIP，不接受脚本的分离 tar/SQL/SQLite 文件。备份不提供远端浏览或下载恢复入口。

上传 ZIP 后显示生成时间、数据库类型/迁移版本和文件数量，校验通过再确认覆盖。恢复要求相同数据库类型、迁移版本、原有效加密密钥：优先 `WMIND_2FA_ENCRYPTION_KEY`，没有配置时为 `WMIND_JWT_SECRET`。这些环境密钥须另行安全保管，不能只保留 ZIP。成功恢复会撤销旧登录会话和未完成的验证，保留已登记 2FA，使用备份中的账号重新登录查看结果。

捕获数据库与文件时暂停业务请求；压缩与远端上传阶段恢复业务访问。恢复期间保持维护状态，先把当前站点打包为本地安全副本，再在数据库事务内安装数据和上传目录，普通错误会回退。数据库和文件系统不具备跨介质的崩溃原子性，进程被强杀或磁盘故障时需从安全副本恢复。上传目录需要能在其父目录中改名，默认 Docker 的 `/data/uploads` 符合；直接把独立卷挂在 uploads 目录时改名可能失败，当前数据仍受事务回退保护。

临时文件与恢复前 ZIP 位于上传目录的同级 `.wmind-backups`（默认 `/data/.wmind-backups`）。恢复前 ZIP 不自动删除，确认运行正常后由运维清理；界面作业结果显示文件名。需要恢复时将该文件复制到电脑并手动上传。归档上限 2 GiB，解压上限 8 GiB；磁盘需容纳捕获快照、上传暂存和恢复前副本。Nginx 已为后台备份路径单独配置 2 GiB/900 秒限制，外层代理也需允许对应上传大小和时间。

已有 `wmind db backup` 与 `deploy/scripts/backup.sh`、`restore.sh` 继续使用原有格式，详见部署文档。
