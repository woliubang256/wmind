## 1. 项目背景与目标

### 1.1 背景

思维导图是需求梳理、方案设计、知识整理的常用工具，XMind 是该领域体验最成熟的商业产品。但在自建与团队内网场景下，直接使用 XMind 存在几个绕不开的问题：

- **数据在第三方**：导图文件散落在个人电脑或商业云盘，团队资产无法沉淀，也无法纳入自有的备份与审计体系。
- **无法私有化部署**：内网、涉密环境无法使用在线服务，桌面版又缺少统一的服务端存储。
- **不可定制**：模板、主题、导出样式无法按组织规范固化；无法与内部系统（需求平台、知识库）打通。
- **订阅成本与账号管理**：团队成员账号由厂商控制，组织层面缺少统一的开通/停用能力。

### 1.2 项目目标

构建 **wmind**——一套可私有化部署、数据自主可控、体验对标 XMind 的 Web 思维导图系统。

一期目标（可验证）：

1. 用户能完成「注册 → 登录 → 从模板新建 → 编辑导图 → 导入/导出」的完整闭环，编辑体验与 XMind 桌面版的核心操作习惯一致。
2. 管理员能在一套后台中完成用户全生命周期管理与站点开关配置，无需改配置文件。
3. 通过 `docker compose up -d` 一条命令完成部署，无外部强依赖。
4. 数据格式自有、可扩展，为后续客户端 App 与协作能力预留接口。

### 1.3 产品定位

- **Self-hosted first**：默认部署形态是「一个实例服务一个组织」，不是多租户 SaaS。
- **Web 优先**：一期只做 Web，桌面级体验靠浏览器内的高性能渲染达成；原生客户端为二期。
- **格式开放**：数据不锁死，支持 XMind / Markdown / OPML 进出。

## 3. 用户角色与权限

| 角色 | 标识 | 说明 | 权限范围 |
| --- | --- | --- | --- |
| 游客 | `anonymous` | 未登录访问者 | 访问登录页、注册页（受站点开关控制）、读取公开站点配置 |
| 注册用户 | `user` | 普通使用者 | 对自己名下的导图 / 模板 / 主题拥有全部增删改查权限；不可访问他人资源与管理接口 |
| 管理员 | `admin` | 系统运营者 | 拥有 `user` 全部权限，外加：用户管理、站点设置、全局统计、审计日志 |

> **权限模型说明**：一期采用「资源属主 + 全局角色」两层模型，不做导图级别的共享授权。导图接口一律以 `owner_id` 做数据隔离，管理员默认**不**能直接读写他人导图内容（仅能管理账号与执行删除），以降低越权风险。若后期引入团队空间，再扩展为 RBAC。

## 4. 功能需求

需求优先级：**P0** = 一期必须交付；**P1** = 一期尽量交付，可延后；**P2** = 远期预留。

| FR-AUTH-02 | 支持「邮箱或用户名 + 密码」登录 | P0 |

| FR-AUTH-06 | 个人资料：昵称、头像（上传或使用默认首字母头像） | P1 |

| FR-AUTH-11 | 邮件发送失败时不阻断主流程（如注册成功但验证邮件失败），给出明确提示并记入日志 | P0 |
| FR-AUTH-12 | 邮件模板中的站点名称、Logo、页脚备案号随站点设置变化 | P1 |
| FR-AUTH-13 | 重置密码与验证邮箱的令牌为一次性，使用后立即失效；新请求令牌时作废该用户的旧令牌 | P0 |

## 5. 非功能需求

### 5.1 性能

| 指标 | 目标 |
| --- | --- |
| 导图列表页 LCP | < 2s（本地/局域网） |
| 编辑器打开 1000 节点导图 | < 1.5s |
| 拖拽 / 选中 / 输入等交互 | 稳定 60fps（单帧 < 16ms） |
| 自动保存接口 P95 | < 300ms |
| 单导图节点数上限 | ≥ 5000 节点仍可编辑（> 2000 节点时允许降级为简化渲染） |
| 列表页接口 P95 | < 200ms（1000 张导图规模） |

### 5.2 兼容性

- 浏览器：Chrome / Edge 最近两个大版本、Safari 16+、Firefox 最近版本。
- 最小分辨率：1280 × 720；建议 1440 × 900 以上。
- 移动端：一期仅保证导图**只读浏览**可用，不保证完整编辑体验。

### 5.3 安全

| 项 | 要求 |
| --- | --- |
| 密码存储 | bcrypt（cost ≥ 12）或 argon2id，加盐 |
| 会话 | JWT 双令牌：access token 短时效（15 min）+ refresh token 长时效（7 天，可撤销） |
| 传输 | 生产环境强制 HTTPS，容器内 HTTP |
| 限流 | 登录/注册/导出/导入接口独立限流；登录失败次数过多临时锁定 |
| 越权 | 所有导图相关接口必须校验 `owner_id`；管理接口校验 `role = admin` |
| XSS | 主题标题、备注等富文本在渲染前清洗；导出 SVG 时转义文本 |
| 上传 | 校验 MIME 与扩展名白名单；限制单文件与解压后总大小，防 zip 炸弹 |
| CSRF | 若使用 Cookie 承载令牌，需 `SameSite=Lax` + CSRF Token；推荐 Bearer 头方案 |
| 分享令牌 | 长度 ≥ 22 字符（≥ 128 bit 熵），不可枚举；撤销/过期/密码错误返回不泄露存在性的错误 |
| 分享页 | 默认 `noindex, nofollow`；不返回导图源码，只返回渲染所需数据 |
| 邮件令牌 | 一次性、短时效（重置密码 30 分钟、验证邮箱 24 小时）；新令牌签发时作废旧令牌 |
| 凭据加密 | SMTP 密码等敏感配置在数据库中以 AES-GCM 加密存储，密钥来自环境变量，不落明文 |
| 邮件注入 | 邮件模板中的用户可控字段（昵称、站点名）做转义，防止邮件头注入 |
| 审计 | 管理员敏感操作留痕；分享链接的创建与撤销也记入审计 |

### 5.4 可用性

- 自动保存 + 本地草稿双保险，异常关闭不丢内容。
- 网络异常时给出明确提示，恢复后自动重试保存。
- 所有破坏性操作（删除导图、删除用户、清空回收站）二次确认。
- 全局错误边界，单模块崩溃不白屏。

### 5.5 可维护性与可扩展性

- 后端严格分层（handler / service / repository），核心格式转换逻辑可单测。
- 前端编辑器内核与 UI 面板解耦，新增面板不改内核。
- API 版本化（`/api/v1`），OpenAPI 文档随代码维护。
- 存储层抽象接口，本地磁盘 → S3/MinIO 可切换。
- 导入导出采用**适配器模式**，新增格式不改内核。

### 6.3 为客户端 App 预留的扩展点（本期只需设计，不实现）

1. **认证**：全部使用 Bearer Token，不依赖 Cookie，便于移动端复用。
2. **API 版本**：`/api/v1` 前缀，破坏性变更走 `/api/v2`。
3. **同步接口**：导图列表接口支持 `updated_since` 参数与 `deleted` 标记，客户端可做增量拉取。
4. **设备表**：`user_devices` 表结构本期建好（可空表），记录设备标识、平台、推送 token。
5. **文档模型可序列化**：`.wmind` JSON 格式与语言无关，客户端可直接复用同一套解析/渲染逻辑（未来用 Kotlin/Swift 重写渲染层）。
6. **离线优先**：文档变更以「操作（operation）」形式也可表达，为将来 OT/CRDT 留口子（一期不做，但模型不阻碍）。
7. **公开只读接口**：分享页的数据接口是纯 token 鉴权的只读接口，客户端可直接复用同一接口实现「查看他人分享的导图」。
8. **邮件接口**：忘记密码与邮箱验证是纯 HTTP 接口，客户端无需内嵌 WebView 即可完成流程（深链回调地址可配置）。

## 7. 验收标准（摘要）

| 场景 | 验收条件 |
| --- | --- |

**仍有待验证的技术前提**（非需求问题，属实现前置条件）：

1. XMind 的 `structureClass` 字符串与 `styles.xml` 结构未经真实样本验证——实现前需准备 5+ 真实 `.xmind` 文件。
2. 10 套配色方案的精确色值未经采样——实现 M3 前需从 XMind 导出 SVG 校准。
3. 默认字体 `NeverMind` 为 XMind 自有字体不可分发——需确认替代字体（建议思源黑体）。
4. 导出 PDF 走前端 jsPDF 还是服务端 Headless Chrome——若中文质量不达标，M6 切换。
